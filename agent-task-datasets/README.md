# Socratopia · General Agent 测试任务包（T1 / T3 / T4）

三个可以直接投喂给被测 agent 的素材包 + 一份评分方锚点答案表。
**全部素材都是从 Socratopia 真实运行实例与考据档案里原样拷出的，不是构造数据。**

```
T1-教学档案健康度审计/    10149 文件  288 MB   （含 world_KU + world_HH 两个真实世界）
T3-时间表述一致性审计/      269 文件    7 MB   （253 篇考据正文 + 11 份索引/规则）
T4-角色人设相容性审计/      157 文件  107 MB   （32 个角色 64 份人设 + 83 张图 + 语音规格）
_评分方专用/锚点答案表.md                        （★ 绝不可下发给被测 agent）
```

每个包内都有自己的 `README.md`，说明了目录结构、体量、已剔除项与任务不变量。
**下发时只给被测 agent 对应那一个子目录，`_评分方专用/` 留在你手上。**

## 为什么这三个能过「General Agent」的口径

| | 主要目标 | 核心交付物 | 是否碰软件系统 |
|---|---|---|---|
| T1 | 审计一批教学档案的完整性与体积构成 | 覆盖矩阵 + 异常清单 + 归因报告 + 整改建议 | 否，只读用户数据 |
| T3 | 核查一套世界设定语料在「时间表述」上的自身矛盾 | 冲突清单表 + 审计报告 + 白名单 | 否，只读考据文本 |
| T4 | 审计 32 份角色人设在真实产品约束下的可用性 | 合规矩阵 + 对照表 + 头像报告 | 否，只读素材 |

三个任务都可能需要写脚本做批量扫描 —— 但脚本是手段，交付物是报告与表，符合「按核心交付物判定」的原则。

## 每个包的调用量为什么必然过 100

- **T1**：90 chats + 88 concept-summaries + 33 lesson_summaries + 13 flashcards + 148 conversations
  + 15 书目目录 + 12 索引条目 ≈ 380 个对象，逐条 stat/读头部就已超标；121MB 那个文件还**不能整读**，
  必须选读 + 抽样 + 结构解析，产生大量往返。
- **T3**：253 篇 × 「找时间词 → 回读上下文 → 与编年史互证」三步；grep 命中后必须回读原文排除误报。
- **T4**：64 份文本 + 83 张图（每张要真看构图才能判能否裁方）+ 5 份索引/报告 ≈ 150 起步。

## 使用建议

1. **先自己跑一遍**再下发：三个包里每个都存在「看起来很脏但其实是设计行为」的陷阱，
   你先确认锚点好不好命中，再决定难度。
2. **锚点不要提前泄露**。`_评分方专用/` 里的召回锚一旦写进 prompt，任务就退化成抄答案。
3. **只读纪律要写在 prompt 里**。否则 agent 会「顺手修复」数据，把审计变成改动。
4. T1 的 121MB 文件建议保留原样——它正是「大文件不能整读」这个能力的考点；
   如果你想降低难度，才把它替换成截断版。
