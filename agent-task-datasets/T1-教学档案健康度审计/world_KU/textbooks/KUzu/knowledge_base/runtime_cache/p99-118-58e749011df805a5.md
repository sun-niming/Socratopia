### 阶段 1: 启动数据加载与JPA入门
**[当前教学焦点 / 队列起点]** 目标: 让学生理解 Spring Boot 启动时预加载数据的两种方式，并掌握引入 Spring Data JPA 依赖的方法。

#### CommandLineRunner预加载数据
*[本轮可见队列 1/3 · concept_id: CommandLineRunner预加载数据]*
Spring Boot 提供的函数式接口 CommandLineRunner，可在应用启动、应用上下文和所有 bean 生成之后、其他任何事情发生之前执行 run() 方法，用于预加载数据到数据库。它接受一个字符串数组参数（命令行原始参数）。可通过 @Bean 注解在配置类中声明，并返回 lambda 实现。
要点:
- CommandLineRunner 和 ApplicationRunner 都是函数式接口，都需实现 run() 方法
- run() 在上下文和所有 bean 生成后、其他事情发生前调用
- 可使用 @Bean 声明返回 lambda 的 CommandLineRunner bean
- CommandLineRunner 的 run() 参数为 String... args，表示命令行原始参数
- 适合用于启动时预加载数据，使用存储库而非 SQL 脚本，对关系型和非关系型数据库均有效
示例:
- @Bean
public CommandLineRunner dataLoader(IngredientRepository repo) {
  return args -> {
    repo.save(new Ingredient("FLTO", "Flour Tortilla", Type.WRAP));
    repo.save(new Ingredient("COTO", "Corn Tortilla", Type.WRAP));
    repo.save(new Ingredient("GRBF", "Ground Beef", Type.PROTEIN));
  };
}
常见误区:
- 认为 CommandLineRunner 的 run() 方法不需要参数（实际需要字符串数组参数，但可忽略）
- 认为 CommandLineRunner 和 ApplicationRunner 完全一样（参数类型不同）
自测:
Q: CommandLineRunner 的 run() 方法在什么时候被调用？
A: 在应用程序启动时，应用程序上下文和所有 bean 生成之后，在其他任何事情发生之前调用。
Q: 如何使用 @Bean 声明一个 CommandLineRunner 来预加载数据？
A: 在配置类中定义一个返回 CommandLineRunner 的 @Bean 方法，返回一个 lambda，在 lambda 中调用 repository 的 save() 方法保存数据。

#### ApplicationRunner预加载数据
*[本轮可见队列 2/3 · concept_id: ApplicationRunner预加载数据]*
Spring Boot 提供的函数式接口 ApplicationRunner，与 CommandLineRunner 类似，在应用启动时执行 run() 方法。区别在于 run() 方法接受 ApplicationArguments 参数，该参数是命令行解析组件，提供了访问参数的方法，如 getOptionValues()。
要点:
- ApplicationRunner 的 run() 方法接受 ApplicationArguments 参数
- ApplicationArguments 提供 getOptionValues() 等方法访问选项参数
- getOptionValues() 返回 List<String>，允许选项多次指定
- 可通过 @Bean 声明返回 lambda 的 ApplicationRunner bean
- 与 CommandLineRunner 一样，适合启动时预加载数据
示例:
- @Bean
public ApplicationRunner dataLoader(IngredientRepository repo) {
  return args -> {
    List<String> version = args.getOptionValues("version");
    repo.save(new Ingredient("FLTO", "Flour Tortilla", Type.WRAP));
  };
}
常见误区:
- 认为 ApplicationRunner 的 run() 参数是字符串数组（实际是 ApplicationArguments）
- 认为 ApplicationRunner 和 CommandLineRunner 没有区别
自测:
Q: ApplicationRunner 和 CommandLineRunner 的关键区别是什么？
A: 传递给 run() 方法的参数不同：CommandLineRunner 接受字符串数组，ApplicationRunner 接受 ApplicationArguments 对象。
Q: ApplicationArguments 的 getOptionValues() 方法有什么作用？
A: 返回指定选项参数的 List<String>，允许选项参数多次指定。

#### 添加Spring Data JPA依赖
*[本轮可见队列 3/3 · concept_id: 添加Spring Data JPA依赖]*
在 Spring Boot 项目中使用 Spring Data JPA，需要添加 spring-boot-starter-data-jpa 依赖。该 starter 默认包含 Hibernate 作为 JPA 实现。若要使用其他 JPA 实现（如 EclipseLink），需排除 Hibernate 并添加相应依赖。
要点:
- 添加 spring-boot-starter-data-jpa 依赖即可使用 Spring Data JPA
- 默认自带 Hibernate 作为 JPA 实现
- 可排除 hibernate-core 并添加其他 JPA 实现（如 EclipseLink）
- 更换 JPA 实现可能需要其他配置更改
示例:
- <dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
- <dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-jpa</artifactId>
  <exclusions>
    <exclusion>
      <groupId>org.hibernate</groupId>
      <artifactId>hibernate-core</artifactId>
    </exclusion>
  </exclusions>
</dependency>
<dependency>
  <groupId>org.eclipse.persistence</groupId>
  <artifactId>org.eclipse.persistence.jpa</artifactId>
  <version>2.7.6</version>
</dependency>
常见误区:
- 认为必须手动添加 Hibernate 依赖（starter 已包含）
- 认为更换 JPA 实现不需要排除默认实现
自测:
Q: Spring Data JPA 的 starter 默认使用哪个 JPA 实现？
A: Hibernate。
Q: 如何将 JPA 实现切换为 EclipseLink？
A: 排除 hibernate-core 依赖，并添加 org.eclipse.persistence.jpa 依赖（如版本 2.7.6）。
