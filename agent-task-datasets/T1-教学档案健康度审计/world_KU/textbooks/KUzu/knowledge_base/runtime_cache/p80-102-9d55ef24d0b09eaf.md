#### 使用 JdbcTemplate 查询数据库
*[本轮可见队列 1/3 · concept_id: 使用 JdbcTemplate 查询数据库]*
在 Spring JDBC 中，JdbcTemplate 的 query() 方法用于从数据库读取数据。findAll() 使用 query(sql, rowMapper) 查询所有行，findById() 使用 query(sql, rowMapper, id) 传入 where 子句的参数。query() 接受 SQL 语句、RowMapper 实现（用于将结果集每一行映射为对象）以及查询参数列表作为最后一个参数。RowMapper 可以用方法引用（如 this::mapRowToIngredient）或显式匿名内部类实现。
要点:
- JdbcTemplate 的 query() 方法用于查询数据库。
- query() 接受 SQL、RowMapper 和可变参数列表（查询参数）。
- findAll() 没有查询参数，findById() 有 id 参数对应当 where 子句中的 ?。
- RowMapper 负责将 ResultSet 的一行映射为一个对象。
- 可以使用 Java 8 方法引用（如 this::mapRowToIngredient）简化 RowMapper 的实现。
- 如果结果为空，findById() 返回 Optional.empty()；否则返回 Optional.of 包装的第一个结果。
示例:
- @Override
public Iterable<Ingredient> findAll() {
    return jdbcTemplate.query(
        "select id, name, type from Ingredient",
        this::mapRowToIngredient);
}
- @Override
public Optional<Ingredient> findById(String id) {
    List<Ingredient> results = jdbcTemplate.query(
        "select id, name, type from Ingredient where id=?",
        this::mapRowToIngredient,
        id);
    return results.size() == 0 ?
        Optional.empty() :
        Optional.of(results.get(0));
}
- private Ingredient mapRowToIngredient(ResultSet row, int rowNum)
    throws SQLException {
    return new Ingredient(
        row.getString("id"),
        row.getString("name"),
        Ingredient.Type.valueOf(row.getString("type")));
}
常见误区:
- 认为 query() 方法只能用于查询，不能用于插入或更新。
- 混淆 RowMapper 和 ResultSetExtractor 的用途。
- 忘记在 findById() 中传入 id 参数导致 SQL 执行失败。
自测:
Q: JdbcTemplate 的 query() 方法需要哪些参数？
A: query() 方法需要 SQL 查询字符串、RowMapper 实现（用于将结果集的行映射为对象）以及可变的查询参数列表（对应 SQL 中的占位符 ?）。
Q: findById() 如何实现当查询结果为空时返回 Optional.empty()？
A: findById() 调用 query() 得到 List<Ingredient> results，然后通过 results.size() == 0 来判断，如果为 0 则返回 Optional.empty()，否则返回 Optional.of(results.get(0))。

#### 使用 JdbcTemplate 插入数据
*[本轮可见队列 2/3 · concept_id: 使用 JdbcTemplate 插入数据]*
JdbcTemplate 的 update() 方法可用于在数据库中写入或更新数据。它接受一个包含 SQL 的字符串以及为查询参数赋值的可变参数列表。与 query() 不同，update() 不需要 RowMapper，因为它不返回结果集。
要点:
- update() 方法用于执行 INSERT、UPDATE、DELETE 等写操作。
- update() 的参数是 SQL 字符串和对应的参数值。
- save() 方法使用 update() 插入数据，并返回插入的对象。
- 与 query() 相比，update() 更简单，因为没有结果集映射步骤。
示例:
- @Override
public Ingredient save(Ingredient ingredient) {
    jdbcTemplate.update(
        "insert into Ingredient (id, name, type) values (?, ?, ?)",
        ingredient.getId(),
        ingredient.getName(),
        ingredient.getType().toString());
    return ingredient;
}
常见误区:
- 认为 update() 方法只能用于更新操作，不能用于插入。
- 在 update() 中错误地传入 RowMapper 参数。
自测:
Q: JdbcTemplate 的 update() 方法有什么作用？
A: update() 方法用于在数据库中写入或更新数据，可以执行 INSERT、UPDATE、DELETE 等 SQL 语句。
Q: save() 方法中如何使用 update() 插入 Ingredient 数据？
A: save() 方法调用 jdbcTemplate.update()，传入 SQL 字符串 "insert into Ingredient (id, name, type) values (?, ?, ?)" 和对应的参数值 ingredient.getId(), ingredient.getName(), ingredient.getType().toString()。

#### Spring 组件扫描与 @Repository 注解
*[本轮可见队列 3/3 · concept_id: Spring 组件扫描与 @Repository 注解]*
@Repository 是 Spring 的原型注解之一（其他包括 @Controller 和 @Component）。使用 @Repository 注解的类会被 Spring 组件扫描自动发现，并在 Spring 应用程序上下文中注册为 bean。当 Spring 创建该 bean 时，可以通过 @Autowired 注解将依赖（如 JdbcTemplate）注入到构造函数中。
要点:
- @Repository 是 Spring 的原型注解，用于标识数据访问层组件。
- 组件扫描会自动发现带有 @Repository、@Controller、@Component 等注解的类。
- 被发现的类会在 Spring 应用程序上下文中生成 bean 实例。
- 如果只有一个构造函数，@Autowired 可以省略；如果有多个构造函数或需要显式注入，则使用 @Autowired。
- @Autowired 可以作用于构造函数，Spring 会注入所需的依赖。
示例:
- @Repository
public class JdbcIngredientRepository implements IngredientRepository {
    private JdbcTemplate jdbcTemplate;

    public JdbcIngredientRepository(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }
}
- @Autowired
public JdbcIngredientRepository(JdbcTemplate jdbcTemplate) {
    this.jdbcTemplate = jdbcTemplate;
}
常见误区:
- 认为 @Repository 只是用于标记，不具备组件扫描功能。
- 认为必须始终显式使用 @Autowired 注解。
自测:
Q: @Repository 注解的作用是什么？
A: @Repository 是 Spring 的原型注解之一，用于标识数据访问层组件。使用它注解的类会被 Spring 组件扫描自动发现，并在应用程序上下文中生成 bean 实例。
Q: 什么时候需要使用 @Autowired 注解？
A: 当类有多个构造函数，或者只想显式地注入依赖时，可以使用 @Autowired 注解。如果类只有一个构造函数，Spring 会自动注入，可以省略 @Autowired。
