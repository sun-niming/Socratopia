## 教学地图（第 221-233 页）

### 阶段 1: 基础概览与key生成
**[当前教学焦点]** 目标: 让学习者先知道消息队列编程的完整流程，再掌握如何生成可用于共享的唯一 key。

#### 消息队列编程总览
原文给出的消息队列编程基本流程是：先用 ftok 产生唯一的 key，再用 msgget 创建或打开消息队列，然后用 msgsnd 发送消息、用 msgrcv 接收消息，最后用 msgctl 删除或控制消息队列。原文还指出，发送或接收消息失败时，常见情况是被中断或队列满。
要点:
- 编程顺序：ftok → msgget → msgsnd/msgrcv → msgctl
- 发送或接收失败的常见情况：被中断、队列满
示例:
- 流程示意：ftok(...) → msgget(...) → msgsnd(...) / msgrcv(...) → msgctl(...)
常见误区:
- 以为可以直接发送或接收消息，而不先创建/打开消息队列
- 以为发送或接收失败只会有一种原因，实际上原文提到被中断和队列满
自测:
Q: 消息队列编程的基本步骤是什么？
A: 先用 ftok 生成唯一 key，再用 msgget 创建或打开消息队列，然后用 msgsnd 发送消息、用 msgrcv 接收消息，最后用 msgctl 删除或控制消息队列。

#### ftok生成key
ftok 用于创建一个 key。原文说明，它通过 path 和 proj_id 生成消息队列使用的唯一标识；不同进程约定使用同一个 path，就可以产生相同的 key。proj_id 是一个序数，取值范围为 0-127。原文还注明相关头文件是 sys/ipc.h。
要点:
- 作用：创建一个 key
- path 用于约定不同进程生成相同的 key
- proj_id 取值范围是 0-127
- 头文件：sys/ipc.h
示例:
- ftok("/tmp/ipc_key", 1)
- 两个进程都使用同一个 path 和相同的 proj_id 调用 ftok，得到相同的 key
常见误区:
- 以为 proj_id 可以取任意整数
- 以为不同进程只要函数名相同就一定得到相同 key，而不需要约定相同的 path
自测:
Q: ftok 的作用是什么，proj_id 的范围是多少？
A: ftok 用来创建一个 key；proj_id 是一个序数，取值范围是 0-127。

可延伸方向: 解释 path 为什么要在不同进程间约定一致; 强调 proj_id 的取值范围和头文件 sys/ipc.h
