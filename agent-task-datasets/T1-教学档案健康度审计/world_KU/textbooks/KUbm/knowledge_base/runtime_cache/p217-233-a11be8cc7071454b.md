## 教学地图（第 217-233 页）

### 阶段 1: FIFO基础：概念、创建与使用流程
**[当前教学焦点]** 目标: 先让学习者理解命名管道是什么、如何创建、以及读写时为什么会阻塞。

#### FIFO概念
命名管道（FIFO）是先创建一个特殊文件（管道文件），再由不同的进程读写这个文件来实现进程间通信的一种方式。
要点:
- FIFO 以特殊文件的形式存在
- 不同进程通过读写同一个管道文件完成通信
示例:
- 在某个路径下创建一个 FIFO 文件，进程A负责写入，进程B负责读取
常见误区:
- FIFO 不是普通的文本文件；它的核心用途是进程间通信，不是长期存储数据
自测:
Q: 命名管道FIFO是什么？
A: 先创建一个特殊文件，再由不同进程读写该文件实现通信。

#### FIFO创建函数
教材列出两种创建命名管道的方法：mkfifo 和 mknod。mkfifo 的原型是 int mkfifo(char *pname, mode_t mode); 其中 pname 是路径，mode 是新建管道文件的权限，成功返回0，失败返回-1；mknod 也可用于创建特殊文件。
要点:
- mkfifo 可用于创建命名管道
- mknod 也可用于创建特殊文件
- mkfifo 的返回值：成功0，失败-1
- 教材给出了相关头文件 sys/types.h、sys/stat.h；mknod 对应 unistd.h、fcntl.h
示例:
- mkfifo("/tmp/fifo", 0666);
常见误区:
- 创建命名管道不是直接 open 就能生成，必须先用创建接口生成管道文件
自测:
Q: mkfifo 的作用是什么？
A: 创建一个命名管道，成功返回0，失败返回-1。

#### FIFO使用步骤
命名管道的编程步骤是：先使用 mkfifo 或 mknod 创建管道文件；再以只读或只写方式打开；然后用 read 读取或 write 写入；最后关闭管道文件。默认情况下，FIFO 的读写是阻塞的，而且只有两端都打开后才能进行读写。
要点:
- 先创建管道文件，再 open、read/write、close
- 默认读写是阻塞的
- 只有两端都打开后才能进行读写
示例:
- 进程A先以只读方式打开FIFO，进程B再以只写方式打开，之后才能正常通信
常见误区:
- FIFO 打开后就能立刻单向读写；实际上默认会阻塞，直到两端都打开
自测:
Q: FIFO 默认的读写方式是什么？
A: 阻塞。

可延伸方向: 可延伸到命名管道与匿名管道的比较; 可延伸到 open/read/write 的实际编程练习
