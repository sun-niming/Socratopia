## 教学地图（第 135-164 页）

### 阶段 1: 文件系统与I/O入口概念
**[当前教学焦点]** 目标: 先建立文件系统中“文件/目录—i节点”关系，再区分 Linux I/O 的两套核心抽象：文件描述符与流，并认识带缓存标准 I/O。

#### i节点查看与文件系统关联
在 Linux 文件系统中，文件和目录都与 i 节点相关联。教材用“ls -i”命令演示查看文件或目录对应的 i 节点号；根目录“/”以及其下的文件、目录都可通过 i 节点与实际文件对象建立对应关系。
要点:
- 可用命令“ls -i”查看文件或目录的 i 节点号
- 教材示意图说明：目录项与 i 节点相关联，i 节点再对应文件信息
- 根目录“/”也是文件系统中的一个目录对象，也有自己的 i 节点
示例:
- 命令示例：ls -i
- 示例输出片段：33358 bin 103828926 data 33554497 etc
常见误区:
- 误以为只有普通文件才有 i 节点，实际上目录也有 i 节点
- 误以为文件名本身就是文件全部信息；教材强调还存在 i 节点这一层
自测:
Q: 在教材示例中，用什么命令查看文件的 i 节点号？
A: 使用“ls -i”命令。
Q: 根目录“/”是否有 i 节点？
A: 有，教材明确将根目录与 i 节点关联说明。

#### 文件描述符与流
在 Unix/Linux 中，程序开始读写文件前，必须先建立程序与文件之间的连接，这个过程称为打开文件。教材给出两种描述这种连接的机制：文件描述符和流。文件描述符是 int 类型对象，多对应系统调用，提供底层输入输出接口；流建立在文件描述符之上，流操作函数属于 C 标准库。
要点:
- 打开文件是程序与文件建立连接或通信通道的过程
- 文件描述符是 int 类型对象，常用于底层 I/O 和设备操作
- 流建立在文件描述符之上，属于 ANSI C 标准库层面的 I/O
- 标准输入、标准输出、标准错误既有文件描述符常量，也有对应流对象
示例:
- 文件描述符常量：STDIN_FILENO、STDOUT_FILENO、STDERR_FILENO
- 标准流：stdin、stdout、stderr
常见误区:
- 把文件描述符和流当成完全相同的概念；教材强调流是建立在文件描述符之上的
- 误以为所有 I/O 都是标准库流操作；教材同时介绍了系统调用接口
自测:
Q: Linux 中描述程序与文件连接的两种机制是什么？
A: 文件描述符和流。
Q: stdin 属于文件描述符还是流？
A: stdin 是流；对应的标准输入文件描述符常量是 STDIN_FILENO。

#### 标准IO流操作
教材将带缓存的文件流操作称为标准 I/O 操作，符合 ANSI C 标准。它会在内存中开辟缓存区供程序中的文件使用。教材指出标准 I/O 更便于移植，效率更高。相关函数包括 fopen、fclose、fgetc、fputc、fgets、fputs、fread、fwrite、fseek、rewind、ftell，特殊流有 stdin、stdout、stderr。
要点:
- 标准 I/O 是带缓存的文件流操作
- 符合 ANSI C 标准，因此可移植性较好
- 教材强调其在内存中使用缓存区
- 常用函数覆盖字符、字符串、块读写和定位操作
- stdin、stdout、stderr 是特殊流
示例:
- 打开与关闭：fopen、fclose
- 字符操作：fgetc、fputc
- 块操作：fread、fwrite
- 定位操作：fseek、rewind、ftell
常见误区:
- 把标准 I/O 和无缓存系统调用混为一谈；教材明确区分了两类 I/O
- 误以为 stdin、stdout、stderr 只在系统调用层存在；教材说明它们也是特殊流
自测:
Q: 标准 I/O 是否带缓存？
A: 是，教材称其为带缓存的文件流操作。
Q: 教材认为标准 I/O 有什么优点？
A: 更便于移植，效率更高。

可延伸方向: 可延伸比较无缓存 I/O 与标准 I/O 的适用场景; 可延伸讲解标准输入输出错误的用途
