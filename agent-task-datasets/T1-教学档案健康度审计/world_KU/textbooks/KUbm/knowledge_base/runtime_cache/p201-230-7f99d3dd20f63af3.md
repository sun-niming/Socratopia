## 教学地图（第 201-203 页）

### 阶段 1: 建立信号的整体认识
**[当前教学焦点]** 目标: 先让学习者理解信号从产生到被内核递送、再到进程响应的全过程，并认识 kill 是发送信号的基本接口。

#### 信号生命周期
信号从产生开始，先由内核保存并管理，再在合适时机传递给目标进程；进程收到后，会按照默认动作或已经注册的信号处理程序作出响应。
要点:
- 信号可以由 kill 命令、组合按键、异常事件等方式产生
- 信号产生后通常先由内核保存，再由内核递送给相关进程
- 进程对信号的处理方式包括默认例程和注册的信号处理程序
示例:
- 进程A使用 kill 命令向进程B发送信号
- 用户按下组合按键产生信号
- 程序发生异常事件而产生信号
常见误区:
- 信号一旦产生就会立刻同步执行处理
- 信号处理一定会终止进程
- 信号只能由程序显式调用函数产生
自测:
Q: 信号从产生到被处理，大致经历哪些环节？
A: 先产生，再由内核保存和传递，最后由进程按默认动作或已注册处理程序响应。
Q: 教材中提到的信号来源有哪些？
A: kill命令、组合按键、异常事件。

#### kill函数
kill(pid_t pid, int sig) 是发送信号的系统调用，用来向指定进程发送 sig 信号；教材给出的相关头文件是 sys/types.h 和 signal.h。
要点:
- 函数原型为 int kill(pid_t pid, int sig)
- 其作用是向目标进程发送指定信号 sig
- 教材列出的头文件是 sys/types.h 和 signal.h
示例:
- int r = kill(1234, sig);  // 向 PID 为 1234 的进程发送 sig
常见误区:
- kill 只能用来“杀死”进程
- kill 的唯一用途是终止当前进程
- 调用 kill 必须总是立刻让进程退出
自测:
Q: kill(pid_t pid, int sig) 的基本作用是什么？
A: 向指定进程发送 sig 信号。
Q: 教材中 kill 需要包含哪些头文件？
A: sys/types.h 和 signal.h。

可延伸方向: 补充信号的常见来源; 区分信号发送与信号处理
