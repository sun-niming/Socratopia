### 阶段 1: 文件I/O基础
**[当前教学焦点]** 目标: 先让学习者掌握文件检测、文件状态标志以及阻塞/非阻塞读写行为，为后续加锁和文件流操作打基础。

#### access文件检测
access是用于检测文件可访问性的系统调用，函数原型为int access(char *path, int mod)。其中path是待检测文件的路径，mod是检测项目，可以取R_OK、W_OK、X_OK、F_OK之一，或将多个检测项按位或后一起测试。F_OK表示检测文件是否存在。
要点:
- access属于不带缓存的文件I/O系统调用
- path参数表示要检测的文件路径
- mod可用于检测读、写、执行权限或文件是否存在
- 多个检测项可以按位或组合使用
示例:
- access("/tmp/a.txt", F_OK)：检测/tmp/a.txt是否存在
- access("./app", R_OK | X_OK)：检测当前目录下app是否可读且可执行
常见误区:
- 把F_OK误解为“文件可打开”，原文只说明它表示“是否存在”
- 认为mod一次只能取一个值，原文说明也可多值按位或
自测:
Q: access中的F_OK表示什么？
A: 表示检测文件是否存在。

#### fcntl修改文件状态标志
fcntl可用于获取或修改文件描述符的状态标志，也可用于加锁。与状态标志相关时，函数形式为int fcntl(int fd, int cmd[, flags|lockType])。fd是文件描述符，cmd是操作命令。F_GETFL用于获取指定描述符的状态标志，F_SETFL用于重设文件状态标志。原文给出的可重设标志包括O_APPEND、O_NONBLOCK、O_ASYNC。
要点:
- fd表示被操作的文件描述符
- F_GETFL用于读取状态标志
- F_SETFL用于写回新的状态标志
- flags与open函数中的flags含义相同
示例:
- 先用fcntl(fd, F_GETFL)取出flags，再修改后用fcntl(fd, F_SETFL, flags)写回
- 将O_NONBLOCK加入状态标志，可改变读写行为
常见误区:
- 把fcntl只看成加锁函数，原文同时强调它还能修改状态标志
- 把F_GETFL和F_SETFL混淆，一个是获取，一个是设置
自测:
Q: fcntl中哪个命令用于获取文件描述符的状态标志？
A: F_GETFL。

#### 阻塞与非阻塞文件操作
文件默认以阻塞方式打开。阻塞方式下，如果当前不能进行读写，进程会等待到可操作时再继续。非阻塞方式下，如果当前不能读写，读写函数会立即返回-1，并将errno置为EWOULDBLOCK。非阻塞方式既可以在打开文件时通过flags加入O_NONBLOCK设置，也可以在文件已打开后通过fcntl修改。修改步骤是：先用fcntl获取flags，再用flags |= O_NONBLOCK设为非阻塞，或用flags &= ~O_NONBLOCK设为阻塞，最后再用fcntl把新flags写回。
要点:
- 文件默认是阻塞方式打开
- 打开时加入O_NONBLOCK可设为非阻塞
- 非阻塞读写失败时立即返回-1，并置errno为EWOULDBLOCK
- 已打开文件可通过fcntl修改阻塞模式
示例:
- 设置非阻塞：flags |= O_NONBLOCK
- 恢复阻塞：flags &= ~O_NONBLOCK
常见误区:
- 认为非阻塞失败时会一直等待，实际上会立即返回-1
- 认为阻塞/非阻塞只能在open时决定，原文说明也可用fcntl修改
自测:
Q: 非阻塞方式下如果暂时不能读写，函数会怎样返回？
A: 会立即返回-1，并把errno置为EWOULDBLOCK。

可延伸方向: 补充系统调用与库函数的区别; 结合errno讲解错误处理
