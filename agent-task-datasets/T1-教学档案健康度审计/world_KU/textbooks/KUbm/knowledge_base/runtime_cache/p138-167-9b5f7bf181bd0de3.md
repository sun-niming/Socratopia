#### system系统调用
system函数用于执行一条shell命令。其格式为 int system(char *cmdStr)。调用时会先产生一个子进程，再由该子进程调用“/bin/sh -c cmdStr”执行参数cmdStr所指定的命令。按照原文说明：/bin/sh调用失败返回127，其他失败返回-1，成功返回0。
要点:
- system通过子进程执行命令
- 实际调用形式是“/bin/sh -c cmdStr”
- 原文给出的返回值含义是：/bin/sh失败为127，其他失败为-1，成功为0
示例:
- system("ls -l")：通过shell执行ls -l命令
常见误区:
- 误以为system是当前进程直接执行命令，而不是先创建子进程再调用shell
- 误以为cmdStr不是shell命令字符串
自测:
Q: system函数如何执行cmdStr指定的命令？
A: 先产生一个子进程，再调用“/bin/sh -c cmdStr”来执行该命令。

#### chmod修改文件权限
chmod函数用于修改path指定文件的权限，格式为 int chmod(char *path, mode_t mode)。使用时要注意当前用户身份。相关头文件为 sys/types.h 和 sys/stat.h。mode是一个32位无符号整数，可用权限位组合表示所有者、组成员和其他人的读、写、执行权限。
要点:
- chmod修改指定路径文件的权限
- 需要包含sys/types.h和sys/stat.h
- 可用的权限位包括S_IRUSR、S_IWUSR、S_IXUSR、S_IRGRP、S_IWGRP、S_IXGRP、S_IROTH、S_IWOTH、S_IXOTH
示例:
- chmod("a.txt", S_IRUSR | S_IWUSR)：给所有者读写权限
常见误区:
- 误以为chmod只影响所有者权限，实际上还可设置组成员和其他人权限
- 误以为权限值只能写成一个单独常量，实际上可以组合多个权限位
自测:
Q: S_IRUSR和S_IXGRP分别表示什么权限？
A: S_IRUSR表示所有者读权限，S_IXGRP表示组成员执行权限。

#### umask权限掩码
umask函数用于修改当前进程环境的权限掩码，格式为 mode_t umask(mode_t cmask)。参数cmask使用八进制值表示。函数会把当前进程的权限掩码改为cmask，并返回修改之前的掩码。
要点:
- umask作用于当前进程环境
- cmask使用八进制值
- 返回值是修改前的掩码
示例:
- old = umask(022)：把当前进程权限掩码改为022，并得到旧掩码old
常见误区:
- 误以为umask返回的是新掩码，实际上原文说明返回的是修改之前的掩码
- 误以为umask修改的是某个文件的权限，实际上它修改的是进程环境中的权限掩码
自测:
Q: umask(cmask)调用后返回什么？
A: 返回修改之前的权限掩码。

#### stat系列函数获取文件属性
fstat、stat和lstat都用于获取文件属性信息，并把结果填充到struct stat类型的缓冲区中。fstat的格式为 int fstat(int fd, struct stat *buf)，它按文件描述符获取属性；stat和lstat按路径获取属性。二者的区别在于：如果目标文件是符号链接，stat返回链接所指向文件的信息，而lstat返回符号链接本身的属性信息。
要点:
- fstat按文件描述符获取属性
- stat和lstat按路径获取属性
- 对符号链接，stat看目标文件，lstat看链接本身
示例:
- fstat(fd, &st)：获取fd对应文件的属性
- lstat("linkfile", &st)：获取符号链接自身属性
常见误区:
- 误以为stat和lstat完全相同，实际上它们对符号链接的处理不同
- 误以为fstat也接收路径参数，实际上它接收文件描述符
自测:
Q: 当path是符号链接时，stat和lstat返回的信息有什么区别？
A: stat返回该链接所指向文件的信息，lstat返回符号链接本身的属性信息。
