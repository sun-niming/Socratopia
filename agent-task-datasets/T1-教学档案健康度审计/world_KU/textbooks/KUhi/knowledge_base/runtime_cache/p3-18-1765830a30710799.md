## 教学地图（第 3-18 页）

### 阶段 1: 复杂度基础
**[当前教学焦点 / 队列起点]** 目标: 先建立复杂度分析所需的基本概念：算法与程序的区别、输入规模、时间复杂度、对数/指数增长和空间复杂度。

#### 算法与程序、输入规模
算法是解决一类问题的有限步骤描述，强调输入、输出、可行步骤和终止性；程序是用具体语言在特定运行环境中的实现。做复杂度分析时，第一步必须先确定输入规模，并用统一符号表示，例如数组常用 n，图常用 V 和 E，字符串匹配常用文本长度 n 和模式长度 m。
要点:
- 先区分“算法”和“程序”
- 复杂度分析必须先确定输入规模
- 不同问题的输入规模符号可能不同
示例:
- 查找学生成绩表中最高分：输入规模可用成绩条数 n 表示
- 在日志文件中查找某个时间之后第一条记录：无序日志只能顺序扫描，按时间排序后可二分查找
常见误区:
- 把程序和算法混为一谈
- 不先说明输入规模就直接写复杂度
- 所有问题都用 n 表示输入规模
自测:
Q: 为什么做复杂度分析前要先确定输入规模？
A: 因为时间和空间复杂度都要相对于输入规模来表达，不同问题的规模符号可能不同，如数组用 n，图用 V 和 E。

#### 时间复杂度分析模板
分析时间复杂度时，按固定步骤进行：先确定输入规模，再找基本操作，然后统计基本操作执行次数，去掉低阶项和常数，最后写出渐进阶。顺序结构看主导项，嵌套循环通常按层分析；如果内层次数依赖外层变量，就要把每一轮的次数累加。
要点:
- 先定输入规模，再找基本操作
- 统计执行次数后再化简
- 内层次数依赖外层变量时要逐轮累加
示例:
- 三角形循环中内层次数是 1+2+...+n = n(n+1)/2，所以时间复杂度是 O(n^2)
- 双层循环 for i=1..n; for j=i..n 不能直接看成简单的 n*n，需要按每轮求和
常见误区:
- 看到双层循环就一定写 O(n^2)
- 复杂度题可以直接猜答案
- 只写结果，不说明基本操作和输入规模
自测:
Q: 分析三角形循环时，为什么不是 O(n)？
A: 因为内层总执行次数是 1+2+...+n = n(n+1)/2，数量级是 n^2，而不是 n。

#### 对数与指数复杂度
如果问题规模每次按固定比例缩小，通常会出现对数复杂度；如果每层分裂出多个选择，而且递归深度与 n 相关，往往会出现指数或阶乘复杂度。判断这类复杂度时，关键是看第 k 次之后规模变成多少。
要点:
- 按比例缩小常对应 O(log n)
- 分裂出多个选择且深度与 n 相关，可能导致指数或阶乘复杂度
- 用第 k 次后的规模推导比死记结论更可靠
示例:
- while i<n: i=i*2，执行次数约为 log2 n
- while n>1: n=floor(n/3)，每次规模缩小为原来的 1/3
常见误区:
- 只记住 O(log n) 的结论，却不会推导
- 认为所有循环都属于线性或平方复杂度
- 把“对数复杂度”误解成“很小就不用分析”
自测:
Q: while n>1: n=floor(n/3) 的时间复杂度是多少？
A: O(log n)，因为每次规模按 1/3 缩小，循环次数约为 log3 n。

#### 空间复杂度
空间复杂度表示算法运行时额外使用的空间，既包括显式辅助结构，也包括隐式递归栈；通常不把输入本身占用的空间算作辅助空间。答题时要明确写出“除输入外的额外空间”。
要点:
- 空间复杂度要考虑辅助结构
- 递归调用会占用递归栈
- 一般不把输入本身算作辅助空间
示例:
- 循环二分查找的辅助空间是 O(1)
- 递归二分查找的递归深度是 O(log n)，所以栈空间是 O(log n)
- 归并排序需要 O(n) 辅助数组，递归栈 O(log n)，总辅助空间由 O(n) 主导
常见误区:
- 只看显式数组，不看递归栈
- 把输入本身也算进辅助空间
- 认为只要时间快，空间就不用分析
自测:
Q: 为什么递归二分查找的空间复杂度不是 O(1)？
A: 因为递归调用会产生递归栈，递归深度为 O(log n)，所以额外栈空间也是 O(log n)。

可延伸方向: 可先用日志查找和循环例子建立直观; 可延伸到常数项、低阶项与渐进表示法

### 阶段 2: 递归分析工具
**[后续教学队列]** 目标: 掌握递归问题的复杂度分析方法：先写递归式，再用递归树展开，并能用模板组织标准答案。

#### 递归式建立
递归算法的复杂度通常先翻译成递归式。建立递归式时要分成三部分：子问题个数、子问题规模、非递归工作量。例如二分查找是 T(n)=T(n/2)+O(1)，归并排序是 T(n)=2T(n/2)+O(n)，快速排序最坏是 T(n)=T(n-1)+O(n)。
要点:
- 递归式由子问题个数、子问题规模、非递归工作量三部分构成
- 要把伪代码翻译成递归式
- 分解和合并的代价要分开看
示例:
- 二分查找：T(n)=T(n/2)+O(1)
- 归并排序：T(n)=2T(n/2)+O(n)
- 快速排序最坏情况：T(n)=T(n-1)+O(n)
常见误区:
- 把递归问题直接套公式，不看子问题数量和规模
- 把分解代价和合并代价混在一起
- 只会写递归代码，不会写递归式
自测:
Q: 如果一个问题分成 3 个规模为 n/2 的子问题，再花 n 做合并，递归式怎么写？
A: T(n)=3T(n/2)+O(n)。

#### 递归树方法
递归树方法是把递归式按层展开来分析。若每层总代价相同，就用“层数乘以每层代价”；若每层代价递增或递减，就判断根、叶或中间层谁占主导。递归树不是装饰图，而是解释递归复杂度的直观工具。
要点:
- 把递归式按层展开
- 每层总代价相同可直接乘以层数
- 代价变化时要判断主导层
示例:
- T(n)=2T(n/2)+n：第 0 层代价 n，第 1 层两个 n/2 合计仍是 n，第 k 层合计仍是 n，层数是 log n，所以总计 O(n log n)
- T(n)=2T(n/2)+1：每层代价不断增加，层数约为 log n，总体是 O(n)
常见误区:
- 递归树只是画图题的装饰
- 只会套结果，不会解释每层代价
- 看见 2T(n/2) 就默认一定是 O(n log n)
自测:
Q: 用递归树分析 T(n)=2T(n/2)+1 的复杂度，结果是什么？
A: O(n)，因为第 k 层共有 2^k 个结点，每个代价为 1，累计到深度 log n 时总和为 O(n)。

#### 伪代码复杂度分析
给定伪代码时，要先标出每条语句属于哪个循环或递归层级，再统计执行次数。若有 if 分支，通常按最坏情况分析；只有题目要求平均情况时，才讨论概率或分布。变量 n、m、V、E、W 的含义也必须写清楚。
要点:
- 先标层级，再统计次数
- if 分支通常按最坏情况分析
- 变量符号必须解释清楚
示例:
- 外层 i 从 1 到 n，内层 j 每次从 1 开始翻倍到 i，则内层是 O(log i)，总时间是 sum log i = O(n log n)
- for i=1..n: j=1; while j<i: j=2*j 不能直接看成 O(n^2)
常见误区:
- 所有双层循环都是 O(n^2)
- 有分支就默认平均情况
- 变量符号不写含义也能算复杂度
自测:
Q: for i=1..n: j=1; while j<i: j=2*j 的时间复杂度是多少？
A: O(n log n)，因为第 i 轮内层执行次数约为 log i，总和为 sum_{i=1}^n log i = O(n log n)。

#### 本章答题模板
复杂度分析题可按四句话组织：输入规模为……；基本操作为……；该操作执行……次，因此时间复杂度为……；额外使用……，因此空间复杂度为……。如果是递归题，再补一行递归式和递归树解释。
要点:
- 用固定句式作答更稳妥
- 时间复杂度要说明“为什么是这个次数”
- 递归题最好补递归式或递归树
示例:
- 输入规模为数组长度 n。基本操作为元素比较。外层循环 n 次，内层第 i 次执行 i 次，总次数为 n(n+1)/2，所以时间复杂度 O(n^2)。只使用常数个变量，空间复杂度 O(1)。
常见误区:
- 只写 Big-O，不说明依据
- 递归题不写递归式也能得完整分
- 时间和空间只需要写一个
自测:
Q: 复杂度分析题的标准答题结构是什么？
A: 输入规模、基本操作、执行次数与时间复杂度、额外空间与空间复杂度；递归题再补递归式和递归树。

可延伸方向: 可延伸到 Master 定理作为后续工具; 可练习把伪代码逐行翻译成递归式
