## 教学地图（第 355-384 页）

### 阶段 1: 共享段与分段保护
**[当前教学焦点 / 队列起点]** 目标: 先讲清共享段如何按计数分配和回收，再讲分段保护的三类检查，建立对分段存储安全性的整体认识。

#### 共享段分配
当一个进程第一次请求使用某个共享段时，系统先为该共享段分配一块物理内存区，再把共享段调入该区，同时将该区始址填入请求进程段表中的相应项；另外还要在共享段表中增加一项，填写有关信息，并把 count 置为 1。之后，若其他进程也要调用该共享段，因为该段已经在内存中，所以不必再分配新的物理内存，只需在调用进程的段表中增加相应表项，填写该共享段的物理地址，并在共享段表中登记调用进程名、存取控制等信息，然后执行 count:=count+1，以表明有多个进程共享该段。
要点:
- 第一次请求共享段时才分配物理内存并装入该段
- 后续进程不再重复分配，只记录同一物理地址
- 共享段表要记录相关信息，并用 count 表示当前共享该段的进程数
示例:
- 第一次请求时：分配物理区 -> 调入共享段 -> 段表填始址 -> 共享段表中 count=1
- 第二个进程调用时：段表增加表项，count:=count+1
常见误区:
- 共享段不是每个进程各自复制一份
- 只要有新进程使用共享段，就要重新装入内存，这个理解是错的
自测:
Q: 一个共享段被第一个进程使用时，系统要做哪些事情？
A: 系统先分配物理区，再把共享段调入该区，把始址填入该进程段表，并在共享段表中建表项，令 count 置为 1。

#### 共享段回收
当某个进程不再需要某共享段时，应先撤消该进程段表中与该共享段对应的表项，并执行 count:=count-1。若减 1 后 count 变为 0，说明已经没有进程在使用该段，这时系统应回收该共享段占用的物理内存，并取消共享段表中对应的表项；若减 1 后 count 不为 0，则只取消调用者进程在共享段表中的有关记录即可。
要点:
- 回收共享段时，先删除该进程自己的段表项
- count 减 1 后若为 0，才由系统回收物理内存
- count 减 1 后若不为 0，说明仍有进程在共享该段，只需删调用者记录
示例:
- count 从 2 减到 1：不回收物理内存，只删除调用者记录
- count 从 1 减到 0：回收该共享段的物理内存，并取消共享段表项
常见误区:
- 某个进程退出共享段后，系统立刻释放整段内存，这不一定对
- 只删除共享段表就够了，不需要处理进程段表，这种理解不完整
自测:
Q: 共享段回收时，count 变成 0 说明什么？
A: 说明已经没有进程使用该共享段，系统应回收其物理内存并取消共享段表中的对应表项。

#### 分段保护
分段保护主要包括三类检查：越界检查、存取控制检查和环保护机构。存取控制检查包括只读、只执行、读/写等限制。环保护机构规定：一个程序可以访问驻留在相同环或较低特权环中的数据；一个程序可以调用驻留在相同环或较高特权环中的服务。
要点:
- 越界检查用于防止访问超出段界限的地址
- 存取控制检查可规定只读、只执行、读/写等权限
- 环保护机构同时约束数据访问和服务调用：数据访问限于相同环或较低特权环，服务调用限于相同环或较高特权环
示例:
- 只读段只能读不能写
- 一个程序访问相同环或较低特权环中的数据
- 一个程序调用相同环或较高特权环中的服务
常见误区:
- 分段保护只做边界检查，不做权限检查，这不完整
- 环保护只限制数据访问，不限制程序调用服务，这不对
自测:
Q: 分段保护包括哪些检查？
A: 包括越界检查、存取控制检查和环保护机构。

可延伸方向: 可延伸到段式存储管理的其他机制; 可比较分段与分页的保护思想

### 阶段 2: I/O系统概述与分层
**[后续教学队列]** 目标: 让学习者先知道 I/O 系统要解决什么问题，再理解其层次化组织方式和面向不同设备的接口。

#### I/O系统主要功能
I/O 系统管理的主要对象是 I/O 设备和相应的设备控制器。它的主要任务是完成用户提出的 I/O 请求，提高 I/O 速率，提高设备利用率，并为更高层进程方便地使用这些设备提供手段。教材给出的 I/O 系统基本功能共有六项：隐藏物理设备细节、与设备无关性、提高处理机和 I/O 设备利用率、对 I/O 设备进行控制、确保对设备的正确共享、错误处理。
要点:
- 管理对象是 I/O 设备及其设备控制器
- 基本任务包括完成 I/O 请求、提高 I/O 速率、提高设备利用率
- 六项基本功能是：隐藏细节、设备无关性、并行利用率、设备控制、正确共享、错误处理
示例:
- 键盘、鼠标器、磁盘、打印机等都由 I/O 系统统一管理
- 让处理机和 I/O 设备尽量并行工作，以提高利用率
常见误区:
- I/O 系统只是把数据从设备搬到内存
- I/O 系统的作用只有设备驱动程序一层
自测:
Q: I/O 系统的六项基本功能是什么？
A: 隐藏物理设备细节、与设备无关性、提高处理机和 I/O 设备利用率、对 I/O 设备进行控制、确保对设备的正确共享、错误处理。

#### I/O软件层次结构
为了使复杂的 I/O 软件具有清晰结构、更好的可移植性和易适应性，现代操作系统通常把 I/O 软件组织成层次式结构。教材给出的四个层次是：用户层软件、设备独立性软件、设备驱动程序和中断处理程序。各层利用下层提供的服务，完成某些子功能，并屏蔽实现细节，向上层提供服务。
要点:
- I/O 软件通常分为四层：用户层软件、设备独立性软件、设备驱动程序、中断处理程序
- 用户层软件提供与用户交互的接口和库函数
- 设备独立性软件负责统一接口、设备命名、保护、分配与释放等
- 设备驱动程序把抽象 I/O 请求转换成具体设备命令；中断处理程序负责保存现场、处理中断、恢复现场
示例:
- 用户层可直接调用与 I/O 有关的库函数
- 设备驱动程序把上层抽象命令装入设备控制器寄存器
常见误区:
- 所有 I/O 功能都在设备驱动程序里完成
- 用户程序可以直接操作硬件寄存器
自测:
Q: I/O 软件的四个层次分别是什么？
A: 用户层软件、设备独立性软件、设备驱动程序、中断处理程序。

#### I/O系统接口
I/O 系统与高层系统之间的接口，会因设备类型不同而进一步分成不同接口。教材给出的主要接口有三类：块设备接口、流设备接口和网络接口。块设备接口用于块设备，能隐藏磁盘的二维结构，并把抽象命令映射为低层操作；流设备接口也称字符设备接口，反映大部分字符设备的本质特征，常用 get、put 和 in-control 操作；网络接口用于支持网络通信，使计算机能通过网络与其他计算机通信或上网浏览。
要点:
- 块设备接口面向块设备，隐藏磁盘二维结构
- 流设备接口也称字符设备接口，常用 get、put、in-control
- 网络接口支持网络通信与上网浏览
示例:
- 磁盘通常使用块设备接口
- 键盘等字符设备可用流设备接口
- 网络通信软件通过网络接口与外部计算机通信
常见误区:
- 所有设备都应该使用同一种接口
- 块设备接口只是简单的读写命令，不涉及结构隐藏
自测:
Q: 教材中 I/O 系统接口分为哪三类？
A: 块设备接口、流设备接口和网络接口。

可延伸方向: 可延伸到设备无关性软件的具体实现; 可比较块设备、字符设备和网络设备的接口差异
