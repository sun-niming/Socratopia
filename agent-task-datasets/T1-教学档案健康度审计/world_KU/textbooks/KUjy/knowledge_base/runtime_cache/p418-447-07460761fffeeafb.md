## 教学地图（第 418-447 页）

### 阶段 1: I/O软件与SPOOLing基础
**[当前教学焦点 / 队列起点]** 目标: 先建立I/O软件分层、用户层获得系统服务的方式，以及SPOOLing的基本动机和作用。

#### 用户层I/O软件
用户层的 I/O 软件是指并不完全位于操作系统内核中的那部分 I/O 软件。原文说明，大部分 I/O 软件在操作系统内部，但仍有少部分位于用户层，包括与用户程序链接在一起的库函数，以及完全运行于内核之外的假脱机系统等。
要点:
- 大部分 I/O 软件在操作系统内部。
- 用户层 I/O 软件包括与用户程序链接的库函数。
- 假脱机系统等也可完全运行在内核之外，但仍属于 I/O 系统。
示例:
- 库函数与用户程序连接在一起，包含在运行时装入内存的二进制程序中。
- spooling 系统和网络传输文件时常使用的守护进程，都是运行在内核之外的程序。
常见误区:
- 认为所有 I/O 软件都只能在内核中。
- 把用户层 I/O 软件等同于普通应用程序，忽略其与 I/O 系统的关系。
自测:
Q: 用户层的 I/O 软件包括哪些内容？
A: 包括与用户程序链接在一起的库函数，以及完全运行于内核之外的假脱机系统等。
Q: 为什么说 spooling 系统仍属于 I/O 系统？
A: 因为它虽然完全运行在内核之外，但它仍承担 I/O 相关功能，所以归属于 I/O 系统。

#### 系统调用与库函数
用户层软件要获得操作系统服务，必须通过系统调用。现代高级语言和 C 语言通常提供与各系统调用一一对应的库函数，用户程序通过调用这些库函数来使用系统调用。库函数与调用程序链接在一起，构成运行时装入内存的二进制程序的一部分。
要点:
- 用户层软件通过系统调用获取操作系统服务。
- 高级语言和 C 语言通常提供与系统调用一一对应的库函数。
- 库函数与用户程序链接在一起，属于运行时装入内存的二进制程序内容。
示例:
- 用户程序通过调用对应的库函数使用系统调用。
常见误区:
- 认为用户程序可以直接绕过系统调用访问操作系统服务。
- 认为库函数只是编译时的可选附加内容，不属于 I/O 系统。
自测:
Q: 用户层软件如何取得操作系统服务？
A: 必须通过一组系统调用来取得操作系统服务。
Q: 库函数和系统调用是什么关系？
A: 通常是一一对应的，用户程序通过调用对应的库函数使用系统调用。

#### SPOOLing技术
SPOOLing 是一种在联机情况下实现同时外围操作的技术，用于缓和 CPU 的高速性与 I/O 设备低速性之间的矛盾。它借助多道程序环境，用一道程序模拟脱机输入时的外围控制机功能，把低速 I/O 设备上的数据传送到高速磁盘；再用另一道程序模拟脱机输出功能，把数据从磁盘传送到低速输出设备。SPOOLing 技术可有效地把一台独占设备改造成共享设备。
要点:
- SPOOLing 的目的是缓和 CPU 高速与 I/O 低速之间的矛盾。
- 它是在联机情况下实现的同时外围操作。
- 它可把独占设备改造成共享设备。
示例:
- 原文中的定义可概括为：SPOOLing(Simultaneaus Periphernal Operating On-Line)。
- 把低速 I/O 设备上的数据传送到高速磁盘；或者把磁盘上的数据传送到低速输出设备。
常见误区:
- 把 SPOOLing 误认为必须脱机运行。
- 把 SPOOLing 误认为只是简单的磁盘缓存。
- 认为它只能用于输出，不能用于输入。
自测:
Q: SPOOLing 技术的主要作用是什么？
A: 用于缓和 CPU 的高速性与 I/O 设备低速性之间的矛盾，并将独占设备改造成共享设备。
Q: SPOOLing 为什么说是联机情况下的同时外围操作？
A: 因为外围操作与 CPU 对数据的处理可以同时进行，而且是在主机直接控制下实现的。

可延伸方向: 区分用户层软件与内核中的I/O软件; 联系库函数与系统调用的对应关系

### 阶段 2: SPOOLing系统与共享打印
**[后续教学队列]** 目标: 讲清SPOOLing系统由哪些部分构成，以及它如何把独占打印机变成可共享设备。

#### SPOOLing系统组成
SPOOLing 系统是对脱机输入、输出工作的模拟，必须有高速随机外存支持，通常采用磁盘存储技术。它主要由四部分组成：输入井和输出井、输入缓冲区和输出缓冲区、输入进程 $SP_i$ 和输出进程 $Spo$、井管理程序。对于请求打印，还会形成请求打印队列；系统为每一个请求打印的进程建立一张请求打印表。
要点:
- SPOOLing 系统依赖高速随机外存，通常是磁盘。
- 系统主要由输入井/输出井、输入/输出缓冲区、输入进程 $SP_i$ 和输出进程 $Spo$、井管理程序组成。
- 请求打印队列由若干请求打印表构成。
示例:
- 输入井和输出井；输入缓冲区和输出缓冲区；输入进程 $SP_i$ 和输出进程 $Spo$；井管理程序。
常见误区:
- 认为 SPOOLing 系统只需要一个缓冲区即可。
- 认为请求打印队列中存放的是实际打印数据而不是请求打印表。
自测:
Q: SPOOLing 系统为什么需要高速随机外存？
A: 因为它是对脱机输入、输出工作的模拟，通常要借助磁盘存储技术来支持。
Q: SPOOLing 系统主要有哪些部分？
A: 输入井和输出井、输入缓冲区和输出缓冲区、输入进程 $SP_i$ 和输出进程 $Spo$、井管理程序。

#### SPOOLing系统特点
SPOOLing 系统有三个主要特点：提高 I/O 的速度；将独占设备改造为共享设备；实现虚拟设备功能。这里的“虚拟设备功能”是指通过软件和磁盘等手段，让用户感觉设备仿佛可共享、可并行使用。
要点:
- 提高 I/O 速度。
- 将独占设备改造为共享设备。
- 实现虚拟设备功能。
示例:
- 原文列出的三点：提高了 I/O 的速度；将独占设备改造为共享设备；实现了虚拟设备功能。
常见误区:
- 把 SPOOLing 的作用只理解为“缓存一点数据”。
- 认为它只解决打印问题，不具有更一般的设备共享意义。
自测:
Q: SPOOLing 系统的三个特点是什么？
A: 提高 I/O 速度；将独占设备改造为共享设备；实现虚拟设备功能。

#### 共享打印机的SPOOLing流程
在 SPOOLing 机制下，一台打印机可以被多个用户共享。用户进程请求打印输出时，输出进程先在输出井中申请一个空闲盘块区，把要打印的数据放入其中；再申请一张空白的用户请求打印表，填入用户打印要求，并将该表挂到请求打印队列中。若打印机空闲，输出进程就从队首取出请求打印表，把输出井中的数据送入内存缓冲区，再由打印机打印。
要点:
- 输出进程先把打印数据放入输出井中的空闲盘块区。
- 输出进程再建立用户请求打印表并挂到请求打印队列。
- 打印机空闲时，按队首请求从输出井取数据，经内存缓冲区送打印机。
示例:
- 当用户进程请求打印输出时，输出进程在输出井中申请一空闲盘块区，并将要打印的数据送入其中。
常见误区:
- 认为打印数据是直接从用户进程立即送到打印机。
- 认为请求打印表只是形式文件而不参与调度。
自测:
Q: 共享打印机的 SPOOLing 过程中，输出进程先做哪两件事？
A: 先在输出井中为打印数据申请空闲盘块区并写入数据；再为用户进程申请请求打印表，填入打印要求并挂到请求打印队列上。
Q: 打印机空闲时，输出进程如何处理请求？
A: 从请求打印队列队首取出请求打印表，根据表中要求把输出井中的数据传送到内存缓冲区，再由打印机打印。

可延伸方向: 用流程图解释请求打印队列与输出井; 比较直接打印与假脱机打印
