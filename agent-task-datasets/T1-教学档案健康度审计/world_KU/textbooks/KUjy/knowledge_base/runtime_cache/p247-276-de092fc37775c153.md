## 教学地图（第 247-276 页）

### 阶段 1: 死锁处理
**[当前教学焦点 / 队列起点]** 目标: 先让弱模型掌握死锁检测时如何记录可用资源与可简化进程，再说明死锁发生后如何解除。

#### 死锁检测数据结构
死锁检测时，系统维护 Available、Work 和 L 三类数据：Available 表示 m 类资源中各类资源的可用数目；Work 是当前工作向量，初值为 $Work=Available$；L 表示已被判定可以处理完的进程集合。先把不占用资源的进程记入 L 表，再反复寻找满足 $Request_i\le Work$ 的进程：令 $Work=Work+Allocation_i$，并把该进程记入 L。若最后不能把所有进程都记入 L，说明资源分配图不可完全简化，系统状态会发生死锁。
要点:
- Available 记录每类资源当前可用的数量。
- Work 表示检测过程中临时可用的资源向量，初值等于 Available。
- L 用来记录已经能够“消去”的进程。
- 只要存在 $Request_i\le Work$ 的进程，就可以继续简化并释放它占有的资源。
示例:
- 初值：$Work=Available$。若找到某个进程满足 $Request_i\le Work$，则令 $Work=Work+Allocation_i$，再把它记入 L 表。
常见误区:
- 不是所有进程一开始都能直接加入 L 表。
- 不能把“未能全部简化”误解为算法失败；它恰恰表示系统可能发生死锁。
自测:
Q: 死锁检测中 Work 的初值是什么？
A: $Work=Available$。
Q: 若最终不能把所有进程都记入 L 表，说明什么？
A: 说明资源分配图不可完全简化，系统状态会发生死锁。

#### 死锁解除方法
教材给出的死锁解除的两种基本方法是剥夺资源和撤消进程。剥夺资源是把某些资源从进程手中收回，再重新分配；撤消进程是直接终止某些进程，释放其占有的资源，从而打破死锁。
要点:
- 剥夺资源：收回资源后重新分配。
- 撤消进程：终止部分进程并释放资源。
- 这两种方法都是在死锁已经发生后用于解除死锁。
示例:
- 当系统发生死锁时，可以选择剥夺资源，或者撤消某些进程来释放资源。
常见误区:
- 解除死锁不只有一种办法。
- 不是所有场景都必须先撤消进程，也可以先考虑剥夺资源。
自测:
Q: 教材中给出的死锁解除方法有哪些？
A: 剥夺资源、撤消进程。

可延伸方向: 可对比“检测”与“解除”的职责差异; 可用资源向量和进程集合的更新过程做小例子演示

### 阶段 2: 存储器层次
**[后续教学队列]** 目标: 讲清存储器为什么要分层，以及主存、寄存器、高速缓存、磁盘缓存分别承担什么作用。

#### 存储器层次结构
计算机存储器通常采用多层结构。对通用计算机而言，存储层次至少应具有三级：最高层是 CPU 寄存器，中间是主存，最底层是辅存；在较高档的计算机中，还可以细分为寄存器、高速缓存、主存储器、磁盘缓存、固定磁盘、可移动存储介质等多层。建立层次结构的根本原因是：处理机速度很快，而存储器不仅要足够快，还要有很大容量并且价格便宜。
要点:
- 通用计算机存储层次至少三级：寄存器、主存、辅存。
- 较高档系统可以把存储层次细分为更多层。
- 存储器层次的要求是：速度快、容量大、价格低。
示例:
- 三级结构可概括为：CPU 寄存器 → 主存 → 辅存。
常见误区:
- 存储器层次不是越少越好，而是为了兼顾速度、容量和成本。
- 辅存不是与寄存器同等级别的高速存储。
自测:
Q: 通用计算机的存储层次至少有几级？
A: 至少三级。
Q: 这三级分别是什么？
A: CPU 寄存器、主存、辅存。

#### 可执行存储器
寄存器和主存储器在存储层次中又被称为可执行存储器。进程可以在很少的时钟周期内用一条 load 或 store 指令访问它们；而访问辅存必须借助 I/O 设备，因此会涉及中断、设备驱动程序以及物理设备的运行，耗时通常比访问可执行存储器多三个数量级甚至更多。
要点:
- 寄存器和主存储器合称可执行存储器。
- 对可执行存储器可用 load 或 store 指令快速访问。
- 访问辅存需要 I/O、中断和设备驱动程序，速度远慢于主存。
示例:
- 进程用一条 load 或 store 指令访问可执行存储器；访问辅存则要经过 I/O 设备。
常见误区:
- 辅存不能像主存那样被直接用 load/store 快速访问。
- 可执行存储器不是指所有存储器，而是特指寄存器和主存。
自测:
Q: 什么叫可执行存储器？
A: 寄存器和主存储器。
Q: 为什么辅存访问更慢？
A: 因为需要经过 I/O 设备，还涉及中断、设备驱动程序和物理设备运行。

#### 主存与寄存器
主存储器就是内存，主要保存进程运行时的程序和数据，CPU 与外围设备交换的信息一般也依托于主存储器地址空间。为了缓和主存访问速度远低于 CPU 执行速度的问题，计算机系统中引入了寄存器和高速缓存。寄存器与 CPU 协调工作，可用于存放操作数，也可作为地址寄存器来加快地址转换。
要点:
- 主存储器保存进程运行时的程序和数据。
- CPU 与外围设备交换的信息通常依托于主存储器地址空间。
- 寄存器用于加速存储器访问，可存放操作数或作为地址寄存器。
示例:
- 寄存器可以存放操作数，地址寄存器可以加快地址转换速度。
常见误区:
- 寄存器不是用来长期保存大量程序和数据的。
- 主存和寄存器的作用不同：主存负责存放运行中的程序数据，寄存器负责加速访问。
自测:
Q: 主存储器的主要作用是什么？
A: 保存进程运行时的程序和数据。
Q: 寄存器能起到什么作用？
A: 与 CPU 协调工作，用来加速存储器访问，如存放操作数或作为地址寄存器。

#### 高速缓存与磁盘缓存
高速缓存依据程序执行的局部性原理，把主存中经常访问的信息存放在高速缓存中，以减少访问主存储器的次数并提高程序执行速度。磁盘缓存则把频繁使用的一部分磁盘数据和信息暂时存放起来，以减少访问磁盘的次数；它利用主存中的存储空间来暂存从磁盘中读写的信息。
要点:
- 高速缓存利用局部性原理。
- 高速缓存的作用是减少主存访问次数。
- 磁盘缓存用于减少磁盘访问次数。
- 磁盘缓存占用的是主存空间，用来暂存磁盘读写信息。
示例:
- 把主存中经常访问的数据放入高速缓存；把频繁使用的磁盘数据暂存到磁盘缓存。
常见误区:
- 磁盘缓存不是独立于主存之外的另一块磁盘。
- 高速缓存的目标不是扩大主存容量，而是减少访问主存的次数。
自测:
Q: 高速缓存依据什么原理工作？
A: 程序执行的局部性原理。
Q: 磁盘缓存的主要作用是什么？
A: 减少访问磁盘的次数。

可延伸方向: 可对比 load/store 与 I/O 访问; 可解释局部性原理如何影响高速缓存
