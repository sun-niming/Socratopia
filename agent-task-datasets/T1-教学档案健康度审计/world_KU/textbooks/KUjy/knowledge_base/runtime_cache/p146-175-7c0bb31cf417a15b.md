## 教学地图（第 146-175 页）

### 阶段 1: 进程基础与线程动机
**[当前教学焦点 / 队列起点]** 目标: 先建立进程管理的基础，再说明并发带来的额外开销，最后引出线程为何被提出。

#### 进程与 PCB
教材在此处强调：进程是一个可独立调度和分派的基本单位。系统为每个进程设置唯一的 PCB，借助 PCB 感知进程存在、对进程进行调度，并把断点信息保存在 PCB 中，以便在需要时恢复进程运行现场。
要点:
- 每个进程都有唯一的 PCB
- 系统可根据 PCB 感知进程的存在并进行调度
- 断点信息可保存在 PCB 中，便于恢复现场
- 进程正因具有这种可调度、可管理的特性，才成为并发执行的基础
示例:
- 进程在被切换出去时，将当前运行现场保存到自己的 PCB 中；再次运行时，再从 PCB 中恢复现场。
常见误区:
- PCB 不是可有可无的附属信息，而是进程管理和切换的核心依据
- 仅有程序代码并不能让进程被调度运行
自测:
Q: 系统为什么要为每个进程设置 PCB？
A: 为了通过 PCB 识别进程、对进程进行调度，并保存和恢复进程运行现场。

#### 并发执行的时空开销
为了使程序能够并发执行，系统必须承担额外的时空开销，主要体现在创建进程、撤消进程和进程切换三个方面。创建时要分配除处理机以外的必要资源并建立 PCB；撤消时要先回收资源，再撤消 PCB；切换时要保存当前进程的 CPU 环境并设置新进程的 CPU 环境。
要点:
- 创建进程时要分配内存空间、I/O 设备等资源，并建立 PCB
- 撤消进程时要先回收其占有的资源，然后再撤消 PCB
- 进程切换需要保留当前 CPU 环境并设置新进程的 CPU 环境
- 这些操作都会消耗处理机时间，因此并发不是零成本的
示例:
- 从进程 A 切换到进程 B 时，系统需要先保存 A 的 CPU 环境，再装入 B 的 CPU 环境。
常见误区:
- 并发执行不会带来额外开销
- 创建、撤消和切换进程都可以不付出时间代价
自测:
Q: 程序并发执行时，系统主要在哪三类操作上付出开销？
A: 创建进程、撤消进程和进程切换。

#### 线程的提出
线程的概念来源于一种设计思想：把进程的两个属性分开处理，即不把作为调度和分派的基本单位同时作为拥有资源的单位，让调度单位“轻装上阵”，并避免对资源拥有单位进行频繁切换，从而减少系统开销、提高并发执行效率。
要点:
- 线程的核心思想是把进程的两个属性分离
- 调度和分派的单位不一定等于拥有资源的单位
- 这样做的目的是减少频繁切换带来的系统开销
- 线程是在提高并发能力与降低系统开销之间折中形成的概念
示例:
- 一个进程内部可以把多个执行流组织成线程，让它们共享资源而分别参与调度。
常见误区:
- 线程不是为了替代进程的所有作用，而是为了更轻量地组织执行流
- 线程并不等同于资源拥有单位
自测:
Q: 线程这一概念主要是为了解决什么问题？
A: 在提高并发执行能力的同时，尽量减少进程频繁切换带来的系统开销。

可延伸方向: PCB 如何支持进程切换与恢复; 并发执行为什么会增加系统开销

### 阶段 2: 线程的基本概念
**[后续教学队列]** 目标: 讲清线程自身的状态、控制结构，以及多线程环境下进程与线程的角色分工。

#### 线程的三种基本状态
线程在运行时也具有间断性，因此与进程一样，线程也有三种基本状态：执行状态、就绪状态和阻塞状态。执行状态表示线程已获得处理机正在运行；就绪状态表示线程已具备执行条件，只等 CPU；阻塞状态表示线程因某事件受阻而暂停。
要点:
- 执行状态：线程已获得处理机并正在运行
- 就绪状态：线程已具备执行条件，只等 CPU
- 阻塞状态：线程因某事件受阻而暂停
- 线程执行键盘输入等系统调用时也可能进入阻塞状态
示例:
- 线程执行从键盘读入数据的系统调用时，该线程就被阻塞。
常见误区:
- 线程的状态不是只有运行和不运行两种
- 阻塞并不等于线程结束，只是暂时停止执行
自测:
Q: 线程阻塞状态的含义是什么？
A: 线程在执行中因某事件受阻而处于暂停状态。

#### 线程控制块 TCB
系统为每个线程配置一个线程控制块 TCB，用来记录控制和管理该线程所需的信息。教材列出的信息包括线程标识符、一组寄存器、线程运行状态、优先级、线程专有存储区、信号屏蔽和堆栈。
要点:
- 每个线程都有自己的 TCB
- TCB 用于记录线程的控制与管理信息
- TCB 中可包含线程标识符、寄存器、状态、优先级等信息
- TCB 还可包含线程专有存储区、信号屏蔽和堆栈
示例:
- TCB 中可记录线程运行状态和一组寄存器，以便线程切换后恢复执行。
常见误区:
- TCB 不是只记录线程名字，而是记录完整管理信息
- 线程切换时依赖的不是程序代码本身，而是 TCB 中保存的信息
自测:
Q: TCB 主要保存什么信息？
A: 保存用于控制和管理线程的信息，如线程标识符、寄存器、状态、优先级、专有存储区、信号屏蔽和堆栈。

#### 多线程 OS 中的进程属性
在多线程操作系统中，一个进程通常包含多个线程，并为这些线程提供资源。此时，进程仍然是一个可拥有资源的基本单位，多个线程可以并发执行，但进程本身已经不再作为可执行实体。
要点:
- 进程是可拥有资源的基本单位
- 一个进程内部可以有多个线程并发执行
- 在多线程 OS 中，进程已不是可执行实体
- 线程负责执行，进程负责资源拥有
示例:
- 一个进程中可以同时存在多个线程，它们共享进程资源并并发执行。
常见误区:
- 在多线程 OS 中，进程不再有资源属性
- 进程和线程在多线程环境下仍然完全同义
自测:
Q: 多线程 OS 中，进程最重要的属性是什么？
A: 进程是一个可拥有资源的基本单位。
