## 教学地图（第 91-116 页）

### 阶段 1: 进程状态控制
**[当前教学焦点 / 队列起点]** 目标: 先讲清进程在等待、唤醒、挂起、激活时的状态变化，为后续同步机制打基础。

#### 进程阻塞
进程在运行中如果发生了需要等待的事件，可以通过调用阻塞原语 block 使自己停止执行，转为等待状态。进入 block 过程后，系统先立即停止该进程执行，把进程控制块 PCB 中的现行状态由“执行”改为“阻塞”，并把 PCB 插入阻塞队列；如果系统按不同事件设置了多个阻塞队列，则应插入与该事件相同的阻塞队列。
要点:
- 阻塞是进程自身的主动行为，不是别的进程直接强制完成的
- 进入 block 后，PCB 状态由执行改为阻塞
- 若系统有多个阻塞队列，应按事件分类插入对应队列
示例:
- 进程正在执行时等待 I/O 完成，于是调用 block 自己阻塞。
常见误区:
- 阻塞不是就绪，也不是直接结束进程
- 阻塞不是 CPU 继续让它运行
自测:
Q: 调用 block 后，进程和 PCB 会发生什么变化？
A: 进程停止执行，PCB 的现行状态由执行改为阻塞，并插入阻塞队列。

#### 进程唤醒
当被阻塞进程所期待的事件发生时，有关进程可以调用唤醒原语 wakeup，把等待该事件的进程唤醒。wakeup 的执行过程是：先把被阻塞进程从等待该事件的阻塞队列中移出，将其 PCB 中的现行状态由阻塞改为就绪，然后把该 PCB 插入就绪队列。
要点:
- wakeup 由有关进程在事件发生后调用
- 唤醒时先从对应阻塞队列移出 PCB
- 状态变化是阻塞→就绪，不是阻塞→执行
示例:
- I/O 操作完成，或所期待的数据已经到达时，调用 wakeup 将等待该事件的进程唤醒。
常见误区:
- 唤醒不等于立刻获得处理机运行
- 被唤醒的进程先进入就绪队列，而不是直接执行
自测:
Q: wakeup 执行后，PCB 会进入哪个队列？
A: 先从阻塞队列移出，PCB 状态改为就绪，再插入就绪队列。

#### 进程挂起与激活
挂起原语 suspend 的功能包括：自身挂起、挂起具有指定标识符的进程、以及将其进程及其全部或部分子孙挂起。激活原语 Active 的功能是使处于静止状态的进程变为活动。
要点:
- suspend 可以作用于自身、指定进程，或其子孙进程
- Active 的作用是把静止状态的进程变为活动
- 这组原语用于控制进程处于活动或静止状态
示例:
- 把某个处于静止状态的进程再次激活，使其恢复活动。
常见误区:
- 挂起不等于阻塞
- 激活不等于直接让进程立刻运行
自测:
Q: suspend 和 Active 分别完成什么功能？
A: suspend 负责挂起进程；Active 负责把静止状态的进程变为活动。

### 阶段 2: 同步问题与临界区
**[后续教学队列]** 目标: 说明为什么并发会带来不确定性，以及为什么临界资源和临界区必须受控。

#### 进程同步
在操作系统中引入进程后，多道程序可以并发执行，这能提高资源利用率和系统吞吐量，但也会使系统更复杂。如果多个进程对系统资源无序争夺，就会造成混乱，使处理结果具有不确定性和不可再现性。进程同步就是用来协调这种并发关系的机制。
要点:
- 并发能提高资源利用率和吞吐量，但也会增加系统复杂性
- 若缺少有效管理，多个进程争夺资源会导致结果不确定
- 进程的同步与互斥机制用于协调间接和直接相互制约关系
示例:
- 进程 P1、P2 公用变量 COUNT，因执行顺序随机，COUNT 的最终值可能不同。
常见误区:
- 同步不是把所有进程都改成串行执行
- 并发执行不一定自动正确，仍需要协调机制
自测:
Q: 为什么共享 COUNT 时，不同执行顺序会得到不同结果？
A: 因为 P1、P2 的执行顺序和交错方式是随机的，若没有同步协调，结果就会不一致。

#### 临界资源与临界区
临界资源是一次只能供一个进程使用的资源，使用完后才能归还系统再给其他进程使用。进程对临界资源必须互斥使用。访问临界资源的那段代码称为临界区；每个进程在进入自己的临界区前，必须先申请，经允许后方能进入。
要点:
- 临界资源一次只能被一个进程占用
- 临界区是访问临界资源的代码段，不是资源本身
- 进入临界区前必须先申请并获得允许
示例:
- 变量 COUNT 作为临界资源时，对它的访问代码段就是临界区。
常见误区:
- 临界资源不是不能共享，而是共享时必须互斥访问
- 临界区不是某个特定函数名，而是访问临界资源的那段代码
自测:
Q: 什么是临界区？
A: 进程中访问临界资源的那段代码称为临界区。

#### 同步四准则
为了实现进程互斥地进入临界区，同步机制应遵循四条准则：空闲让进、忙则等待、有限等待、让权等待。空闲让进指无进程处于临界区时，应让一个要求进入的进程立即进入；忙则等待指已有进程处于临界区时，其他进程必须等待；有限等待指要求进入的进程应在有限时间内进入；让权等待指等待进入临界区的进程应立即释放处理机，避免忙等。
要点:
- 空闲让进：临界区空闲时应立即允许进入
- 忙则等待：临界区已有进程时，其它进程必须等待
- 有限等待：不能无限期等待，要在有限时间内进入
- 让权等待：等待时应立即释放处理机，避免忙等
示例:
- 当临界区无人占用时，某个申请进入的进程应立即进入；若已有进程在临界区内，其它进程则必须等待。
常见误区:
- 忙等不是同步机制的目标
- 让权等待要求释放处理机，而不是占着 CPU 一直测试
自测:
Q: 同步机制应遵循哪四条准则？
A: 空闲让进、忙则等待、有限等待、让权等待。
