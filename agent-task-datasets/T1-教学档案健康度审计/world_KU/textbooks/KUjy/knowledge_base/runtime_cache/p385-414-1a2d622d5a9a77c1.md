## 教学地图（第 385-414 页）

### 阶段 1: I/O通道与中断基础
**[当前教学焦点 / 队列起点]** 目标: 先建立 I/O 通道、瓶颈和中断的基本概念，让学习者理解为什么操作系统必须依赖中断来协调 CPU、I/O 和进程切换。

#### 数组多路通道
数组多路通道（Block Multiplexor Channel）把数组选择通道的高传输速率与字节多路通道的子通道分时并行优点结合起来。它含有多个非分配型子通道，因此既能获得很高的数据传输速率，又能保持较好的通道利用率，常用于连接多台高、中速外围设备，按数组方式传送数据。
要点:
- 兼有数组选择通道的高速度和字节多路通道的分时并行能力
- 含有多个非分配型子通道
- 适合连接多台高、中速外围设备，数据按数组方式传送
示例:
- 用于连接多台高、中速外围设备的数组方式传送
常见误区:
- 不是只能同时服务一个设备；它的子通道可以分时并行操作
- 它追求的不是单纯最高速率，而是高速度与较高利用率的结合
自测:
Q: 数组多路通道的主要特点是什么？
A: 它结合了数组选择通道的高传输速率和字节多路通道分时并行操作的优点，含有多个非分配型子通道。

#### 瓶颈问题与多通路I/O系统
由于通道价格昂贵，系统中设置的通道数量通常较少，这会使 I/O 形成瓶颈，进而降低整个系统吞吐量。教材给出的最有效解决办法，是增加设备到主机之间的通路，而不是增加通道本身。
要点:
- 通道少会使 I/O 成为瓶颈
- 瓶颈会降低系统吞吐量
- 解决思路是增加设备到主机的通路，不增加通道
示例:
- 单通路 I/O 系统可以改为多通路 I/O 系统
常见误区:
- 解决瓶颈不一定是多加通道；教材强调的是增加通路而不增加通道
- I/O 瓶颈不仅影响单个设备，也会拉低整个系统吞吐量
自测:
Q: 教材中解决 I/O 瓶颈问题的最有效方法是什么？
A: 增加设备到主机间的通路，而不增加通道。

#### 中断在操作系统中的作用
中断在操作系统中是实现多道程序、设备管理以及 CPU 与 I/O 并行执行的基础。没有中断，就不可能实现多道程序，因为进程之间的切换是通过中断完成的；同时，提高处理机利用率也需要中断支持。
要点:
- 中断是多道程序实现的基础
- 进程切换通过中断完成
- 设备管理、CPU 与 I/O 并行也依赖中断支持
示例:
- CPU 在执行程序时，借助中断转去处理 I/O 设备请求
常见误区:
- 中断只是 I/O 设备的附属机制；教材强调它是 OS 的基础机制之一
- 没有中断也能方便地实现进程切换，教材是否定的
自测:
Q: 为什么说中断在操作系统中很重要？
A: 因为它是多道程序实现的基础，也是设备管理和 CPU 与 I/O 并行执行的基础。

#### 中断与陷入
中断是 CPU 对 I/O 设备发来的中断信号的响应：CPU 暂停当前程序，保存 CPU 环境，转去执行 I/O 设备的中断处理程序，执行完后再返回断点继续执行原程序。由于它由外部设备引起，所以也称外中断。陷入是由 CPU 内部事件引起的中断，例如运算上溢或下溢、非法指令、地址越界和电源故障等，通常称为内中断。
要点:
- 中断来自外部设备，陷入来自 CPU 内部事件
- 处理中断时要保存现场并返回断点
- 陷入例子包括上溢、下溢、非法指令、地址越界、电源故障
示例:
- I/O 设备发出中断信号，CPU 暂停原程序并转去执行中断处理程序
常见误区:
- 把所有中断都看成外部 I/O 引起的是错误的
- 陷入不是普通的 I/O 外设中断，而是内部事件引起的
自测:
Q: 中断和陷入有什么区别？
A: 中断通常由外部 I/O 设备引起；陷入由 CPU 内部事件引起，如上溢、下溢、非法指令、地址越界等。

可延伸方向: 可延伸到中断向量表、中断优先级和多中断源处理

### 阶段 2: 中断处理与驱动程序
**[后续教学队列]** 目标: 讲清中断进入软件后的处理链条，以及设备驱动程序在高层软件和硬件之间承担的转换、控制和通信职责。

#### 中断处理程序
中断处理程序是 I/O 系统中最低的一层，也是整个 I/O 系统的基础。它负责在 CPU 响应中断后进行现场保护、分析中断原因、调用相应设备的中断处理程序、恢复现场等工作。教材给出的流程是：测定是否有未响应的中断信号，唤醒被阻塞的驱动程序进程；保护被中断进程的 CPU 环境；分析中断原因并转入相应设备的中断处理程序；进行中断处理；恢复被中断进程现场。
要点:
- 负责进程上下文切换、测试中断源、读取设备状态、修改进程状态
- 先保护现场，再分析原因并调用对应设备处理程序，最后恢复现场
- 不同 I/O 设备的处理中，除第一步外其余步骤基本相同
示例:
- 打印机、磁盘、终端等设备都可各自对应不同的中断处理程序
常见误区:
- 中断处理程序只做一次简单转跳；教材表明它还包含现场保护和恢复等步骤
- 所有步骤都因设备而不同；教材说明除第一步外其余步骤对所有 I/O 设备相同
自测:
Q: 中断处理程序的基本步骤有哪些？
A: 测定是否有未响应的中断信号并唤醒驱动程序进程；保护被中断进程的 CPU 环境；分析中断原因并转入相应设备中断处理程序；进行中断处理；恢复被中断进程现场。

#### 设备驱动程序概述
设备驱动程序通常又称设备处理程序，是 I/O 系统的高层与设备控制器之间的通信程序。它接收上层软件发来的抽象 I/O 要求，如 read 或 write，再将其转换为具体要求发送给设备控制器，启动设备执行；同时也把控制器发来的信号传送给上层软件。由于它与硬件密切相关，通常每一类设备都要配置一种驱动程序。
要点:
- 位于高层软件与设备控制器之间
- 负责抽象 I/O 到具体 I/O 的转换
- 也负责把控制器信号传回上层软件
- 通常按设备类别配置驱动程序
示例:
- 打印机和显示器通常需要不同的驱动程序
常见误区:
- 驱动程序不是普通应用程序，而是与硬件紧密相关的低级系统例程
- 不是一个驱动程序就能通用于所有设备
自测:
Q: 设备驱动程序的作用是什么？
A: 它在高层软件和设备控制器之间传递信息，把抽象 I/O 请求转换成具体控制命令，并把控制器信号传回上层软件。

#### 设备驱动程序的功能
设备驱动程序的功能主要包括五方面：接收 I/O 进程的命令和参数，并将抽象要求转换为具体要求；检查 I/O 请求合法性、了解设备状态并设置工作方式；发出 I/O 命令，设备空闲时立即启动，忙碌时把请求挂入设备队列；及时响应控制器或通道发来的中断请求，并调用相应中断处理程序；在有通道的系统中，根据用户 I/O 请求自动构成通道程序。
要点:
- 命令与参数接收及抽象到具体的转换
- 合法性检查、状态检查和工作方式设置
- 设备忙时要排队等待
- 要响应中断并调用相应处理程序
- 通道系统中还要构成通道程序
示例:
- 将磁盘块号转换成盘面、磁道号及扇区号
常见误区:
- 驱动程序只负责启动设备，不负责检查合法性和处理中断
- 设备忙时不是立刻启动，而是应挂到设备队列等待
自测:
Q: 设备驱动程序的主要功能有哪些？
A: 接收命令和参数并转换请求、检查合法性和设备状态、发出 I/O 命令并排队等待、响应中断、在通道系统中构成通道程序。

#### 设备驱动程序的特点
设备驱动程序是低级系统例程，具有强烈的硬件相关性。它主要充当请求 I/O 的进程与设备控制器之间的通信和转换程序；不同类型设备应配置不同驱动程序；它与 I/O 控制方式紧密相关；其中一部分必须用汇编语言编写；驱动程序应允许可重入；驱动程序不允许系统调用。
要点:
- 低级系统例程，和硬件关系紧密
- 通常需要按设备类型分别编写
- 与 I/O 控制方式相关，部分代码需用汇编语言
- 应支持可重入
- 不允许系统调用
示例:
- 打印机驱动与显示器驱动可能不同
常见误区:
- 驱动程序可以像普通程序一样随意使用系统调用
- 驱动程序不需要考虑可重入性
自测:
Q: 设备驱动程序有哪些特点？
A: 它是低级系统例程，与硬件和 I/O 控制方式紧密相关，通常按设备类型配置，部分代码需用汇编语言，且应允许可重入并不允许系统调用。

可延伸方向: 可延伸到不同设备类型的驱动差异和驱动程序重入问题
