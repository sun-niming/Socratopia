## 教学地图（第 110-139 页）

### 阶段 1: 信号量机制扩展
**[当前教学焦点 / 队列起点]** 目标: 先建立弱模型对信号量改进版的理解：为什么要避免忙等，以及为什么需要支持一次申请多个资源单位。

#### 记录型信号量
记录型信号量是一种不会产生忙等的进程同步机制。它在整型信号量的资源计数变量 value 之外，还增加了一个进程链表指针 list，用来把所有等待该资源的进程链接起来。若 wait(S) 发现 S≤0，则进程不再反复测试，而是转入等待队列；因此它遵循“让权等待”，不占用 CPU 忙等。
要点:
- 与整型信号量不同，记录型信号量不采用忙等，而是阻塞等待。
- 信号量的基本信息包括资源数目 value 和等待进程链表 list。
- 当 S≤0 时，等待进程被链接到 list 中，直到被唤醒。
示例:
- wait(S)：当 S≤0 时，进程进入等待队列，不断测试的做法被取消。
- 记录型信号量用 value 表示资源数目，用 list 表示等待该资源的进程链表。
常见误区:
- 把信号量理解成只包含一个整数 value，而忽略等待队列。
- 认为 wait(S) 在任何情况下都会忙等。
自测:
Q: 记录型信号量比整型信号量主要改进了什么？
A: 它避免了忙等，并增加了等待进程链表 list，使 wait(S) 在资源不足时转入阻塞等待。

#### 信号量集
信号量集是一种扩展的信号量机制。它在每次分配资源之前，都要先测试资源数量是否大于某一下限值；只有满足条件时才允许分配。它适用于一次需要申请多个资源单位，或者当资源数量低于下限时必须禁止分配的场合。
要点:
- 一次申请多个单位资源时，不必反复执行多次 wait(S)，而应先做整体测试。
- 分配前必须检查资源数量是否高于可分配下限值。
- 信号量集可减少低效操作，并有助于降低死锁概率。
示例:
- 当进程一次需要 N 个单位资源时，不必做 N 次 wait(S)，而是在每次分配前测试是否满足下限条件。
常见误区:
- 把信号量集理解成若干个彼此独立的信号量。
- 认为只要资源大于 0 就一定可以分配，忽略了下限限制。
自测:
Q: 信号量集与普通信号量相比，最核心的差别是什么？
A: 它在分配前要先测试资源数量是否达到规定下限，适合一次申请多个资源单位或有最低保留量要求的场合。

可延伸方向: 补充 wait/signal 的基本含义; 对比整型信号量与记录型信号量

### 阶段 2: 信号量的应用
**[后续教学队列]** 目标: 在应用层面掌握信号量如何控制资源数量、协调先后顺序，并把语句级前后关系转化为 P/V 约束。

#### 资源数目控制
当多个并发进程共享固定数量的同类临界资源时，可以用一个信号量来控制资源数。把信号量初值设为资源总数，进程在使用资源前执行 P(S)，释放资源后执行 V(S)。这样，S 的值就表示当前还可继续使用的资源单位数。
要点:
- 信号量初值通常等于可用资源总数。
- P(S) 表示申请一个资源单位，V(S) 表示释放一个资源单位。
- 当资源被用完时，后来的进程必须等待。
示例:
- 三个进程共用两个 I/O 缓冲区，设信号量 S 初始值为 2。
- 若 S>0，表示还有可继续进入或继续使用的资源；若 S=0，表示资源已满额使用。
常见误区:
- 把初值总是设成 1；实际上当资源有多个时，初值应等于资源总数。
- 把资源数控制误认为程序逻辑中的普通变量计数，而不是同步机制。
自测:
Q: 三个进程共用两个 I/O 缓冲区时，信号量初值应设为多少？
A: 应设为 2，因为信号量初值应等于可用缓冲区的总数。

#### 进程同步
进程同步是指让多个并发进程按照既定先后次序协作执行，而不是同时无序运行。教材中的例子是：A 进程从卡片机读入信息到缓冲区，B 进程加工缓冲区中的信息。可用两个信号量分别表示“缓冲区中是否已有可加工信息”和“缓冲区是否为空”，从而保证先写入、后加工。
要点:
- 同步关注的是执行顺序，而不是单纯的资源互斥。
- 常用一个信号量表示“事件已经发生”或“数据已经准备好”。
- 在生产者-消费者式场景中，常用一对信号量分别控制空位与可用数据。
示例:
- A 进程读入信息后再通知 B 进程加工。
- 教材给出的设置是：S1 表示缓冲区中有否可供加工的信息，初始值为 0；S2 表示缓冲区是否为空，初始值为 1。
常见误区:
- 把同步和互斥混为一谈。同步强调顺序，互斥强调同一时刻只能有一个进程进入临界区。
- 认为只要进程都能运行，就一定满足同步要求。
自测:
Q: 同步问题与互斥问题有什么不同？
A: 同步关注进程执行的先后顺序，互斥关注多个进程对同一临界资源的排他访问。

#### 前趋关系
前趋关系是指某个语句必须在另一个语句之前执行。实现方法是让前驱语句执行后发出信号，让后继语句在执行前等待同一个信号量。通常把共享信号量初值设为 0，把 signal(S) 放在前驱语句后面，把 wait(S) 放在后继语句前面。
要点:
- 前驱语句负责发出 signal(S)。
- 后继语句前必须执行 wait(S)，否则不能开始。
- 共享信号量初值通常设为 0，以保证后继语句先被阻塞。
示例:
- 进程 P1 中：S1; signal(S);
进程 P2 中：wait(S); S2;
- 若有更复杂的前趋图，可以为不同依赖关系设置多个信号量，如 a、b、c、d、e、f、g。
常见误区:
- 认为只要两个进程同时运行，语句顺序自然就对了。并发执行并不自动保证前趋关系。
- 把 signal 和 wait 的位置写反，会破坏执行次序。
自测:
Q: 如何用一个信号量保证 S1 先于 S2 执行？
A: 将共享信号量 S 初值设为 0，在 S1 后执行 signal(S)，在 S2 前执行 wait(S)。

可延伸方向: 扩展到多资源并发控制; 由两进程同步推广到复杂前趋图
