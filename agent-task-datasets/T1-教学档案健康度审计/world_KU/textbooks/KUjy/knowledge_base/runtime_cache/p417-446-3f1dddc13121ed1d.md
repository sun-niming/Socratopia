## 教学地图（第 417-446 页）

### 阶段 1: I/O分配与用户层软件基础
**[当前教学焦点 / 队列起点]** 目标: 先建立 I/O 请求如何进入操作系统、如何分配独占设备，以及用户层软件如何通过系统调用获取服务的整体图景。

#### 独占设备分配程序
对于具有 I/O 通道的系统，进程提出 I/O 请求后，系统的设备分配程序按顺序完成三步：先分配设备，再分配控制器，最后分配通道。
要点:
- 基本步骤固定为：分配设备 → 分配控制器 → 分配通道
- 这是独占设备分配的基本程序
- 适用于具有 I/O 通道的系统
示例:
- 某进程申请独占打印机时，系统先找到并分配打印机设备，再分配其控制器，最后分配通道。
常见误区:
- 不是先分配通道再找设备
- 分配程序不是任意顺序，而是按设备、控制器、通道的顺序进行
自测:
Q: 独占设备的基本分配程序包含哪三个步骤？
A: 分配设备、分配控制器、分配通道。

#### 设备分配程序的改进
基本的独占设备分配程序存在两个问题：进程以物理设备名提出 I/O 请求，以及采用单通路 I/O 系统结构，容易产生瓶颈。因此，应从增加设备独立性和考虑多通路情况两方面改进，以提高灵活性和分配成功率。
要点:
- 问题一：进程用物理设备名提出 I/O 请求
- 问题二：单通路结构容易形成瓶颈
- 改进方向：增加设备独立性、考虑多通路情况
示例:
- 把“请求某一具体物理设备”改为更具独立性的请求方式，可以让系统在分配时有更多选择。
常见误区:
- 改进不是简单增加设备数量
- 改进的目标是提高灵活性和成功率，不是改变分配的基本对象
自测:
Q: 基本设备分配程序的两个主要问题是什么？
A: 进程以物理设备名提出 I/O 请求，以及单通路结构容易产生瓶颈。

#### 用户层I/O软件
大部分 I/O 软件位于操作系统内部，但仍有一小部分在用户层，包括与用户程序链接在一起的库函数，以及完全运行于内核之外的假脱机系统等。
要点:
- 用户层 I/O 软件只占一小部分
- 包括与用户程序链接的库函数
- 也包括完全运行于内核之外的程序，如假脱机系统
示例:
- 一个应用程序调用与系统调用对应的库函数来完成文件或设备操作，这些库函数属于用户层 I/O 软件。
常见误区:
- 用户层 I/O 软件不等于全部 I/O 软件
- 并非所有 I/O 相关程序都必须运行在内核内
自测:
Q: 用户层 I/O 软件包括哪些内容？
A: 包括与用户程序链接在一起的库函数，以及完全运行于内核之外的假脱机系统等。

#### 系统调用与库函数
用户层软件必须通过系统调用取得操作系统服务。现代高级语言和 C 语言通常提供与各系统调用一一对应的库函数，用户程序通过调用这些库函数间接使用系统调用；这些库函数会与调用程序连接在一起，包含在运行时装入内存的二进制程序中。
要点:
- 用户层软件通过系统调用获得 OS 服务
- 库函数与系统调用通常一一对应
- 库函数会被链接进运行时装入内存的二进制程序
示例:
- 用户程序不直接写内核接口，而是调用对应的库函数，再由库函数转入系统调用。
常见误区:
- 库函数本身不是系统调用，但可以封装系统调用
- 用户程序通常不是直接与内核服务逐条对接，而是通过库函数
自测:
Q: 用户层软件怎样取得操作系统服务？
A: 通过一组系统调用取得操作系统服务；在现代语言中通常再由库函数来间接调用这些系统调用。

可延伸方向: 可延伸到设备驱动与通道管理; 可延伸到库函数封装与系统调用接口

### 阶段 2: 假脱机与共享打印
**[后续教学队列]** 目标: 说明如何借助磁盘和队列把独占设备改造成共享设备，并用共享打印机作为完整实例。

#### 假脱机技术
假脱机（SPOOLing）是在联机情况下实现同时外围操作的一种技术。它利用高速磁盘等随机外存，把低速 I/O 设备上的数据先传到磁盘，再由系统在需要时从磁盘转送到低速输出设备；其作用之一是把独占设备改造成共享设备。
要点:
- 核心思想是“先入磁盘，再按需输出”
- 是在联机条件下实现的同时外围操作
- 可把独占设备改造成共享设备
示例:
- 打印任务先进入磁盘上的输出井，打印机空闲时再由系统取出并打印。
常见误区:
- SPOOLing 不是让打印机本身变快
- 它强调的是排队、并行和共享，而不是设备物理性能提升
自测:
Q: SPOOLing 技术的作用是什么？
A: 把一台独占设备改造成共享设备。

#### SPOOLing系统组成
SPOOLing 系统是对脱机输入、输出工作的模拟，必须依赖高速随机外存，通常是磁盘。它主要由输入井和输出井、输入缓冲区和输出缓冲区、输入进程 SPi 和输出进程 Spo、井管理程序组成；请求打印队列由若干张请求打印表组成。
要点:
- 必须有高速随机外存支持，通常采用磁盘
- 主要组成：输入井、输出井、输入缓冲区、输出缓冲区
- 还有输入进程 SPi、输出进程 Spo 和井管理程序
- 请求打印队列由多个请求打印表构成
示例:
- 一个打印请求会对应一张请求打印表，表项进入请求打印队列等待输出。
常见误区:
- SPOOLing 系统不是只有一个缓冲区
- 请求打印队列不是设备本身，而是由请求打印表组织起来的等待结构
自测:
Q: SPOOLing 系统的主要组成部分有哪些？
A: 输入井和输出井、输入缓冲区和输出缓冲区、输入进程 SPi、输出进程 Spo、井管理程序。

#### SPOOLing系统特点
SPOOLing 系统有三个主要特点：提高 I/O 的速度；将独占设备改造为共享设备；实现虚拟设备功能。
要点:
- 提高 I/O 速度
- 将独占设备改造为共享设备
- 实现虚拟设备功能
示例:
- 多个用户可以共享一台打印机，而每个用户都感觉自己像拥有一台专用打印机。
常见误区:
- 虚拟设备并不等于真实设备数量增加
- 共享设备并不是让多个进程同时直接操作设备
自测:
Q: SPOOLing 系统有哪些主要特点？
A: 提高 I/O 速度、将独占设备改造为共享设备、实现虚拟设备功能。

#### 共享打印机
SPOOLing 技术可以把一台打印机改造成供多个用户共享的设备。用户进程请求打印输出时，输出进程先在输出井申请一空闲盘块区并写入要打印的数据，再为该进程建立一张用户请求打印表并挂到请求打印队列上；当打印机空闲时，输出进程从队首取表并把输出井中的数据传送到内存缓冲区，再由打印机打印。
要点:
- 先把打印数据写入输出井
- 再建立请求打印表并挂入请求打印队列
- 打印机空闲时按队首表项取数据并打印
示例:
- 多个作业提交打印任务后，真正打印的顺序由请求打印队列控制，而不是由用户程序直接控制打印机。
常见误区:
- 用户进程不是直接向打印机写数据
- 共享打印机的核心是排队与缓冲，不是多台打印机同时工作
自测:
Q: 共享打印机中，打印数据先存放到哪里？
A: 先存放到输出井中的空闲盘块区。

可延伸方向: 可延伸到打印系统的作业排队策略; 可延伸到虚拟设备与脱机输入输出
