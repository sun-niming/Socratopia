## 教学地图（第 375-404 页）

### 阶段 1: 设备基础与分类
**[当前教学焦点 / 队列起点]** 目标: 先建立I/O设备、设备控制器以及两者接口的基本概念，再让学习者知道设备控制器在系统中的位置和作用。

#### I/O设备分类
原文给出了 I/O 设备的三种分类方法：按传输速率、按信息交换的单位、按设备的共享属性。按传输速率可分为低速设备、中速设备和高速设备；按信息交换单位可分为块设备和字符设备；按共享属性可分为独占设备、共享设备和虚拟设备。
要点:
- 按传输速率分类：低速设备每秒几个字节至数百个字节；中速设备每秒数千个字节至数万个字节；高速设备每秒数百千个字节至数十兆字节。
- 低速设备典型有键盘、鼠标器、语音输入/输出；中速设备典型有行式打印机、激光打印机；高速设备典型有磁带机、磁盘机、光盘机。
- 块设备用于存储信息，存取以数据块为单位，属于有结构设备；字符设备用于数据输入和输出，基本单位是字符。
- 按共享属性分类时，原文列出独占设备、共享设备、虚拟设备。
示例:
- 键盘、鼠标器属于低速设备；磁盘属于块设备；打印机属于中速设备。
- 块设备的典型例子是磁盘，每个盘块大小约为 512B～4KB。
常见误区:
- 字符设备不等于“只处理字符内容”的设备，而是指以字符为基本单位进行输入/输出的设备。
- 块设备不是简单地“文件很大”的设备，而是以块为单位交换信息的设备。
自测:
Q: I/O设备按原文可以从哪三方面分类？
A: 按传输速率、按信息交换单位、按设备共享属性分类。
Q: 磁盘属于哪一类I/O设备？
A: 磁盘通常属于块设备，也属于高速设备。

#### 设备与控制器接口
通常设备并不是直接与 CPU 通信，而是与设备控制器通信，因此设备和设备控制器之间需要一个接口。该接口中有三类信号：数据信号、控制信号和状态信号。
要点:
- 设备并不直接和 CPU 通信，而是先与设备控制器通信。
- 设备与控制器之间的接口要传递数据信号、控制信号和状态信号。
- 原文图示中包含数据信号线、状态信号线和控制信号线。
示例:
- 接口中传递的三类信号分别是：数据、控制和状态。
常见误区:
- 容易误以为外设直接连 CPU 就能工作；原文强调通常是通过设备控制器间接通信。
- “状态信号”不是数据本身，而是描述设备工作状态的信息。
自测:
Q: 设备和CPU之间为什么还要有接口？
A: 因为设备通常不是直接与CPU通信，而是与设备控制器通信，所以需要设备与控制器之间的接口。
Q: 接口中有哪三类信号？
A: 数据信号、控制信号、状态信号。

#### 设备控制器
设备控制器是 CPU 与 I/O 设备之间的接口。它接收 CPU 发来的命令，并控制 I/O 设备工作，从而使处理机从繁杂的设备控制事务中解脱出来。原文还指出，设备控制器通常由设备控制器与处理机的接口、设备控制器与设备的接口和 I/O 逻辑三部分组成。
要点:
- 基本功能包括：接收和识别命令、数据交换、标识和报告设备状态、地址识别、数据缓冲、差错控制。
- 命令识别依赖控制寄存器和命令译码；状态报告依赖状态寄存器。
- 设备控制器的组成包括：与处理机的接口、与设备的接口、I/O逻辑。
示例:
- 数据交换的方向可表示为：CPU(总线) → 控制器(数据寄存器) → 设备。
常见误区:
- 设备控制器不是简单的“接线盒”，它承担命令识别、状态管理、缓冲和差错控制等任务。
- 设备控制器既要对 CPU 负责，也要对具体设备负责。
自测:
Q: 设备控制器在系统中的作用是什么？
A: 它是CPU与I/O设备间的接口，接收CPU命令并控制I/O设备工作。
Q: 设备控制器通常由哪三部分组成？
A: 设备控制器与处理机的接口、设备控制器与设备的接口、I/O逻辑。

可延伸方向: 可以补充端口、寄存器与信号线的直观含义; 可以对比CPU直接通信与经控制器通信的差异

### 阶段 2: I/O编址与通道
**[后续教学队列]** 目标: 说明设备寄存器如何编址，以及为什么需要更强的I/O通道来减轻CPU负担并缓解瓶颈。

#### I/O编址方式
原文介绍了两种 I/O 编址方式：利用特定的 I/O 指令，以及内存映射 I/O。前者为控制寄存器分配专门的 I/O 端口，并设置专门的 I/O 指令；后者不再区分内存单元地址和设备控制器寄存器地址，二者使用同一套编址。
要点:
- 特定 I/O 指令方式中，每个控制寄存器分配一个 I/O 端口，端口是 8 位或 16 位整数。
- 专门的 I/O 指令示例：`io-store cpu-reg,dev-no,dev-reg`。
- 内存映射 I/O 中，地址统一记作 `k`；当 `k` 在 $0\sim n-1$ 时表示内存地址，当 `k\ge n$` 时表示控制器寄存器地址。
- 若 `k=n`，就表示设备控制器 0 的第 1 个寄存器 `opcode` 的地址。
- 内存映射 I/O 允许用一般的存储指令访问控制器寄存器，例如 `store cpu-reg,n`。
示例:
- 特定 I/O 指令：`io-store cpu-reg,dev-no,dev-reg`。
- 内存映射 I/O：`store cpu-reg,n` 将 CPU 寄存器内容传到控制器 0 的第 1 个寄存器。
常见误区:
- 内存映射 I/O 并不是“把 I/O 变成内存”，而是把设备寄存器映射到统一地址空间。
- 特定 I/O 指令方式和普通存储指令在编址上是分开的。
自测:
Q: 内存映射I/O与特定I/O指令方式的根本区别是什么？
A: 内存映射I/O不再区分内存地址和设备控制器寄存器地址，而特定I/O指令方式要为控制寄存器分配专门I/O端口并使用专门I/O指令。
Q: 在内存映射I/O中，k>=n表示什么？
A: 表示某个控制器的寄存器地址。

#### I/O通道
I/O 通道是为减轻 CPU 的 I/O 负担而在 CPU 和设备控制器之间增设的特殊处理机。它能够执行 I/O 指令，并通过执行通道程序来控制 I/O 操作。与一般处理机相比，它的指令类型单一，而且没有自己的内存，通道程序存放在主机内存中，因此通道与 CPU 共享内存。
要点:
- 引入 I/O 通道的目的，是把一些原来由 CPU 处理的 I/O 任务转由通道承担。
- I/O 通道可以执行 I/O 指令，并通过执行通道程序控制 I/O 操作。
- 通道硬件较简单，指令类型单一，主要局限于 I/O 相关指令。
- 通道没有自己的内存，通道程序放在主机内存中，所以通道与 CPU 共享内存。
示例:
- 原文把 I/O 通道直接描述为“一种特殊的处理机”。
常见误区:
- I/O通道不是普通意义上的总线通路，而是一种能执行通道程序的特殊处理机。
- I/O通道不是独占自己的内存，它与CPU共享主机内存。
自测:
Q: 为什么要引入I/O通道？
A: 为了把原来由CPU处理的一些I/O任务转由通道承担，从而减轻CPU负担。
Q: I/O通道与一般处理机相比有哪些主要不同？
A: 指令类型单一，且没有自己的内存，通道程序存放在主机内存中。

#### 通道类型
原文列出了三种通道类型：字节多路通道、数组选择通道、数组多路通道。它们的区别主要在于数据传送粒度、子通道数量以及是否能让多个设备分时并行工作。
要点:
- 字节多路通道（Byte Multiplexor Channel）按字节交叉方式工作，通常含有许多非分配型子通道，每个子通道连接一台 I/O 设备。
- 数组选择通道（Block Selector Channel）适于连接高速设备，但每次只允许一个设备传输数据，在一段时间内独占通道，利用率较低。
- 数组多路通道（Block Multiplexor Channel）结合了数组选择通道的高传输速率和字节多路通道的分时并行优点，含有多个非分配型子通道。
- 数组多路通道既有较高的数据传输速率，又能获得较满意的通道利用率，适于连接多台高、中速外围设备。
示例:
- 字节多路通道：多个子通道分别连接多台设备，按字节交叉工作。
- 数组多路通道：用于连接多台高、中速外围设备，数据按数组方式传送。
常见误区:
- 数组选择通道虽然适合高速设备，但并不意味着它能同时让多台设备真正并行传输。
- 数组多路通道不是简单地“更快”，还强调较好的通道利用率。
自测:
Q: 字节多路通道的工作方式是什么？
A: 按字节交叉方式工作。
Q: 为什么数组多路通道被认为更实用？
A: 因为它兼有较高传输速率和较好的通道利用率，能广泛用于连接多台高、中速外围设备。

#### I/O瓶颈与多通路
由于通道价格昂贵，系统中可设置的通道数量往往较少，这容易使通道成为 I/O 瓶颈，从而降低系统吞吐量。原文指出，解决瓶颈问题最有效的方法是增加设备到主机之间的通路，而不增加通道，即采用多通路 I/O 系统。
要点:
- 通道数量少时，通道容易成为 I/O 瓶颈。
- I/O瓶颈会造成整个系统吞吐量下降。
- 解决方法是增加设备到主机间的通路，而不是增加通道数量。
- 多通路 I/O 系统是对单通路 I/O 系统的改进。
示例:
- 原文给出的思路是：增加设备到主机间的通路，而不增加通道。
常见误区:
- “瓶颈”不一定出在 CPU 上，原文这里指的是 I/O 通道可能成为瓶颈。
- 增加通路与增加通道不是一回事。
自测:
Q: I/O瓶颈为什么会出现？
A: 因为通道价格昂贵，系统中设置的通道数量往往较少。
Q: 解决I/O瓶颈最有效的方法是什么？
A: 增加设备到主机间的通路，而不增加通道。

可延伸方向: 可延伸解释内存映射I/O与普通存储指令的联系; 可进一步比较字节多路通道与数组多路通道的适用场景
