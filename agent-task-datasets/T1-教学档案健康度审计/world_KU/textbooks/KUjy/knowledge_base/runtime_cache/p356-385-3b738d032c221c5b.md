## 教学地图（第 356-385 页）

### 阶段 1: 共享段与分段保护
**[当前教学焦点 / 队列起点]** 目标: 先讲清共享段如何分配与回收，再说明分段保护的三类检查及环保护的访问规则，为后续系统管理知识打基础。

#### 共享段分配
当某个共享段第一次被某个进程请求使用时，系统先为该共享段分配一块物理内存区，再把共享段调入该物理区，同时把该物理区的始址填入请求进程段表中的相应项；另外还要在共享段表中增加一表项并填写有关数据，把 count 置为 1。
要点:
- 第一次使用共享段时才需要为它分配物理内存区并调入内存。
- 系统要同时维护请求进程的段表和共享段表。
- 初次分配后把 count 置为 1，表示当前只有 1 个进程共享该段。
示例:
- 例如进程 A 第一次使用某共享段时：分配物理区 → 调入该共享段 → 在 A 的段表中登记该段始址 → 在共享段表中登记并令 count = 1。
常见误区:
- 共享段第一次被使用时，所有后续进程也都要重新分配物理内存。
- 只修改进程段表即可，不需要维护共享段表。
自测:
Q: 共享段第一次被进程请求时，系统要做哪几步？
A: 为该共享段分配物理区、把共享段调入该区、在请求进程段表中登记该区始址、在共享段表中增加表项并把 count 置为 1。

#### 共享段回收
当某进程不再需要某共享段时，应撤消该段在该进程段表中的表项，并执行 count := count - 1。若减 1 后结果为 0，则系统回收该共享段占用的物理内存，并取消共享段表中对应表项；若结果不为 0，则只取消调用者进程在共享段表中的有关记录。
要点:
- 回收共享段时，先删除该进程段表中对应的表项。
- 每有一个进程放弃共享段，count 就减 1。
- count 减到 0 时，系统才真正回收物理内存并删除共享段表项。
- count 不为 0 时，说明仍有进程在使用该段。
示例:
- 例如 3 个进程共享同一共享段，某个进程退出使用后，count 从 3 变为 2，只需删除它在共享段表中的记录，不必释放物理内存。
常见误区:
- 只要有一个进程释放共享段，系统就立即回收该段的物理内存。
- count 只是统计请求次数，与是否仍有进程使用无关。
自测:
Q: 共享段回收时，count 减 1 后若结果为 0，系统应做什么？
A: 回收该共享段的物理内存，并取消共享段表中该段对应的表项。
Q: 若 count 减 1 后结果不为 0，系统应怎样处理？
A: 只取消调用者进程在共享段表中的有关记录，不回收该共享段的物理内存。

#### 分段保护检查
分段保护主要包括三类检查：越界检查、存取控制检查和环保护机构。越界检查用于防止对段的非法越界访问；存取控制检查用于限制对段的访问方式；环保护机构用于按特权环约束程序对数据和服务的访问。
要点:
- 越界检查：防止访问超过段边界的地址。
- 存取控制检查：限制只读、只执行、读/写等访问方式。
- 环保护机构：通过特权环进一步控制程序可访问的数据和可调用的服务。
示例:
- 例如某段被标记为只读，则对它的写访问应被存取控制检查拒绝。
常见误区:
- 只要地址在物理内存范围内，就一定允许访问。
- 分段保护只靠一种检查就足够，其他检查可以省略。
自测:
Q: 分段保护包括哪三类检查？
A: 越界检查、存取控制检查、环保护机构。
Q: 存取控制检查中提到的三种访问方式是什么？
A: 只读、只执行、读/写。

#### 环保护规则
环保护机构规定：一个程序可以访问驻留在相同环或较低特权环中的数据；一个程序可以调用驻留在相同环或较高特权环中的服务。
要点:
- 数据访问受限制：只能访问相同环或较低特权环中的数据。
- 服务调用受限制：只能调用相同环或较高特权环中的服务。
- 图中给出了环 0、环 1、环 2 之间的数据访问与调用/返回关系。
示例:
- 例如在环 1 中运行的程序，可以访问环 1 或环 2 中的数据，也可以调用环 1 或环 0 中的服务。
常见误区:
- 程序可以随意访问任意环中的数据。
- 调用服务和访问数据遵循同一方向的环约束。
自测:
Q: 环保护机构对数据访问的规则是什么？
A: 一个程序可以访问驻留在相同环或较低特权环中的数据。
Q: 环保护机构对服务调用的规则是什么？
A: 一个程序可以调用驻留在相同环或较高特权环中的服务。

可延伸方向: 可补充分段与共享段在内存管理中的位置; 可延伸到进程并发访问控制

### 阶段 2: I/O系统基础
**[后续教学队列]** 目标: 建立对 I/O 系统目标、基本功能、软件层次和面向不同设备的接口的整体认识。

#### I/O系统任务
I/O 系统管理的主要对象是 I/O 设备及其相应的设备控制器。它的主要任务是完成用户提出的 I/O 请求，提高 I/O 速率，提高设备利用率，并为更高层进程方便地使用这些设备提供手段。
要点:
- 管理对象是 I/O 设备和相应的设备控制器。
- 核心任务之一是完成用户提出的 I/O 请求。
- 还要提高 I/O 速率和设备利用率。
- 同时要为更高层进程使用设备提供便利。
示例:
- 例如用户发出读磁盘请求时，I/O 系统需要把该请求交给相应设备控制器并尽量提高处理效率。
常见误区:
- I/O 系统只负责传递请求，不关心效率。
- I/O 系统只管理设备，不管理设备控制器。
自测:
Q: I/O 系统管理的主要对象是什么？
A: I/O 设备和相应的设备控制器。
Q: I/O 系统的主要任务有哪些？
A: 完成用户提出的 I/O 请求，提高 I/O 速率，提高设备利用率，并为高层进程方便使用设备提供手段。

#### I/O基本功能
I/O 系统的基本功能有六项：隐藏物理设备细节、与设备无关性、尽可能让处理机和 I/O 设备并行工作以提高利用率、对 I/O 设备进行控制、确保对设备的正确共享、进行错误处理。
要点:
- 隐藏物理设备的细节，方便用户使用设备。
- 与设备无关性建立在隐藏设备细节的基础上。
- 尽可能让处理机和 I/O 设备并行操作，以提高双方利用率。
- 对 I/O 设备进行控制是驱动程序的功能。
- 要确保独占设备和共享设备都能被正确共享。
- 错误处理时，临时性错误可通过重试纠正，持久性错误才向上层报告。
示例:
- 例如对临时性错误，可重复执行操作；若仍失败，再考虑报告错误。
常见误区:
- 所有 I/O 错误都应立即上报到上层。
- 设备无关性和隐藏设备细节是同一件事，没有先后关系。
自测:
Q: I/O 系统的六项基本功能是什么？
A: 隐藏物理设备细节、与设备无关性、提高处理机和 I/O 设备利用率、对 I/O 设备进行控制、确保正确共享、错误处理。
Q: 临时性错误和持久性错误的处理方式有什么不同？
A: 临时性错误可通过重试纠正；持久性错误才需要向上层报告。

#### I/O软件分层
现代 I/O 系统通常采用层次式结构。I/O 软件被组织成四个层次：用户层软件、设备独立性软件、设备驱动程序和中断处理程序。每一层利用其下层提供的服务完成某些子功能，并屏蔽实现细节，向高层提供服务。
要点:
- 采用层次式结构是为了让复杂的 I/O 软件具有清晰结构、更好的可移植性和可适应性。
- 四个层次依次是：用户层软件、设备独立性软件、设备驱动程序、中断处理程序。
- 高层利用下层提供的服务，下层隐藏实现细节。
- 中断处理程序直接与硬件交互，设备驱动程序连接进程与设备控制器，设备独立性软件提供与设备无关的统一接口。
示例:
- 用户层软件可直接调用库函数发出 I/O 请求；设备驱动程序把抽象 I/O 请求转换成具体设备命令。
常见误区:
- I/O 软件只要一个层次就能完成全部功能。
- 设备驱动程序和设备独立性软件是同一层。
自测:
Q: I/O 软件通常分成哪四个层次？
A: 用户层软件、设备独立性软件、设备驱动程序、中断处理程序。
Q: 采用层次式结构的主要好处是什么？
A: 使 I/O 软件结构清晰，并具有更好的可移植性和可适应性。

#### I/O系统接口
I/O 系统与高层之间会根据设备类型进一步划分接口，教材中给出三类：块设备接口、流设备接口和网络通信接口。块设备接口主要面向磁盘等块设备，隐藏磁盘二维结构并把抽象命令映射为低层操作；流设备接口又称字符设备接口，使用 get、put 和 in-control 指令；网络通信接口则为计算机连接网络并进行通信提供支持。
要点:
- 块设备接口：面向块设备，隐藏磁盘二维结构，映射抽象命令到低层操作。
- 流设备接口：也称字符设备接口，反映字符设备的本质特征。
- 流设备接口常用 get、put 操作和 in-control 指令。
- 网络通信接口：使计算机通过网络与其他计算机通信或浏览网络。
示例:
- 例如对磁盘的读/写通常通过块设备接口完成；对键盘这类字符设备可通过流设备接口处理。
常见误区:
- 所有设备都用同一种接口。
- 网络接口只负责物理连接，不涉及通信软件。
自测:
Q: I/O 系统与高层之间按设备类型可分为哪三类接口？
A: 块设备接口、流设备接口、网络通信接口。
Q: 流设备接口又称为什么接口？
A: 字符设备接口。

可延伸方向: 可延伸到用户层库函数与系统调用; 可补充块设备、字符设备、网络设备的差异
