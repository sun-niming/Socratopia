## 教学地图（第 140-169 页）

### 阶段 1: 同步基础与信箱
**[当前教学焦点 / 队列起点]** 目标: 先建立消息存放结构与进程同步的直观模型，再过渡到信号量和消息原语的写法。

#### 信箱数据结构
信箱是一种数据结构，逻辑上分为信箱头和信箱体。信箱头是描述部分，保存信箱名、信箱大小、已存信件数和空格子数；信箱体由若干格子组成，每个格子可存放一个信件。
要点:
- 信箱头负责描述信箱，不存放具体信件内容
- 信箱体由若干格子组成，且每格只能放一个信件
- 信箱头信息包括 boxname、boxsize、mesnum、fromnum
示例:
- 信箱头可写成 boxname、boxsize、mesnum、fromnum；信箱体中可以出现“满 信件”“空 格子”这样的格子状态
常见误区:
- 信箱不是只有一堆消息格子，它还必须有头部描述信息
自测:
Q: 信箱头和信箱体分别做什么?
A: 信箱头负责描述信箱，信箱体由若干格子组成，每个格子存一个信件。

#### 三进程同步实例
某台机挂有输入机和打印机时，可把任务分成 3 个进程：输入进程 R、复制进程 C、打印进程 P。R 负责把数据从卡片机输入到缓冲区 B1，C 负责把 B1 复制到 B2，P 负责在打印机上打印 B2。
要点:
- 系统可设 3 个进程：R、C、P
- R 受 C 约束，C 受 R 和 P 约束，P 受 C 约束
- 这是一个典型的进程协作与同步问题
示例:
- R 输入到 B1，C 再把 B1 复制到 B2，最后 P 打印 B2
常见误区:
- 三个进程不是完全独立运行的，它们存在先后制约
自测:
Q: R、C、P 分别做什么?
A: R 负责输入到 B1，C 负责把 B1 复制到 B2，P 负责在打印机上打印 B2。

#### P-V与消息原语同步
对三进程同步问题，可用 4 个信号量 S1=1、S2=0、S3=1、S4=0 编写 P-V 同步算法；也可以用消息通信原语表示为用 RECEIVE 代替 P，用 SEND 代替 V。原文给出的对应关系是：RECEIVE(C) 代替 P(S1) 和 P(S4)，SEND(C) 代替 V(S2) 和 V(S3)；RECEIVE(R) 代替 P(S2)，SEND(R) 代替 V(S1)；RECEIVE(P) 代替 P(S3)，SEND(P) 代替 V(S4)。
要点:
- 初值可设 S1=1，S2=0，S3=1，S4=0
- RECEIVE 和 SEND 可分别替代 P 和 V 操作
- 原文还说明，S1 也可以先设为 0，再把 R 进程的 P(S1) 调到 V(S2) 后面
示例:
- R 用 RECEIVE(R)/SEND(R)，C 用 RECEIVE(C)/SEND(C)，P 用 RECEIVE(P)/SEND(P)
常见误区:
- 消息通信原语不是额外增加了一个任务，而是表达同一同步关系的另一种方式
自测:
Q: 该实例中 4 个信号量的初值是多少?
A: S1=1，S2=0，S3=1，S4=0。

可延伸方向: 可延伸到同步原语的更多变体; 可继续讲互斥与条件同步的区别

### 阶段 2: 进程属性到线程引入
**[后续教学队列]** 目标: 让弱模型先理解进程为什么能独立运行、并发为什么有开销，再说明线程为何出现以及它承担什么角色。

#### 进程的两个基本属性
进程有两个基本属性：第一，它是一个可拥有资源的独立单位；第二，它又是一个可独立调度和分派的基本单位。
要点:
- 独立运行的进程必须拥有一定资源，如程序正文、数据、I/O 设备、已打开文件、信号量等
- 每个进程在系统中有唯一的 PCB，系统可据此感知、调度和恢复进程
- 进程之所以能独立运行，正因为同时具备资源属性和调度属性
示例:
- PCB 中可保存断点信息，用于恢复进程运行现场
常见误区:
- 进程不只是程序本身，还要有资源和 PCB 支持
- 独立调度不等于独立拥有处理机
自测:
Q: 进程的两个基本属性是什么?
A: 可拥有资源的独立单位；可独立调度和分派的基本单位。

#### 程序并发执行的时空开销
为了使程序能并发执行，系统需要创建进程、撤消进程和进行进程切换，这些都会带来资源和处理机时间开销。
要点:
- 创建进程时要分配除处理机以外的资源，并建立 PCB
- 撤消进程时要先回收资源，再撤消 PCB
- 进程切换时要保存当前 CPU 环境并设置新进程的 CPU 环境
示例:
- 系统创建进程时要分配内存空间、I/O 设备并建立 PCB
常见误区:
- 并发不是免费的，特别是进程切换会花费不少处理机时间
自测:
Q: 创建进程时系统必须做什么?
A: 为进程分配除处理机以外的必需资源，并建立相应的 PCB。

#### 线程引入的目的
在操作系统中引入线程，是为了在进程并发执行的基础上，进一步减少程序并发执行时付出的时空开销，从而使 OS 具有更好的并发性。
要点:
- 进程解决的是多程序并发执行
- 线程追求的是更低的并发开销
- 线程的引入目标不是替代进程，而是让并发更轻量
示例:
- 教材明确指出：引入线程是为了减少程序并发执行时所付出的时空开销
常见误区:
- 引入线程不是为了取消进程，而是为了减少开销
自测:
Q: 为什么还要在进程之外引入线程?
A: 为了减少并发执行时的时空开销，并使 OS 具有更好的并发性。

#### 线程作为调度和分派单位
线程的提出，是把进程的两个基本属性分开处理：把调度和分派的基本单位与拥有资源的基本单位分离开，使线程成为调度和分派的基本单位，而资源仍主要由进程拥有。
要点:
- 让调度单位更轻量，以做到轻装上阵
- 拥有资源的单位不再频繁切换
- 线程成为更适合并发执行的基本执行单元
示例:
- 教材中的概括是：并不把作为调度和分派的基本单位也同时作为拥有资源的单位
常见误区:
- 线程作为调度单位，不等于进程不再拥有资源
自测:
Q: 线程为什么被看作调度和分派的基本单位?
A: 因为操作系统把进程的资源属性和调度属性分开处理，线程承担调度和分派。

可延伸方向: 可延伸到进程与线程的关系辨析; 可继续讲多线程为何能降低切换成本
