## 教学地图（第 90-119 页）

### 阶段 1: 进程状态控制原语
**[当前教学焦点 / 队列起点]** 目标: 先让学习者分清阻塞、唤醒、挂起、激活分别在什么条件下发生，以及 PCB 和队列如何变化。

#### 进程阻塞触发事件
教材列出会引起进程阻塞的四类事件：1）向系统请求共享资源失败；2）等待某种操作完成；3）新数据尚未到达；4）等待新任务的到达。只要进程在运行中遇到这些条件之一，就需要转入阻塞状态等待。
要点:
- 请求共享资源而系统暂时无足够资源时，进程阻塞等待
- 进程启动某种操作后，若必须等该操作完成才能继续，则先阻塞
- 合作进程所需数据未到达前不能继续运行，只能阻塞
- 等待新任务到达也是阻塞原因之一
示例:
- 例如：进程启动 I/O 操作后，必须等 I/O 完成才能继续执行。
常见误区:
- 阻塞不等于终止，进程只是暂时停止执行并等待条件满足
自测:
Q: 教材中列出的进程阻塞触发事件有哪些？
A: 向系统请求共享资源失败、等待某种操作完成、新数据尚未到达、等待新任务的到达。

#### 阻塞原语 block
阻塞原语 block 用于停止调用进程的执行，使其变为等待状态。进程发生阻塞事件时，会通过调用 block 将自己阻塞。进入 block 后，应立即停止执行，把进程控制块 PCB 中的现行状态由“执行”改为“阻塞”，并将 PCB 插入阻塞队列；如果系统按不同事件设置了多个阻塞队列，则应插入与该事件对应的队列。
要点:
- 阻塞是进程自身的一种主动行为
- block 的作用是停止调用进程的执行并进入等待
- block 过程中要把 PCB 状态由执行改为阻塞
- PCB 需要插入阻塞队列，且可按事件分别排队
示例:
- 进程正在执行，若所需资源暂时得不到满足，则调用 block 后转入阻塞队列等待。
常见误区:
- 阻塞不是系统随意剥夺处理机，而是进程在条件不满足时主动进入等待
自测:
Q: block 原语执行后，PCB 的状态如何变化？
A: 由“执行”改为“阻塞”，并插入相应的阻塞队列。

#### 唤醒原语 wakeup
唤醒原语 wakeup 用于唤醒某一处于等待队列中的进程。当被阻塞进程所期待的事件发生时，由有关进程调用 wakeup，把该进程从等待该事件的阻塞队列中移出，将其 PCB 中的现行状态由“阻塞”改为“就绪”，然后再将 PCB 插入就绪队列。
要点:
- wakeup 的对象是处于等待队列中的进程
- 触发条件是被等待的事件已经发生
- 唤醒时要先从阻塞队列中移出 PCB
- PCB 状态由阻塞改为就绪，再进入就绪队列
示例:
- 例如：被阻塞进程等待的 I/O 操作完成后，可由有关进程调用 wakeup 将其唤醒。
常见误区:
- 唤醒后并不表示立即运行，进程只是先进入就绪队列等待调度
自测:
Q: wakeup 原语执行后，进程会直接运行吗？
A: 不会，进程先变为就绪状态并进入就绪队列，之后还要等待调度。

#### 挂起与激活原语
挂起原语 suspend 用于使进程进入静止状态，它可以实现自身挂起、挂起具有指定标识符的进程，也可以挂起该进程及其全部或部分子孙。激活原语 Active 用于使处于静止状态的进程变为活动状态。
要点:
- suspend 的作用是把进程置为静止状态
- suspend 可以针对自身、指定进程或其部分子孙
- Active 的作用是把静止状态的进程变为活动
- 挂起与激活与阻塞/唤醒不同，强调的是静止与活动状态
示例:
- 例如：一个进程可先被 suspend，之后再由 Active 重新变为活动。
常见误区:
- 挂起不等于阻塞；挂起强调静止状态，而阻塞强调等待某事件
自测:
Q: 挂起原语和激活原语分别做什么？
A: suspend 使进程进入静止状态，Active 使静止状态的进程变为活动。

### 阶段 2: 同步、互斥与临界区
**[后续教学队列]** 目标: 建立并发进程为什么需要协调的整体认识，并掌握临界资源、临界区和同步机制应满足的基本要求。

#### 进程同步与互斥
在多道程序环境中，进程并发执行会形成两类相互制约关系：间接相互制约关系（进程—资源—进程）称为互斥；直接相互制约关系（进程—进程）称为同步。由于进程获得处理机运行的时机和运行速度不能由自己控制，这种特性称为异步性，可能导致共享变量或数据结构的访问顺序不同，从而使每次执行结果不一致。
要点:
- 互斥对应的是进程—资源—进程的间接制约关系
- 同步对应的是进程—进程的直接制约关系
- 进程的异步性会带来结果的不确定性
- 多个进程共享变量时，不同执行顺序可能产生不同结果
示例:
- 例如：两个进程 P1、P2 公用变量 COUNT，初始值为 0；由于执行顺序可能交错，不同顺序会得到不同的 COUNT 值。
常见误区:
- 同步不等于互斥：同步强调先后次序，互斥强调不能同时进入共享资源
自测:
Q: 教材中把哪种关系称为互斥，哪种关系称为同步？
A: 间接相互制约关系称为互斥，直接相互制约关系称为同步。

#### 临界资源与临界区
临界资源是一次只能供一个进程使用的资源，使用完后归还系统，才能供其他进程使用。进程中访问临界资源的那段代码称为临界区。为了实现对临界资源的互斥访问，诸进程必须互斥地进入自己的临界区，并且每个进程在进入临界区前必须先申请，经允许后方可进入。
要点:
- 临界资源一次只能被一个进程使用
- 临界区是访问临界资源的那段代码
- 进入临界区前必须先申请并获得允许
- 实现临界资源互斥访问的核心是控制临界区进入
示例:
- 例如：变量 COUNT 在教材中被看作临界资源。
常见误区:
- 临界区不是资源本身，而是访问该资源的代码段
自测:
Q: 什么是临界区？
A: 进程中访问临界资源的那段代码。

#### 同步机制四准则
为实现进程互斥地进入临界区，同步机制应遵循四条准则：空闲让进、忙则等待、有限等待、让权等待。空闲让进要求当无进程处于临界区时，必须立即让一个要求进入的进程进入；忙则等待要求已有进程在临界区内时，其它进程必须等待；有限等待要求要求进入临界区的进程应在有限时间内进入，避免死等；让权等待要求等待进程立即释放处理机，避免忙等。
要点:
- 空闲让进：临界区空闲时应立即允许进入
- 忙则等待：临界区忙时其他进程必须等待
- 有限等待：等待不能无限延长，要避免死等
- 让权等待：等待时应释放处理机，避免忙等
示例:
- 例如：若某进程想进入临界区但当前已有进程在内，它应等待而不是一直占用 CPU 反复检测。
常见误区:
- 忙则等待不等于忙等；是否忙等取决于等待时是否还占用处理机
自测:
Q: 同步机制应遵循哪四条准则？
A: 空闲让进、忙则等待、有限等待、让权等待。
