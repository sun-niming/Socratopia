## 教学地图（第 16-45 页）

### 阶段 1: 早期系统与批处理演进
**[当前教学焦点 / 队列起点]** 目标: 先让学习者理解没有操作系统时的人工操作和脱机 I/O，再理解单道批处理为何效率有限，最后过渡到多道批处理如何提高资源利用率。

#### 人工操作与脱机I/O方式
在未配置操作系统的计算机系统中，人工操作方式是指用户直接占用全机、由人工完成装入、运行和输出等操作；其缺点是用户独占全机、CPU 等待人工操作。脱机输入/输出方式则把输入输出与主机计算分离，借助外围机和磁盘进行中间处理，从而减少 CPU 空闲时间、提高 I/O 速度。
要点:
- 人工操作方式的两个缺点：用户独占全机、CPU 等待人工操作。
- 脱机 I/O 的主要优点：减少 CPU 空闲时间、提高 I/O 速度。
- 脱机 I/O 中出现了外围机、磁盘、主机和输入/输出设备之间的分工。
示例:
- 输入设备 → 外围机 → 磁盘 → 主机；主机再把结果送往外围机 → 输出设备。
常见误区:
- 脱机输入/输出不是把 I/O 变成完全无人操作。
- 脱机 I/O 的目的不是提高 CPU 运算速度，而是减少 CPU 因等待 I/O 造成的空闲。
自测:
Q: 人工操作方式的两个主要缺点是什么？
A: 用户独占全机，CPU 等待人工操作。
Q: 脱机输入/输出方式的主要优点是什么？
A: 减少 CPU 的空闲时间，提高 I/O 速度。

#### 单道批处理系统
单道批处理系统是在内存中只装入一道作业的批处理系统。它把一个作业按“源程序检查—装配成目标程序—运行”的顺序自动处理，具有自动性、顺序性和单道性。由于内存中只有一道程序，一旦该程序发出 I/O 请求，CPU 就要等待 I/O 完成，因此资源利用率较低。
要点:
- 内存中同一时刻只有一道程序。
- 处理过程按顺序自动进行。
- 程序发出 I/O 请求时 CPU 会等待，导致资源利用不充分。
示例:
- 流程可概括为：源程序 → 检查有错吗？ → 装配 → 目标程序 → 运行。
常见误区:
- 单道批处理并不是多道作业并发。
- 它虽然能自动处理作业，但不能避免 I/O 造成的 CPU 空闲。
自测:
Q: 单道批处理系统的主要特征有哪些？
A: 自动性、顺序性、单道性。
Q: 单道批处理系统的主要缺点是什么？
A: 资源得不到充分利用，CPU 会因 I/O 请求而等待。

#### 多道批处理系统
多道批处理系统是指内存中同时存在多道用户作业，它们共享 CPU 和系统中的各种资源。这样做可以提高 CPU 利用率、提高内存和 I/O 设备利用率，并增加系统吞吐量。它的特征是多道性、无序性和调度性。其缺点是平均周转时间长、无交互能力。
要点:
- 多道批处理的核心是“多道作业同时驻留内存、共享资源”。
- 主要优点：资源利用率高、系统吞吐量大。
- 主要缺点：平均周转时间长、无交互能力。
- 还需要解决处理机争用、内存分配和保护、I/O 设备分配、文件组织与管理、作业管理、用户与系统接口等问题。
示例:
- 教材所述多道批处理系统可视为：多个用户作业在内存中并存，由调度机制决定其运行次序。
常见误区:
- 多道批处理不等于多台机器并行处理。
- “多道性”强调驻留多道作业，不是每道作业都在同一时刻执行。
自测:
Q: 多道批处理系统为什么能提高 CPU 利用率？
A: 因为内存中同时有多道作业，当某道作业等待 I/O 时，CPU 可以转去处理其他作业。
Q: 多道批处理系统的两个主要缺点是什么？
A: 平均周转时间长、无交互能力。

可延伸方向: 可进一步比较批处理与交互式系统。; 可引出“CPU 等待 I/O”的问题。

### 阶段 2: 交互与实时需求
**[后续教学队列]** 目标: 理解分时系统如何满足多人交互，以及实时系统为何强调截止时间和及时响应。

#### 分时系统
分时系统是指在一台主机上连接多个带显示器和键盘的终端，允许多个用户通过自己的终端以交互方式使用计算机，并共享主机资源。它产生的主要动力来自用户需求，重点在于人—机交互、共享主机和便于用户上机。实现分时系统的关键问题是及时接收和及时处理。其特征包括多路性、独立性、及时性和交互性。
要点:
- 多个终端用户共享同一主机。
- 以交互方式工作，而不是批量等待。
- 关键在于对各终端请求及时接收、及时处理。
- 特征：多路性、独立性、及时性、交互性。
示例:
- 一台主机连接多个终端，每个用户都能在自己的终端上与系统对话。
常见误区:
- 分时系统的“及时性”不是硬实时的截止时间要求，而是用户可接受的响应时间。
- 分时系统强调交互，不是批处理。
自测:
Q: 分时系统的关键问题是什么？
A: 及时接收和及时处理。
Q: 分时系统的主要特征有哪些？
A: 多路性、独立性、及时性、交互性。

#### 实时系统
实时系统是指系统能及时响应外部事件的请求，并在规定时间内完成对该事件的处理，同时控制所有实时任务协调一致地运行。实时系统可分为工业控制系统、信息查询系统、多媒体系统和嵌入式系统。实时任务按是否周期性可分为周期性实时任务和非周期性实时任务；按截止时间要求可分为硬实时任务和软实时任务。
要点:
- 实时的核心是“在规定时间内完成处理”。
- 实时任务可以按周期性分为周期性与非周期性任务。
- 非周期性任务也有截止时间，可分为开始截止时间和完成截止时间。
- 硬实时任务必须满足截止时间；软实时任务允许偶尔错过截止时间。
- 与分时系统相比，实时系统更强调控制对象的截止时间和高度可靠性。
示例:
- 硬实时任务：若不满足截止时间，可能出现难以预测的结果。
- 软实时任务：偶尔错过截止时间，对系统影响不大。
常见误区:
- 实时系统并不等于运行速度一定最快，而是强调及时性。
- 软实时任务也有关联的截止时间，只是要求不那么严格。
自测:
Q: 什么是实时系统？
A: 能及时响应外部事件请求，并在规定时间内完成处理、协调实时任务运行的系统。
Q: 硬实时任务和软实时任务有什么区别？
A: 硬实时任务必须满足截止时间，否则结果可能难以预测；软实时任务的截止时间不那么严格，偶尔错过影响不大。

可延伸方向: 可扩展到实时系统与分时系统的对比。; 可讨论硬实时与软实时的区别。
