## 教学地图（第 477-506 页）

### 阶段 1: 先建立文件组织与目录的基本概念
**[当前教学焦点 / 队列起点]** 目标: 先说明文件组织方式中的索引、顺序与直接访问思想，为后续目录和共享做铺垫。

#### 索引文件与多索引表
索引文件是使用按关键字建立索引表的文件组织方式。它与顺序文件一样，都只能按该关键字进行检索；如果实际应用需要按不同属性或不同关键字检索同一条记录，就需要为顺序文件建立多个索引表。也就是说，对每一种可能成为检索条件的域（属性或关键字），都配置一张索引表，并且每张索引表都按相应属性或关键字排序。
要点:
- 索引文件本质上仍是围绕关键字检索。
- 当需要按多个属性检索时，可为同一顺序文件建立多个索引表。
- 每张索引表对应一种检索条件的域，并按该属性/关键字排序。
示例:
- 例如，若记录既可能按“学号”检索，也可能按“姓名”检索，则可分别建立“学号索引表”和“姓名索引表”。
常见误区:
- 不是建立一个索引表就能满足所有属性检索。
- 索引文件并不等于任意字段都能自动检索；仍需预先为相应关键字建立索引。
自测:
Q: 为什么实际应用中常需要为顺序文件建立多个索引表？
A: 因为不同用户可能希望按不同属性或不同关键字检索同一条记录，所以要为每种可能的检索条件分别建立索引表。

#### 索引顺序文件
索引顺序文件是对顺序文件的一种改进：它既保留了记录按关键字顺序组织这一特征，又增加了文件索引表以支持随机访问，还增加了溢出（overflow）文件来记录新增加、删除和修改的记录。它基本上克服了变长记录顺序文件不能随机访问，以及不便于删除和插入的缺点。
要点:
- 保留顺序文件中记录按关键字顺序组织的特征。
- 通过文件索引表实现随机访问。
- 通过溢出文件记录新增、删除和修改的记录。
示例:
- 原文所述：索引顺序文件“增加了两个新特征：一个是引入了文件索引表……另一个是增加了溢出（overflow）文件”。
常见误区:
- 索引顺序文件不是完全放弃顺序组织。
- 溢出文件不是主文件本体，而是用于记录变动记录的附加部分。
自测:
Q: 索引顺序文件相对于顺序文件增加了哪两个新特征？
A: 增加了文件索引表以实现随机访问，以及溢出文件以记录新增加、删除和修改的记录。

#### 一级索引顺序文件
一级索引顺序文件是最简单的索引顺序文件。建立方法是：先把变长记录顺序文件中的所有记录分成若干组，例如每 50 个记录为一组；再为顺序文件建立索引表，并为每组中的第一个记录建立一个索引项，索引项中包含该记录的关键字和指向该记录的指针。
要点:
- 先分组，再为每组首记录建立索引项。
- 索引项包含关键字和指向记录的指针。
- 这种结构是最常见的一种逻辑文件形式。
示例:
- 例如，把记录按 50 个一组分组，则每组第一个记录在索引表中对应一个索引项。
常见误区:
- 不是每条记录都必须单独建索引项。
- 一级索引并不等于多级索引；它只对“组首记录”建立一层索引。
自测:
Q: 一级索引顺序文件的索引项通常包含什么？
A: 包含该记录的关键字和指向该记录的指针。

#### 直接文件
直接文件是根据给定的记录键值，直接获得指定记录物理地址的一类文件组织方式。也就是说，记录键值本身就决定了记录的物理地址；这种从记录键值到物理地址的转换称为键值转换（Key to address transformation）。组织直接文件的关键在于选择合适的键值到物理地址的转换方法。
要点:
- 给定键值后，可直接得到物理地址。
- 键值本身决定物理地址。
- 核心问题是如何实现键值到地址的转换。
示例:
- 原文表述：根据给定的记录键值，直接获得指定记录的物理地址。
常见误区:
- 直接文件不一定等于顺序文件。
- “直接”指地址映射直接，不表示访问过程中完全没有任何转换。
自测:
Q: 什么是键值转换？
A: 指记录键值到记录物理地址的转换。

可延伸方向: 比较顺序文件、索引文件、直接文件的检索特点; 补充哈希地址映射的直观含义

### 阶段 2: 再讲目录、FCB 与索引结点
**[后续教学队列]** 目标: 让弱模型理解文件如何被目录管理、如何通过FCB/i结点描述文件。

#### Hash 文件
Hash 文件是一种应用最广泛的直接文件。它利用 Hash 函数（散列函数）把关键字转换为相应记录的地址；但为了实现文件存储空间的动态分配，通常由 Hash 函数求得的并不是记录本身的地址，而是指向目录表相应表目的指针，而该表目的内容再指向相应记录所在的物理块。
要点:
- Hash 文件属于直接文件。
- Hash 函数把关键字映射到地址或目录表项。
- 为支持动态分配，常先定位到目录表项，再由表项指向物理块。
示例:
- 可写为：$h(	ext{关键字}) ightarrow 	ext{目录表项指针} ightarrow 	ext{物理块}$。
常见误区:
- Hash 函数不一定直接返回记录所在物理地址。
- Hash 文件不等于简单地“按顺序存放”。
自测:
Q: Hash 文件中 Hash 函数通常返回什么？
A: 通常返回指向目录表相应表目的指针，而不是直接返回记录的物理地址。

#### 文件目录的作用
文件目录用于有效管理大量文件，其最基本的功能是把文件名转换为该文件在外存中的物理位置。文件目录还承担按名存取、提高目录检索速度、支持文件共享以及允许文件重名等管理要求。
要点:
- 文件目录的核心作用是文件名到外存物理位置的转换。
- 目录管理要支持按名存取。
- 目录管理还要考虑检索速度、共享和重名问题。
示例:
- 例如，用户输入文件名后，系统通过目录找到该文件在外存中的位置。
常见误区:
- 文件目录不只是“文件列表”，而是负责名字到位置的映射。
- 目录的管理目标不止是查找，还包括共享和重名处理。
自测:
Q: 文件目录最基本的功能是什么？
A: 将文件名转换为该文件在外存的物理位置。

#### 文件控制块 FCB
文件控制块（FCB）是为了对一个文件进行正确存取而设置的数据结构。文件与文件控制块一一对应，一个文件控制块就是一个文件目录项；文件控制块的有序集合构成文件目录。通常一个文件目录也可看作一个文件，称为目录文件。
要点:
- 每个文件都对应一个文件控制块。
- FCB 也是目录项。
- 文件控制块的有序集合就是文件目录。
示例:
- 原文可概括为：文件与文件控制块一一对应。
常见误区:
- FCB 不是整个文件本身。
- 文件目录不是随意堆放的条目，而是 FCB 的有序集合。
自测:
Q: 文件控制块和文件目录是什么关系？
A: 文件与文件控制块一一对应，而文件控制块的有序集合称为文件目录。

#### FCB 三类信息
文件控制块包含三类信息：基本信息、存储控制信息和使用信息。基本信息包括文件名、文件物理位置和文件长度；存储控制信息包括文件主的存取权限、核准用户的存取权限和一般用户的存取权限；使用信息包括建立日期和时间、上一次修改日期和时间、当前使用信息。
要点:
- 基本信息：文件名、物理位置、文件长度等。
- 存储控制信息：各种访问权限。
- 使用信息：建立、修改及当前使用情况。
示例:
- 可按表述记忆：基本信息管“是什么、在哪里、占多大”；存储控制信息管“谁能访问”；使用信息管“什么时候建立和修改”。
常见误区:
- 权限信息不属于基本信息。
- 文件长度不是“使用信息”，而是基本信息的一部分。
自测:
Q: 文件控制块包含哪三类信息？
A: 基本信息、存储控制信息、使用信息。

可延伸方向: 把目录理解成文件名到物理位置的映射; 用表格方式梳理FCB信息分类
