## 教学地图（第 388-417 页）

### 阶段 1: I/O系统与中断基础
**[当前教学焦点 / 队列起点]** 目标: 先建立中断在 I/O 系统中的地位，区分外部中断与内中断，并了解多中断源处理所依赖的基本概念。

#### 中断的作用
中断是操作系统 I/O 系统中的关键机制。它使 CPU 在设备发出中断信号时，能够暂停当前程序、保存 CPU 环境、转去执行中断处理程序，处理完毕后再返回断点继续执行原程序。原文强调：中断是多道程序实现的基础，因为进程之间的切换通过中断完成；中断也是设备管理的基础，因为它支持提高处理机利用率以及 CPU 与 I/O 设备并行执行。
要点:
- 中断处理程序是 I/O 系统中最低的一层，也是整个 I/O 系统的基础。
- 没有中断，就不可能实现多道程序。
- 为了提高处理机利用率并实现 CPU 与 I/O 设备并行执行，必须有中断支持。
示例:
- CPU 响应 I/O 设备发来的中断信号后，暂停正在执行的程序，保存 CPU 环境，转去执行 I/O 设备的中断处理程序，完成后返回断点继续执行。
常见误区:
- 把中断看成只是“设备报警”而忽略其在进程切换和并行执行中的基础作用。
- 认为中断只对某一种设备有用，而不是 I/O 系统的基础机制。
自测:
Q: 为什么说中断是多道程序得以实现的基础？
A: 因为进程之间的切换是通过中断来完成的，没有中断就不能实现多道程序。
Q: 中断在设备管理中有什么作用？
A: 它用于支持提高处理机利用率，并使 CPU 与 I/O 设备并行执行。

#### 中断与陷入
中断可分为外部设备引起的中断和 CPU 内部事件引起的中断。原文中，CPU 对 I/O 设备发来的中断信号的响应称为中断；而由 CPU 内部事件引起的中断，例如上溢、下溢、非法指令、地址越界、电源故障等，通常称为内中断或陷入。
要点:
- 中断：CPU 对 I/O 设备发来的中断信号的响应。
- CPU 暂停当前程序，保存环境后转去执行中断处理程序。
- 内中断或陷入：由 CPU 内部事件引起，如上溢、下溢、非法指令、地址越界、电源故障等。
示例:
- 程序执行时发生非法指令，属于 CPU 内部事件引起的中断，可称为陷入。
常见误区:
- 把所有中断都理解为外部设备发来的信号。
- 把陷入和普通外部中断混为一谈。
自测:
Q: 什么叫中断？
A: 中断是 CPU 对 I/O 设备发来的中断信号的一种响应。
Q: 什么叫陷入？
A: 由 CPU 内部事件所引起的中断称为内中断或陷入。

#### 中断向量表与优先级
面对多个中断源，系统需要借助中断向量表和中断优先级来组织中断响应。原文只列出了这两个概念以及多中断源处理方式，但未展开其具体定义与实现细节；因此本卡片仅保留为中断处理中的必要概念性知识点。
要点:
- 中断简介中包含中断向量表和中断优先级。
- 多中断源的处理方式与中断优先级、屏蔽中断、嵌套中断有关。
- 这些概念用于协调多个中断请求的响应顺序。
示例:
- 多中断源情况下，系统可依据中断优先级决定先响应哪个中断。
常见误区:
- 认为所有中断都按到达顺序依次处理。
- 把中断向量表等同于设备本身的状态表。
自测:
Q: 原文中提到多中断源处理方式与哪些概念有关？
A: 中断向量表、中断优先级、屏蔽中断、嵌套中断。

可延伸方向: 补充中断响应的现场保护思想; 可进一步联系进程切换为何依赖中断

### 阶段 2: 中断处理与设备驱动
**[后续教学队列]** 目标: 说明中断到来后系统如何处理，以及驱动程序在软件层次中的位置、职责和特点。

#### 中断处理程序的步骤
中断处理程序是在设备发出中断请求后，由 CPU 转入执行的一组处理步骤。原文给出的处理过程是：测定是否有未响应的中断信号并唤醒被阻塞的驱动程序进程；保护被中断进程的 CPU 环境；分析中断原因并转入相应设备中断处理程序；进行中断处理；恢复被中断进程的现场。除第一步外，其余步骤对所有 I/O 设备都相同。
要点:
- 要先检查是否存在未响应的中断信号，并唤醒被阻塞的驱动程序进程。
- 必须先保护被中断进程的 CPU 环境，再进行后续处理。
- 要分析中断原因，进入相应设备的中断处理程序。
- 处理完成后恢复被中断进程的 CPU 现场，返回继续执行。
示例:
- 当某进程请求 I/O 后，I/O 完成时设备控制器向 CPU 发出中断请求，CPU 响应后进入中断处理程序，最后恢复现场并返回原进程。
常见误区:
- 认为中断到来后可以直接修改进程状态而不保存现场。
- 认为所有步骤都因设备不同而完全不同；原文指出除第一步外其余步骤对所有 I/O 设备都相同。
自测:
Q: 中断处理程序的标准流程是什么？
A: 测定是否有未响应的中断信号并唤醒被阻塞的驱动程序进程；保护被中断进程的 CPU 环境；分析中断原因并转入相应处理程序；进行中断处理；恢复被中断进程的现场。
Q: 为什么要先保护被中断进程的 CPU 环境？
A: 为了在中断处理完成后能够恢复现场，继续执行原来的程序。

#### 设备驱动程序
设备驱动程序是 I/O 系统中高层软件与设备控制器之间的通信程序，也称设备处理程序。它把上层软件发来的抽象 I/O 要求转换成具体要求发送给设备控制器，同时把设备控制器发来的信号传送给上层软件。由于驱动程序与硬件密切相关，通常每一类设备都应配置一种驱动程序。
要点:
- 设备驱动程序位于 I/O 系统高层与设备控制器之间。
- 它负责抽象 I/O 要求与具体设备操作之间的转换。
- 设备驱动程序与硬件密切相关，通常一类设备配置一种驱动程序。
示例:
- 打印机和显示器通常需要不同的驱动程序。
常见误区:
- 把驱动程序当作普通应用程序。
- 认为所有设备都可以共用同一个驱动程序。
自测:
Q: 设备驱动程序的核心作用是什么？
A: 接收上层软件发来的抽象 I/O 要求，转换为具体要求发送给设备控制器，并把控制器信号传回上层软件。
Q: 为什么打印机和显示器通常需要不同驱动程序？
A: 因为驱动程序与硬件密切相关，不同设备应配置不同驱动程序。

#### 驱动程序的功能
设备驱动程序的主要功能包括：接收 I/O 进程的命令和参数并完成抽象到具体的转换；检查用户 I/O 请求的合法性并了解设备状态、设置工作方式；发出 I/O 命令并在设备忙碌时排队等待；及时响应控制器或通道发来的中断请求并调用相应中断处理程序；在具有通道的系统中，还要根据 I/O 请求自动构成通道程序。
要点:
- 把抽象要求转换为具体要求，例如把磁盘块号转换为盘面、磁道号、扇区号。
- 检查 I/O 请求合法性，了解设备状态，传递参数，设置工作方式。
- 设备空闲时立即启动；设备忙碌时把请求挂到设备队列。
- 响应中断请求并调用对应中断处理程序。
- 在设置有通道的系统中，驱动程序还可自动构成通道程序。
示例:
- 将磁盘块号转换为磁盘的盘面、磁道号及扇区号。
常见误区:
- 认为驱动程序只负责启动设备，不负责检查、转换和中断响应。
- 认为驱动程序在设备忙时会丢弃请求。
自测:
Q: 设备驱动程序至少有哪些功能？
A: 接收命令和参数并转换；检查合法性和设备状态；发出 I/O 命令并在忙时排队；响应中断；在通道系统中自动构成通道程序。
Q: 当设备忙碌时，驱动程序怎样处理请求？
A: 将请求者的请求块挂在设备队列上等待。

#### 驱动程序特点
设备驱动程序属于低级系统例程，与一般应用程序和系统程序不同。原文列出的特点包括：它是请求 I/O 的进程与设备控制器之间的通信与转换程序；与硬件特性紧密相关，因而不同设备需不同驱动程序；与 I/O 控制方式紧密相关；部分必须用汇编语言编写；应允许可重入；不允许系统调用。
要点:
- 驱动程序是低级系统例程。
- 与硬件特性和 I/O 控制方式紧密相关。
- 部分代码必须用汇编语言书写。
- 驱动程序应允许可重入。
- 驱动程序不允许系统调用。
示例:
- 一个正在运行的驱动程序常会在一次调用完成前被再次调用，因此必须允许可重入。
常见误区:
- 认为驱动程序可以像普通程序一样任意调用系统调用。
- 认为驱动程序不需要考虑可重入性。
自测:
Q: 为什么驱动程序要允许可重入？
A: 因为一个正在运行的驱动程序常会在一次调用完成前被再次调用。
Q: 驱动程序为什么通常要用汇编语言写一部分？
A: 因为它与硬件紧密相关。

可延伸方向: 可延伸到不同设备为何需要不同驱动程序; 可对比驱动程序与普通程序的差异
