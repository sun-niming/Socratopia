## 教学地图（第 375-404 页）

### 阶段 1: I/O设备分类基础
**[当前教学焦点 / 队列起点]** 目标: 先建立 I/O 设备的分类框架，区分按速度、按交换单位和按共享属性三种视角。

#### I/O设备按传输速率分类
教材按传输速率把 I/O 设备分为三类：低速设备、中速设备和高速设备。低速设备的传输速率仅为每秒钟几个字节至数百个字节，典型设备有键盘、鼠标器、语音的输入和输出设备；中速设备的传输速率在每秒钟数千个字节至数万个字节，典型设备有行式打印机、激光打印机；高速设备的传输速率在数百千个字节至数十兆字节，典型设备有磁带机、磁盘机、光盘机。
要点:
- 低速设备：每秒几个字节至数百个字节。
- 中速设备：每秒数千个字节至数万个字节。
- 高速设备：每秒数百千个字节至数十兆字节。
示例:
- 键盘、鼠标器、语音输入/输出属于低速设备。
- 行式打印机、激光打印机属于中速设备。
- 磁带机、磁盘机、光盘机属于高速设备。
常见误区:
- 传输速率分类不等于按存储方式分类。
- “高速/中速/低速”是按大致速率划分，教材给出的是典型范围和典型设备。
自测:
Q: 教材按传输速率如何划分 I/O 设备？
A: 分为低速设备、中速设备和高速设备。

#### I/O设备按交换单位和共享属性分类
按信息交换的单位，I/O 设备可分为块设备（Block Device）和字符设备（Character Device）。块设备用于存储信息，信息存取以数据块为单位，属于有结构设备；典型块设备是磁盘，每个盘块大小为 512B～4KB，磁盘设备通常可随机读/写任一块，且 I/O 常采用 DMA 方式。字符设备用于数据输入和输出，其基本单位是字符。按设备的共享属性，教材还把设备分为独占设备、共享设备和虚拟设备。
要点:
- 块设备以“数据块”为基本存取单位，主要用于存储信息。
- 字符设备以“字符”为基本单位，主要用于输入/输出。
- 按共享属性可分为独占设备、共享设备、虚拟设备。
示例:
- 磁盘是典型的块设备，每个盘块大小为 512B～4KB。
- 键盘、终端一类的输入输出常按字符设备理解。
常见误区:
- 块设备不是按速度分类得到的概念。
- 字符设备的基本单位是字符，不是数据块。
- 共享属性分类与传输速率分类是不同维度。
自测:
Q: 磁盘属于哪一类 I/O 设备？为什么？
A: 属于块设备，因为它以数据块为单位进行存取。

可延伸方向: 可继续延伸到块设备的 DMA 特征; 可对比字符设备与块设备的用途差异

### 阶段 2: 设备接口与编址
**[后续教学队列]** 目标: 理解设备、控制器与 CPU 的连接方式，以及设备寄存器在系统中的编址与访问方法。

#### 设备与控制器接口
设备通常并不是直接与 CPU 通信，而是与设备控制器通信，因此设备与设备控制器之间需要设置接口。该接口中传递三种类型的信号：数据信号、控制信号和状态信号；相应地，接口包含数据信号线、控制信号线和状态信号线。
要点:
- CPU 与 I/O 设备之间通常要先经过设备控制器。
- 接口中的三类信号是数据信号、控制信号、状态信号。
- 三类信号分别通过数据信号线、控制信号线、状态信号线传送。
示例:
- 教材图示中设备侧与控制器侧之间通过数据信号线、状态信号线、控制信号线连接。
常见误区:
- 设备不是直接与 CPU 进行通信。
- 状态信号不是数据本身，而是表示设备/控制器当前状态的信息。
自测:
Q: 设备与设备控制器之间为什么要设置接口？
A: 因为设备通常不直接与 CPU 通信，而是与设备控制器通信。

#### 设备控制器的功能与组成
设备控制器是 CPU 与 I/O 设备之间的接口，它接收 CPU 发来的命令并控制 I/O 设备工作，使处理机从繁杂的设备控制事务中解脱出来。其基本功能包括：接收和识别命令、数据交换、标识和报告设备状态、地址识别、数据缓冲和差错控制。教材还指出，设备控制器大多由三部分组成：设备控制器与处理机的接口、设备控制器与设备的接口、I/O 逻辑。
要点:
- 设备控制器处在 CPU 与 I/O 设备之间。
- 基本功能包括命令接收、数据交换、状态报告、地址识别、缓冲和差错控制。
- 典型组成包括处理机接口、设备接口和 I/O 逻辑。
示例:
- 地址识别依赖设备和寄存器地址及地址译码器。
- 数据缓冲可用缓冲器暂存由 CPU 传来的数据。
常见误区:
- 设备控制器不是简单的连线部件，而是承担命令识别、状态报告等功能。
- 设备控制器的作用之一是把 CPU 从繁杂的设备控制事务中解脱出来。
自测:
Q: 设备控制器的三个组成部分是什么？
A: 设备控制器与处理机的接口、设备控制器与设备的接口、I/O 逻辑。

#### I/O编址：特定I/O指令与内存映射I/O
教材先介绍利用特定 I/O 指令的方式：早期计算机为每个控制寄存器分配一个 I/O 端口，端口是一个 8 位或 16 位整数，并设置专门的 I/O 指令，例如 `io-store cpu-reg,dev-no,dev-reg`。这种方式的主要缺点是访问内存和访问设备需要两种不同的指令。内存映射 I/O 则不再区分内存单元地址和设备控制器中的寄存器地址，统一用 `k` 表示；当 `k` 处于 `0～n-1` 时表示内存地址，若 `k>=n` 时表示某个控制器的寄存器地址，因此可以直接使用普通存储指令，如 `store cpu-reg,n`。
要点:
- 特定 I/O 指令方式：I/O 端口与专门 I/O 指令并存。
- 其缺点是访问内存和访问设备要用不同指令。
- 内存映射 I/O：内存地址与控制器寄存器地址统一编址，直接用普通存储指令。
示例:
- `io-store cpu-reg,dev-no,dev-reg` 是教材给出的特定 I/O 指令形式。
- `store cpu-reg,n` 可用于把 CPU 寄存器内容送到控制器 0 的第 1 个寄存器。
常见误区:
- 内存映射 I/O 不是“给设备单独开一种完全不同的地址体系”，而是与内存统一编址。
- 特定 I/O 指令方式和内存映射 I/O 不能混为一谈。
自测:
Q: 内存映射 I/O 的核心特点是什么？
A: 内存地址和设备控制器寄存器地址统一编址，访问时可以直接使用普通存储指令。

可延伸方向: 可延伸到端口 I/O 与内存映射 I/O 的工程取舍; 可引出控制器如何承担命令识别和状态报告
