## 教学地图（第 417-446 页）

### 阶段 1: 设备分配与用户层 I/O
**[当前教学焦点 / 队列起点]** 目标: 先建立 I/O 系统的软件层次和设备分配基础，理解设备、控制器、通道的分配关系，以及用户程序如何通过库函数使用操作系统服务。

#### 独占设备的基本分配程序
在具有 I/O 通道的系统中，当进程提出 I/O 请求后，系统按照设备、控制器、通道的顺序进行独占设备分配。
要点:
- 基本步骤依次为：分配设备、分配控制器、分配通道。
- 该程序适用于具有 I/O 通道的系统。
示例:
- 进程提出 I/O 请求后，系统先选择并分配所需设备，再分配控制该设备的控制器，最后分配进行数据传送的通道。
常见误区:
- 不能把设备、控制器和通道看成同一个资源；基本分配程序分别对三者进行分配。
- 原文只说明了分配顺序，没有给出具体的分配算法或安全性判断方法。
自测:
Q: 具有 I/O 通道的系统中，独占设备的基本分配程序包括哪些步骤？
A: 依次包括分配设备、分配控制器和分配通道。

#### 独占设备分配程序的改进方向
基本设备分配程序存在物理设备依赖和单通路瓶颈两个问题，因此应通过增加设备独立性和考虑多通路情况来改进，以提高分配的灵活性和成功率。
要点:
- 问题一：进程以物理设备名提出 I/O 请求，使进程依赖具体硬件设备。
- 问题二：采用单通路 I/O 系统结构，容易产生瓶颈。
- 改进方向：增加设备的独立性；考虑多通路情况。
示例:
- 将“请求某个具体物理设备”改进为请求某类逻辑设备，体现增加设备独立性的方向。原文未进一步说明具体实现方法。
常见误区:
- 增加设备独立性并不等于增加物理设备数量，而是减少进程对具体物理设备名称的依赖。
- 多通路的目的不是改变 I/O 数据内容，而是减少单一路径造成的瓶颈。
自测:
Q: 基本设备分配程序存在的两个主要问题是什么？
A: 进程以物理设备名提出 I/O 请求；系统采用单通路 I/O 结构，容易产生瓶颈。
Q: 改进独占设备分配程序的两个方向是什么？
A: 增加设备的独立性，以及考虑多通路情况。

#### 用户层 I/O 软件的组成
用户层 I/O 软件是位于操作系统用户层、但仍属于 I/O 系统的软件，主要包括与用户程序链接在一起的库函数，以及完全运行于内核之外的假脱机系统、网络文件传输中使用的守护进程等程序。
要点:
- 大部分 I/O 软件位于操作系统内部，但仍有一小部分位于用户层。
- 用户层 I/O 软件包括与用户程序链接的库函数。
- SPOOLing 系统和某些网络文件传输守护进程可以完全运行在内核之外，但仍属于 I/O 系统。
示例:
- C 语言程序调用 I/O 库函数；该库函数与调用程序连接，并包含在运行时装入内存的二进制程序中。
常见误区:
- 运行在内核之外不代表不属于 I/O 系统。
- 用户层 I/O 软件不只包括库函数，也包括假脱机系统和某些守护进程。
自测:
Q: 用户层 I/O 软件主要包括哪些内容？
A: 包括与用户程序链接的库函数，以及完全运行于内核之外的假脱机系统、网络文件传输守护进程等程序。

#### 系统调用与库函数的关系
用户层软件必须通过系统调用取得操作系统服务；现代高级语言和 C 语言通常提供与系统调用对应的库函数，用户程序通过调用库函数间接使用系统调用。
要点:
- 系统调用是用户层软件取得操作系统服务的接口。
- 库函数通常与各系统调用一一对应。
- 库函数会与调用程序连接，并包含在运行时装入内存的二进制程序中。
- 库函数集合也是 I/O 系统的组成部分。
示例:
- 用户程序调用一个与 I/O 系统调用对应的库函数，库函数再帮助程序使用相应的系统调用。
常见误区:
- 用户程序通常不是直接通过普通函数调用获得操作系统服务，而是通过库函数使用系统调用。
- 库函数虽然与用户程序连接，但仍属于 I/O 系统的一部分。
自测:
Q: 用户程序通常如何使用系统调用？
A: 用户程序调用与系统调用对应的库函数，由库函数帮助用户程序使用系统调用。
Q: 库函数在 I/O 系统中具有什么地位？
A: 库函数集合是 I/O 系统的组成部分。

可延伸方向: 可延伸到设备独立性、逻辑设备名和多通路 I/O 的具体实现。

### 阶段 2: SPOOLing 与共享设备
**[后续教学队列]** 目标: 理解 SPOOLing 如何借助磁盘和进程模拟脱机输入、输出，并掌握共享打印机中数据、请求打印表和队列的流转过程。

#### SPOOLing 假脱机技术
SPOOLing 是在联机情况下，利用多道程序和高速磁盘模拟脱机输入、输出，使外围设备操作能够与 CPU 数据处理同时进行的技术；它可以把独占设备改造成共享设备。
要点:
- 脱机输入、输出技术原本利用专门的外围控制机，在低速 I/O 设备与高速磁盘之间传送数据。
- 引入多道程序后，可用一道程序模拟脱机输入的外围控制机，另一道程序模拟脱机输出的外围控制机。
- SPOOLing 使外围操作与 CPU 数据处理同时进行。
- SPOOLing 是把独占设备改造成共享设备的有效技术。
示例:
- 打印数据先被写入高速磁盘，之后再由输出进程从磁盘取出并送往打印机；用户进程不必直接长期占用打印机。
常见误区:
- SPOOLing 不只是简单的 I/O 缓冲，它还利用磁盘和相应进程模拟脱机输入、输出。
- SPOOLing 改造的是设备的使用方式，不是把物理独占设备变成硬件上的多台设备。
自测:
Q: SPOOLing 技术的核心作用是什么？
A: 在联机情况下模拟脱机输入、输出，使外围操作与 CPU 处理并行进行，并将独占设备改造成共享设备。
Q: SPOOLing 依靠什么介质暂存数据？
A: 通常依靠高速随机外存，教材中主要指磁盘存储技术。

#### SPOOLing 系统的组成与打印队列
SPOOLing 系统是对脱机输入、输出工作的模拟，通常需要高速随机外存支持，主要由输入井、输出井、输入缓冲区、输出缓冲区、输入进程 SPi、输出进程 SPo 以及井管理程序组成。
要点:
- 输入井和输出井通常位于磁盘等高速随机外存中，用于暂存输入、输出数据。
- 输入缓冲区和输出缓冲区用于数据在进程、磁盘和设备之间的传送。
- 输入进程 SPi 和输出进程 SPo 分别执行输入、输出方向的假脱机工作。
- 井管理程序负责管理输入井和输出井。
- 请求打印队列由若干张请求打印表组成；系统为每个请求打印的进程建立一张请求打印表。
示例:
- 多个进程分别提交打印请求，系统为每个进程建立请求打印表，并将这些表组成请求打印队列。
常见误区:
- 请求打印表记录的是打印要求，不等同于实际打印数据本身。
- 输入井、输出井是数据暂存区域，不是物理输入、输出设备。
自测:
Q: SPOOLing 系统主要由哪些部分组成？
A: 输入井和输出井、输入缓冲区和输出缓冲区、输入进程 SPi、输出进程 SPo，以及井管理程序。
Q: 请求打印队列由什么组成？
A: 由若干张请求打印表组成，系统为每个请求打印的进程建立一张请求打印表。

#### SPOOLing 系统的特点
SPOOLing 系统具有提高 I/O 速度、将独占设备改造成共享设备、实现虚拟设备功能三个主要特点。
要点:
- 通过磁盘等高速外存暂存数据，可以提高 I/O 速度。
- 通过排队和后台传送，可以让多个用户共享原本的独占设备。
- SPOOLing 可以向用户提供虚拟设备功能，使用户感觉自己能够使用一个独立的设备。
示例:
- 多个用户向同一台打印机提交输出请求，系统通过输出井和请求打印队列依次处理这些请求。
常见误区:
- “共享设备”不表示多个用户在同一时刻直接操作打印机，而是由系统排队和调度。
- 虚拟设备功能是 SPOOLing 提供的逻辑使用效果，不是新增了物理设备。
自测:
Q: SPOOLing 系统有哪三个主要特点？
A: 提高 I/O 速度，将独占设备改造成共享设备，实现虚拟设备功能。

#### SPOOLing 共享打印机的工作流程
利用 SPOOLing 共享打印机时，用户进程先把打印数据和打印要求交给假脱机系统；假脱机系统将数据存入输出井、建立请求打印表并排队，打印机空闲时再按队列顺序打印。
要点:
- 用户进程请求打印时，输出进程先在输出井中申请一个空闲盘块区，并把待打印数据送入其中。
- 输出进程再申请一张空白用户请求打印表，填写打印要求，并把该表挂到请求打印队列上。
- 打印机空闲时，输出进程从请求打印队列队首取出请求打印表。
- 输出进程根据表中要求，将数据从输出井传送到内存缓冲区，再由打印机打印。
示例:
- 若进程 A 和进程 B 先后提交打印请求，系统分别保存两者的数据并建立请求打印表，然后按照请求打印队列的顺序处理。
常见误区:
- 提交打印请求成功不等于数据已经立即由打印机输出。
- 打印数据存放在输出井，打印要求记录在请求打印表中，两者作用不同。
自测:
Q: 用户进程请求打印时，SPOOLing 系统首先做哪两件事？
A: 在输出井中申请空闲盘块区并写入打印数据；申请并填写请求打印表，再将其挂到请求打印队列上。
Q: 打印机空闲时，输出进程如何完成打印？
A: 从请求打印队列队首取出请求打印表，按表中要求把数据从输出井送到内存缓冲区，再由打印机打印。
