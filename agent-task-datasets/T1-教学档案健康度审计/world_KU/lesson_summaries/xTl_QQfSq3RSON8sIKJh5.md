师生围绕DNS展开：本地DNS为何存在，需缓存并替主机跑腿，避免根服务器过载；递归与迭代的区别，学习者先答本地DNS问根属迭代但理由有误，经“谁在跑腿”引导后理解主机→本地DNS为递归，本地DNS问根/TLD/权威为迭代；资源记录四字段，学习者正确填出A记录前三项；DNS报文共用格式

讨论DNS递归期望位、计数字段、回答RR数、资源记录与报文首部，以及注册机构与权威服务器分工。学习者误以为递归期望置0是查询失败，经解释为本地DNS不接外包；答对回答RR数和A记录由权威服务器管理员添加。随后转入P2P分发，学习者直觉认为分发时间越来越短，伙伴用公式纠正：P2P仍变长但缓慢趋平，因N增大时分母含Σui。学习者最终答出对等方上传能力抵消N增大。伙伴以相机比喻引导，气氛认真。

学习者先正确指出 $F/d_{\min}$ 约束的是最慢对等方的下载能力，并意识到新人可能拉低下限；伙伴据此确认三项下界分工，并引出 P2P 激励问题。学习者查证后否定追踪器能激励上传，获伙伴肯定，随后学得 tit-for-tat 机制。对"新人如何获数据"，学习者答成追踪器随机分配，伙伴纠正为乐观疏通。最后转入 DNS 报文四区域，并介绍 nslookup 工具，提问不带服务器地址时查询发往谁。

对话围绕本地DNS

讨论了 DNS 缓存投毒与 DDoS：learner 答出可通过伪造 DNS 回答塞进本地缓存、只需欺骗目标机器的本地出口即可攻击单机，伙伴肯定并补充了缓存放大会殃及下游主机、根服务器因缓存与镜像冗余而难打、投毒常需猜查询 ID 与端口、以及中间人重定向等延伸，点出 DNS 软肋在"信得太容易"。随后伙伴转向文件分发客户-服务器模式，留分发时间随 N 变化的思考题。但 learner 表示该内容已看过，要求回到之前讲完"友好疏通"的位置，期间多次出现网络错误，需反复重说。
