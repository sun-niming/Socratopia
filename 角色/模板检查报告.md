## 原有问题与处理

| 问题 | 影响 | 本次处理 |
|---|---|---|
| 27 份模板缺少 `## 基本信息` | 合并时旧字段留在正文，可能重复或互相冲突 | 全部改为可识别的头部；用实际解析器验证重复合并 |
| 索引与头部姓名、身份、关键词不完全一致 | 表单值和正文中的人设出现不同描述 | 统一为索引元数据，别名放到角色背景中 |
| `age: null` 与外表年龄、数百年经历等混用 | 编辑后出现不同年龄，推测被写成确定事实 | 头部省略未确定年龄；原背景资料保留 |
| 用 `avatar` 保存素材路径，说明却称 API 就绪 | API 实际读取 `avatarSourcePath`；`personaPath` 也不会自动读取 | 修正字段名，并明确从素材索引转换请求体的方法 |
| 010 的头像指向 `图片/` 文件夹 | 路径虽存在，却不是可读取的图片文件 | 改为 `图片/头像.webp` |
| 多个头像引用窄长介绍图，即使已有方形图 | 默认方形裁剪不便 | 11 个原神角色改用已有方形官方图；原图完整保留 |
| 部分要求绝不给答案、连续追问或反复练习 | 妨碍讲解、纠错与已掌握后的推进 | 改为必要引导、卡住时讲清、掌握后进入下一项 |
| 有自动总结下课、作业安排、虚构记录和奖惩 | 干扰项目结束与保存流程，制造不存在的状态 | 由系统流程处理，人物意象不表示真实写入 |
| 例子替学习者回答、使用空洞比喻或不规范旁白 | 模型可能模仿错误互动形式 | 重写为有具体内容的独立示例，避免模拟用户回应 |
| 缺少独立的情绪表现章节 | 角色表现集中在口头禅，受挫与纠错反应不够清楚 | 每个角色补充差异化的肯定、共情与自我纠正方式 |

新增“情绪表现”、统一例子结构属于模板质量改进，不是创建 API 对 Markdown 结构的硬性校验。长度限制来自前端；基本信息标题来自合并接口的实际识别逻辑。

## 验证范围与使用边界

`templates-smoke-test.js` 使用实际合并接口中的头部解析函数，以及实际模块 19964 的人设与头像存储逻辑。文件系统根目录替换为 `tmp/` 临时目录，写入依赖替换为本地文件写入；不触碰真实用户数据。

校验覆盖全部角色的前端长度限制、索引对应关系、头部解析与再次合并、素材路径、头像扩展名及文件签名、人设全文保存与读回、头像复制前后的 SHA-256 一致性。测试先在原模板上确认失败，再对优化版本执行。

所有 63 张原图另用 Pillow 进行格式识别、尺寸读取与完整解码；所有 27 份原始设定材料和 63 张图片通过修改前后的文件哈希核对，保留不变。方形图优先只是选材优化，最终头像构图仍以界面裁剪预览为准。

本次未调用真实模型生成课堂回答，未执行带鉴权的 HTTP 创建请求或实际 UI 保存；因此验证的是模板格式、内容约束与本地存储兼容性，不是所有模型在课堂上的表现保证。背景素材的外部来源未逐条联网复核，本次也不把素材中的所有剧情、引语视为已经独立核实的官方事实。

本报告所述的 27 份新模板只涉及角色素材库，不改运行时 bundle、ASAR、账户、密钥、既有世界和既有伙伴。新模板需要按 README 创建或更新伙伴后使用。用户后续追加并确认的旧账户 26 份模板，另见 [旧版模板优化报告](旧版模板优化报告.md)。
