# 角色库（Socratopia 角色模板素材）

本目录包含 27 个角色的背景材料、63 张原始图片，以及用于 Socratopia「自定义伙伴」的中文人设模板。`模板.md` 是实际使用的人设，`设定.md` 是背景参考，两者用途不同。

## 目录结构

每个角色一个编号子目录，编号从 `001` 开始递增：

```
角色/
├── 001-<角色名>/
│   ├── 模板.md        # 可粘贴到自定义伙伴人设编辑框的完整 Markdown
│   ├── 设定.md        # 背景资料及早期教学风格设想，不直接注入课堂
│   ├── 图片/          # 人物图片（头像、立绘、参考图等）
│   └── 素材/          # 其他相关素材（可选）
├── 002-<角色名>/
├── ...
├── templates-index.json       # 素材编号、基本信息和相对路径
├── templates-smoke-test.js    # 本地校验，不连接模型或写入用户账户
└── 模板检查报告.md
```

## 收录内容约定

- **背景故事**：角色的来历、世界观定位、与教学场景的关系
- **人物设定**：性格、说话风格、口头禅、擅长学科、教学偏好
- **人物图片**：放入 `图片/` 子目录，保留原始文件名，不压缩覆盖原图
- 素材收集完成后，可用于创建 Socratopia 角色模板

## 角色模板（persona）

`模板.md` 的结构统一为：`# 名字` → `## 基本信息` → `---` → 角色速写、说话方式、教学风格、情绪表现、互动规则、对话示例。基本信息中的姓名、性别、身份、性格关键词与索引一致。

`## 基本信息` 必须保留：`merge-persona` 接口用它识别并移除旧头部，再拼入表单里的新基本信息。只有标题和字段列表、没有这一节名时，旧字段会混入正文，造成新旧信息重复。

本批角色的 `age` 均保留为 `null`，模板头部相应省略年龄行。外表年龄、种族寿命、经历的年代不能直接当作明确的数值年龄。人物背景仍可查阅各自的 `设定.md`。010「队长」与 013 艾尔海森为 `male`，其余为 `female`。

## 在项目中使用

当前界面不会自动扫描本目录，也没有直接导入整份 `templates-index.json` 的功能。

1. 在「自定义伙伴」中新建模板，按索引填写姓名、性别、身份和性格关键词，年龄留空。
2. 将对应 `模板.md` 的完整内容粘贴到人设编辑框，包括标题和基本信息。
3. 在头像选择器中选择索引 `avatarSourcePath` 指定的图片，根据预览调整裁剪后保存。
4. 按项目现有流程将保存的伙伴用于世界或课堂。仅修改本素材目录，不会更新已经创建的伙伴或既有世界中的人设副本。

当前前端按 JavaScript 字符串长度限制：姓名 20、身份 60、性格关键词 100、人设全文 1500。保存时可能调用模型合并基本信息；合并后的结果也受 1500 字符限制。模板保留了余量，但模型输出仍应以保存后的实际内容为准。

## 索引与 API 字段

`templates-index.json` 是便于携带的素材清单，**不是可原样 POST 的请求体**。

| 索引字段 | 提交到 `POST /api/custom-companions` 时的处理 |
|---|---|
| `id` | 仅表示素材编号，不提交；项目会生成 `ct_...` 运行时 ID |
| `name`、`gender`、`age`、`identity`、`personality` | 按单个角色原样提交 |
| `personaPath` | 读取 UTF-8 文本，将全文放入请求字段 `persona`；不能只传路径 |
| `avatarSourcePath` | 索引中相对本目录；提交前转成服务端能够读取的绝对文件路径 |

例如在 Windows Node.js 中准备一个角色的请求体（仅构造数据，不发送请求）：

```js
const fs = require('node:fs');
const path = require('node:path');
const libraryRoot = 'E:/huanjing/sogeladi/Socratopia/角色';
const index = JSON.parse(fs.readFileSync(path.join(libraryRoot, 'templates-index.json'), 'utf8'));
const template = index.templates.find(item => item.id === '001');
const { name, gender, age, identity, personality } = template;
const payload = {
  name, gender, age, identity, personality,
  persona: fs.readFileSync(path.resolve(libraryRoot, template.personaPath), 'utf8'),
  avatarSourcePath: path.resolve(libraryRoot, template.avatarSourcePath)
};
```

请求通过项目已有的鉴权上下文发送。Windows 服务端需要 Windows 路径，不能使用 WSL 的 `/mnt/e/...` 路径。图片路径缺失时，现有存储逻辑可能跳过头像复制，因此应先运行本目录校验。

图片索引优先选择现有方形角色图；010 使用实际的 `头像.webp`。部分角色只有长图或横图，属于可用素材，仍需按界面预览裁剪。所有原图保留，不压缩、不覆盖。

## 检查与后续维护

在项目根目录执行：

```bash
node 角色/templates-smoke-test.js
node --check 角色/templates-smoke-test.js
```

若当前 WSL 只有 Windows Node.js，则使用 `node.exe` 替代 `node`。

脚本检查字段与长度、目录覆盖、基本信息合并与再次合并、素材文件路径和头像格式，并调用项目实际存储模块，在 `tmp/` 临时目录中逐个验证人设与头像保存、读取后清理。它不启动应用，不连接模型，也不修改真实账户。

新增模板时同时更新索引，保持模板可独立使用。背景材料中的早期教学设想不等于现行课堂规则；“永不给答案”“无限追问”“角色自行下课”等要求不可带回模板。具体检查依据和本次调整见 [模板检查报告](模板检查报告.md)。

用户另外确认的本地旧账户 26 份人物模板也已作差异化优化，直接写回原数据目录；它们不属于本索引的 27 个素材角色。具体范围、人物特点、验证和备份位置见 [旧版模板优化报告](旧版模板优化报告.md)。
