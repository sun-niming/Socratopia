# 项目整理工作控制说明（Decisions & Scope）

本文件记录**整理工作本身的决策**：范围、分类标准、取舍、命名约定。不是产品事实，产品事实放专题文档。

## 决策记录

### D-001 工作目录选择
- 日期：2026-09-14
- 决定：使用 `docs/project-reconstruction/` 作为统一整理目录，新建。
- 依据：检查时根目录不存在 `docs/`，也不存在等价整理目录（`角色/`、`outputs/`、`tmp/`、`PROJECT_MATH_SPEECH_DOSSIER/` 各管一段，无总入口）。
- 后果：不搬迁、不删除任何既有文档；只在 `docs/project-reconstruction/` 内新建索引与专题。

### D-002 既有文档处置原则
- 决定：旧文档先"标注判断"（有效 / 部分过时 / 重复 / 历史资料 / 待确认），并建立新旧映射；搬迁或删除留到后续批次。
- 依据：用户要求避免破坏原有链接与证据。

### D-003 证据分级用语
统一四档，全文强制使用：
- **已证实**：有直接证据（文件路径+锚点 / 提交哈希 / 命令+输出）。
- **合理推断**：写明依据与不确定性。
- **待确认**：资料不足或存在冲突。
- **重构建议**：未来方案，非历史事实。

### D-004 指令文件冲突处置
- 事实：`AGENTS.md` 声称"`CLAUDE.md` 在本仓库缺失，`AGENTS.md` 是唯一指令文件"，但根目录 `CLAUDE.md` 实际存在（8171 字节，2026-09-11）。用户在任务里也说"先读取并遵守 AGENTS.md"。
- 决定：两者都读，冲突处以**当前代码实测**为准，并把冲突记入 `OPEN-QUESTIONS.md`。不擅自修改 `AGENTS.md`。
- 已发现的具体冲突见 `OPEN-QUESTIONS.md` Q-001 ~ Q-004。

### D-005 敏感信息处理
- `resources/settings.json`、`resources/set.json`、`resources/app.asar` 不提交。
- 整理文档中不粘贴 API key 原文，只写结构；需要时说"端点已配置"而非值。
- 依据：AGENTS.md "Never commit" + 用户约束。

### D-006 分期边界
- 本轮**只读**（外加：新建 `docs/project-reconstruction/` 内文件、以及在 `tools/` 下如需可加分析脚本）。
- 不改业务代码、不删文件、不重打包、不重建运行产物。
- 运行 smoke test 前先确认是否触碰真实 API/用户数据（见各批次记录的"是否安全执行"判断）。

### D-007 时间证据规则
- 文件修改时间**不单独**作为开发时间证据，只作旁证。
- Git 提交时间可作证据，但本仓库 git 历史起点为 2026-06-17（`b7ad6eb Initialize lightweight patch repository`），**不能**代表项目起点。
- 早于 2026-06-17 的历史只能靠文档、产物内嵌信息、`outputs/`、`tmp/` 等间接材料推断，且必须标"合理推断"。

### D-008 不要反向编造创始故事
- 若找不到早期产品材料，就列"已知最早证据 + 待补充问题"，不从当前功能倒推愿景。

### D-009 上下文受限的落盘纪律
- 每批完成后立即更新 `WORKSTATE.md` + `RESUME.md` + 相关专题。
- `RESUME.md` 控制在一千中文字内。

### D-010 【硬前提】无源码仓库 —— 本目录即唯一真源
- 日期：2026-09-14
- 事实（用户确认，Q-002）：**不存在 `socralab-app/v2` 源码仓库的本机副本**。`Socratopia_2.0` 兄弟副本也不存在（Q-001）。
- 据此确立，全文强制：
  1. **不得**在任何结论里写"改源码即可"或"重新构建一下"。
  2. "修改实现"的**全部**合法落点只有三类：手写文件（`resources/server/server.js`、`resources/server/lib/**`）；编译产物（`.next/server/app/api/**/route.js`、`.next/server/chunks/**`、`.next/static/chunks/**`）；Electron 产物（`main.js`/`preload.js` + ASAR 重打包）。
  3. 任何"上游/原始 team 的实现细节"只能从产物反推，**标为合理推断**。
  4. 讨论"本体 vs 分支"边界时，本体一侧**无文档可查**，只能靠产物特征与随包内容判断。
  5. 重构路线里"恢复构建链路"是一个**待验证的选项**（Q-021），不是既有事实；"继续改 bundle"也**不是临时状态**，而是已持续近三个月的现实形态。
- 影响面的具体条目：`PRACTICE_FEATURE_TECHNICAL_PLAN_AND_CLAUDE_PROMPTS.md`（E-116）"不建议作为第一选择"的热修路线实际已是唯一路线；`方案.md`（E-113）、`RENAME.md`（E-080）中"在源仓库实现"的措辞需对齐。
