# 可插拔知识源核收指标

## 1. 核收目标

验证 Socratopia 是否真正具备可插拔知识源能力，并确认 Kimi 只是其中一个可替换 Provider。

核收重点：

- 抽象是否稳定。
- Provider 是否可替换。
- 外部知识是否可追溯。
- Kimi 不可用时主流程是否正常。
- 隐私、安全、缓存、日志是否可控。

## 2. MVP 核收范围

MVP 不要求自动控制 Kimi 客户端。

MVP 必须完成：

- Provider contract。
- Source router。
- Evidence normalizer。
- Trust policy。
- Evidence cache 的最小实现或接口占位。
- Kimi manual provider。
- 至少一个本地 provider。
- smoke test。

MVP 可以暂缓：

- Kimi 客户端自动化。
- Kimi 本地目录深度解析。
- UI 设置页。
- 多 Provider 并发查询。
- 外部 Search / RAG / Database 的真实接入。

## 3. 架构核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| A1 | Provider 可插拔 | 新增 provider 不需要修改教学核心逻辑 |
| A2 | 统一接口 | 所有 provider 都实现 `isAvailable`、`query`、`healthCheck` |
| A3 | 统一返回 | 所有 provider 输出都能转成 evidence package |
| A4 | 本地优先 | 教材内问题默认先查本地教材和本地知识库 |
| A5 | 外部降级 | 外部 provider 超时或失败不影响本地教学回答 |
| A6 | 配置隔离 | provider 开关、模式、超时、优先级可配置 |
| A7 | 无硬编码 Kimi | Router、Verifier、Composer 不出现 Kimi 专属逻辑 |

## 4. Kimi Provider 核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| K1 | 无官方 API 假设 | 代码和文档不假定 Kimi 存在 REST API |
| K2 | manual 模式可用 | 能生成结构化 Kimi 查询 prompt |
| K3 | 输出可解析 | 粘回的 Kimi 输出可转成 answer、claims、sources、uncertainties |
| K4 | 无来源处理 | Kimi 未给出处时标记为 `unknown` 或 `low`，不伪造引用 |
| K5 | 不绑定 Kimi | 关闭 Kimi provider 后其他 provider 仍能工作 |
| K6 | 健康检查 | 能返回 disabled、manual、unavailable、ok 等状态 |
| K7 | 隐私边界 | 默认不读取 Kimi 账号、token、cookie、聊天记录 |

## 5. 证据与可信度核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| E1 | Claim 拆分 | 外部回答能拆成多个 claims |
| E2 | Source 记录 | 每个 source 至少记录 title、url 或 origin、retrievedAt |
| E3 | 可信度标注 | 每条 claim 或 source 至少有 high/medium/low/unknown |
| E4 | 冲突处理 | 外部知识与教材冲突时默认教材优先 |
| E5 | 时间敏感 | 最新事实、软件版本、政策等标记较短缓存期 |
| E6 | 未核验提示 | 无法确认来源时不会被包装成确定事实 |

## 6. 缓存核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| C1 | 缓存对象 | 缓存 evidence package，不缓存不可追溯最终答案 |
| C2 | 缓存 key | key 包含 provider、mode、question hash、context hash |
| C3 | 过期时间 | 不同任务类型可设置不同 ttl |
| C4 | 可禁用 | 用户可关闭外部知识缓存 |
| C5 | 可追踪 | 缓存记录包含 createdAt、retrievedAt、providerId |
| C6 | 不存敏感凭证 | 缓存中不出现 token、cookie、api key |

## 7. 隐私与安全核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| S1 | 授权读取 | 读取 `C:\Users\ASUS\.kimi` 前需要用户明确授权 |
| S2 | 最小读取 | 首次调查只列文件名、大小、修改时间、类型 |
| S3 | 敏感屏蔽 | 日志和错误信息不打印 token、cookie、账号、密钥 |
| S4 | 本地数据边界 | 不默认上传用户教材、笔记、聊天记录到外部 provider |
| S5 | 用户可控 | 用户可以关闭某个 provider 或全部外部知识源 |
| S6 | 可审计 | 每次外部知识查询记录 provider、时间、模式、是否使用缓存 |

## 8. 稳定性核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| R1 | 超时控制 | provider 超过配置时间后返回 timeout，不阻塞主流程 |
| R2 | 错误隔离 | 单个 provider 抛错不会让 API route 崩溃 |
| R3 | 降级回答 | 外部失败时仍能用本地上下文生成回答 |
| R4 | 可观测 | 日志包含 providerId、mode、status、latencyMs |
| R5 | 重试限制 | 自动重试有次数上限，避免无限请求 |
| R6 | 离线可用 | 没有网络或 Kimi 不可用时，本地功能可继续使用 |

## 9. 扩展性核收指标

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| X1 | 接入 Search | 新增 search provider 不需要修改 Kimi provider |
| X2 | 接入 RAG | 新增 rag provider 只需实现 provider contract |
| X3 | 接入数据库 | database provider 可返回同样 evidence package |
| X4 | 多源合并 | Router 能接收多个 provider 的结果并排序 |
| X5 | Provider 能力声明 | Router 按 capabilities 选择 provider |
| X6 | 课程级配置 | 后续可按课程启用不同 provider |

## 10. 测试核收指标

必须新增或通过以下测试：

```text
node --check resources/server/lib/knowledge/provider-contract.js
node --check resources/server/lib/knowledge/source-router.js
node --check resources/server/lib/knowledge/evidence-normalizer.js
node --check resources/server/lib/knowledge/trust-policy.js
node resources/server/lib/knowledge/smoke-test.js
```

如仅提交文档，不要求上述代码测试通过，但实现阶段必须满足。

smoke test 至少覆盖：

- Kimi provider disabled。
- Kimi provider manual prompt generation。
- 本地 provider 返回证据包。
- Router local-first 策略。
- Provider timeout 降级。
- Evidence normalizer 处理无来源回答。
- Trust policy 标记 unknown 来源。

## 11. 产品体验核收指标

后续 UI 产品化时应满足：

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| U1 | 外部知识开关 | 用户可在设置中启用或关闭外部知识源 |
| U2 | Provider 状态 | 用户可看到 Kimi/Search/RAG/Database 是否可用 |
| U3 | 来源可见 | 教学回答可查看外部资料来源 |
| U4 | 不打断学习 | 外部知识慢时不阻塞基础教学流程 |
| U5 | 明确提示 | 使用外部未核验资料时给出清晰提示 |
| U6 | 手动模式可理解 | manual Kimi 模式有清楚的复制、粘贴和解析流程 |

## 12. Kimi 目录调查核收指标

当用户授权读取 `C:\Users\ASUS\.kimi` 时，调查结果应满足：

| 编号 | 指标 | 通过标准 |
| --- | --- | --- |
| D1 | 只读操作 | 不修改、不删除、不移动 Kimi 文件 |
| D2 | 目录清单 | 输出文件名、大小、修改时间、可能类型 |
| D3 | 敏感规避 | 默认跳过疑似 token、cookie、account、session 文件内容 |
| D4 | 格式识别 | 判断是否存在 SQLite、LevelDB、JSON、日志、缓存 |
| D5 | 兼容建议 | 输出可行接入路径和不可依赖项 |
| D6 | 不承诺稳定 | 明确私有客户端数据结构可能随版本改变 |

## 13. 最终交付核收

当完整能力完成时，应能演示以下流程：

1. 用户在 Socratopia 中提出一个教材外扩展问题。
2. Router 先检查本地教材和本地知识库。
3. 本地不足时调用启用的外部 provider。
4. Kimi manual 或 bridge provider 返回候选证据。
5. Evidence normalizer 生成 claims 和 sources。
6. Trust policy 标注可信度和未知来源。
7. Composer 生成教学回答，并保留来源追踪。
8. 关闭 Kimi provider 后，同一流程仍能通过其他 provider 或本地降级完成。

若以上流程可重复、可观察、可配置，则认为可插拔知识源能力通过核收。
