# 此对话上下文

## 1. 用户意图

用户希望把 Kimi 作为 Socratopia 正在开发的软件的知识库外设，而不是作为 Codex 的临时搜索外设。

更准确的目标是：

- 将 Kimi 做成 Socratopia 的一个可插拔知识源。
- 后期方便接入其他 RAG、Search、数据库、机构知识库等。
- Kimi 只是当前优先兼容的一个 Provider，不应成为不可替换的核心依赖。

## 2. 已澄清的概念

最初讨论中提到“把 Kimi 作为联网搜索的外设”，之后用户明确：

- 不是让 Codex 临时调用 Kimi。
- 是让 Socratopia 软件本身具备调用外部知识源的能力。
- Kimi 是其中一个外部知识源。
- 该能力应服务于知识准确、拓展和核验。

因此推荐术语是：

- 可插拔知识源
- Knowledge Source Provider
- External Knowledge Connector
- 联网知识外设

不推荐把 Kimi 称为 Socratopia 的“数据库”，因为 Kimi 不是可直接控制和迁移的数据仓库。

## 3. 关于 Kimi 的当前信息

用户补充：

- 当前 Kimi 没有官方 API。
- 用户拥有 Kimi 会员。
- 当前只有 Kimi 客户端。
- 用户可以提供 Kimi 的目录供检查。
- 已提供本地数据目录：`C:\Users\ASUS\.kimi`。
- 用户可能并不一直使用 Kimi 作为知识来源。

这意味着：

- Kimi Provider 不能按标准 REST API client 设计。
- 需要兼容客户端、本地目录、可能的 Kimi Web 或人工桥接方式。
- 不能依赖 Kimi 的私有本地数据结构作为长期接口。
- 不能将 Kimi 作为唯一事实来源或唯一外部知识源。

## 5. 设计决策

本次对话形成的关键决策：

1. Kimi 是 Provider，不是核心数据库。
2. 本地教材和本地知识库优先。
3. 外部知识结果必须转成统一证据包。
4. 外部知识需要可信度、来源、时间和冲突标记。
5. Provider 不可用时，Socratopia 主流程不能崩溃。
6. Kimi 需要兼容，但不应成为架构中心。
7. 先做抽象和手动模式，再考虑自动桥接客户端。
8. 读取 `C:\Users\ASUS\.kimi` 前应明确只读范围和隐私边界。

## 6. 推荐实现路线

第一步不直接接 Kimi 客户端，而是先实现抽象层：

```text
provider-contract
source-router
evidence-normalizer
evidence-cache
trust-policy
```

然后实现 Kimi 的 `manual` 模式：

```text
Socratopia 生成结构化 Kimi 查询 prompt
  -> 用户或桥接器提交给 Kimi
  -> 取回 Kimi 输出
  -> normalizer 转成 evidence package
  -> verifier 标注可信度
  -> composer 决定是否进入教学回答
```

再逐步增加：

- Kimi 客户端目录只读探测。
- Kimi Web / 客户端自动桥接。
- Search Provider。
- RAG Provider。
- Database Provider。

## 7. 待确认问题

后续进入实现前，建议确认：

1. 是否允许只读扫描 `C:\Users\ASUS\.kimi` 的目录结构。
2. 是否允许读取其中的配置文件或数据库文件头信息。
3. 是否禁止读取聊天记录、账号、token、cookie 等敏感信息。
4. Kimi 自动桥接优先走客户端还是 Kimi Web。
5. 外部知识源是否需要在 UI 中展示来源和可信度。
6. 教学回答中是否要默认标注“外部资料参与”。
7. 是否需要用户为不同课程配置不同知识源。

## 8. 当前不需要的额外信息

当前为了写计划书和验收指标，不需要更多 Kimi 信息。

进入 Phase 2 兼容性调查时，可能需要：

- Kimi 客户端安装路径。
- Kimi 客户端版本号。
- 是否已登录会员账号。
- 是否允许打开 Kimi 客户端或 Kimi Web。
- 是否允许只读列出 `C:\Users\ASUS\.kimi` 下的文件名、大小、修改时间。
- 如存在 SQLite、LevelDB、JSON、日志文件，是否允许检查文件头和字段名。

默认不需要、也不应请求：

- Kimi 账号密码。
- 浏览器 cookie。
- token、密钥、会话凭证。
- 完整聊天记录。
- 与当前功能无关的私人文件内容。
