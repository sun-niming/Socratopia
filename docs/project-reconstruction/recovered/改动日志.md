# 改动日志

## 2026-06-29 — 知识源模块超时控制

### 背景

验收 Phase 1 知识源模块时发现核收指标 **R1（超时控制）** 未实现：`provider-contract.js` 已定义 `constraints.maxLatencyMs` 字段（默认 45000ms），但 `source-router.js` 的 `queryProvider` 未对 provider 调用设置超时兜底，provider 可能无限阻塞主流程。

### 改动文件

`resources/server/lib/knowledge/source-router.js`

### 改动内容

1. **新增 `timeoutPromise` 辅助函数**—— 基于 `setTimeout` + Promise reject 实现，超时后抛出带 provider 标识的消息。
2. **`queryProvider` 加入 `Promise.race` 超时**—— 将 `provider.query(request, ctx)` 与超时 Promise 竞速，超时时间优先取 `request.constraints.maxLatencyMs`，缺省 45000ms。
3. **错误分支区分超时/普通错误**—— catch 中检测 `"timed out"` 关键词，超时返回 `status: "timeout"` 而非 `"error"`。
4. **新增 `logAndReturn` 辅助函数**—— 每次 queryProvider 返回前输出结构化日志 `provider=<id> mode=<mode> status=<status> latencyMs=<ms>`，满足核收指标 R4（可观测）。

### 验证结果

- `node --check resources/server/lib/knowledge/source-router.js` 语法通过
- `node resources/server/lib/knowledge/smoke-test.js` — **39/39 通过**（新增日志行正常输出）
- 回归验证：`node --check` 通过全部 8 个知识源模块

## 2026-06-29 — 知识源 Phase 1 遗留缺陷修补

### 背景

核收报告指出三个代码级缺项：C4（缓存不可禁用）、R5（无重试机制）、A6（无外部配置入口）。smoke test 也未覆盖 timeout/retry/disable 场景。

### 改动文件

| File | Changes |
|------|---------|
| `resources/server/lib/knowledge/evidence-cache.js` | 新增 `setEnabled`/`isEnabled`，`get`/`set` 入口处检查 |
| `resources/server/lib/knowledge/source-router.js` | 新增 `configure()` 和 retry 循环，`query()` 过滤 `disabledProviders` |
| `resources/server/lib/knowledge/smoke-test.js` | 新增 7 个测试用例（46 tests total） |

### 改动内容

**C4 — evidence-cache.js**
- 新增模块级 `enabled` 标志（默认 `true`）
- 导出 `setEnabled(v)` / `isEnabled()`
- `get()` 和 `set()` 入口处 `if (!enabled) return null / return`

**A6 — source-router.js configure()**
- 新增 `config` 对象：`defaultMaxLatencyMs`, `maxRetries`, `disabledProviders`
- 新增 `configure(opts)` 方法用于外部注入配置
- `configure` 中 `disableCache: true` 调用 `cache.setEnabled(false)`
- `query()` 中 `route.filter(id => !disabledProviders[id])` 过滤已禁用 provider

**R5 — source-router.js retry loop**
- `queryProvider` 改为 for 循环：`maxAttempts = 1 + config.maxRetries`
- catch 检测 timeout，`attempt < maxAttempts` 时 `sleep(500ms * 2^(attempt-1))` 后退避重试
- 全部尝试耗尽后返回 timeout/error（不抛出）
- 每次重试输出结构化日志

### 新增 smoke test（7 cases, 46 total）

| 测试 | 覆盖 |
|------|------|
| cache disabled: setEnabled(false) blocks get/set | C4 |
| cache re-enabled: setEnabled(true) restores normal behavior | C4 |
| disabledProviders config filtered in query() | A6 |
| configure() accepts and propagates all opts | A6 |
| timeout via queryProvider returns timeout status | R1 |
| retry exhausts on persistent timeout | R5 |
| retry succeeds on second attempt (verifies backoff + retry logic) | R5 |

### 验证结果

## 2026-08-06 — `/Close_Reading` PDF 独立精读 Skill（P1）

### 需求与边界

依据《Socratopia `/Close_Reading` PDF 精读 Skill 需求文档》新增按需 PDF 精读链路。功能与 P0 知识卡片、课堂 Prompt、教材窗口推进和学习进度隔离；普通课堂消息不进入精读链路。

### 用户可见行为

- 支持 `/Close_Reading`、`/close_reading`、`/精读`，以及同时具备页码/当前页与明确精读动作的强匹配自然语言。
- 支持页码、跨页范围、目标关键词、翻译/解释/逐行分析/摘录/对照、`maxPages` 和明确记忆意图。
- 参数缺失时按“指令页码 → 当前教材页/会话阅读页 → 最近 4 条用户消息”补齐；仍无页码时只询问 PDF 物理页码。
- 独立 `read_textbook_excerpt` 固定工作流先读取目标页；仅在关键词未命中或完整内容未闭合时补读邻页，默认上限 3 页、硬上限 5 页。
- 文字层为空、退化或视觉页中关键词未命中时，按需将页面渲染为 PNG，并使用 `set.json.vision` 配置做逐字视觉转录；视觉来源明确标记为 `vision-transcription`。
- 证据经过 UTF-8、BOM、NUL、控制字符、Unicode NFC、替换字符和私用区字符检查；保留代码与数学符号，不做全角/半角或 ASCII 近似替换。
- 回答仅使用本次 `PDF_EVIDENCE` 和 Skill 局部 Prompt，不写入普通课堂常驻 Prompt。

### 功能开关

- 配置：`closeReading.enabled=false`；亦可用环境变量 `SOCRATOPIA_CLOSE_READING=false` 紧急停用。
- 默认启用。关闭时不执行自然语言路由、不读取 PDF、不调用视觉/回答模型、不创建记忆候选；显式命令只返回功能已关闭提示，普通课堂继续原链路。

### 记忆与下课流程

- 未明确要求记忆时，最近精读结论仅保存在进程内存，不落盘；原始页级证据不会写入教材窗口或知识库。
- “记住这次精读”“保存到课后笔记”等明确意图才会生成 `conversations/<conversationId>/close_reading_candidates.json` 候选。
- 候选仅包含结论、受限短摘、PDF 页码、来源类型和视觉误差标记，并按内容去重、最多保留 20 条。
- 点击“下课并保存记忆”时，候选注入既有课后更新请求，要求写入既有日记/记忆输出，同时明确禁止改变 `PROGRESS_MD` 页码或已学范围。
