## 2. 高危发现

### V-01 渲染进程 XSS 入口：选段朗读面板与主聊天页共用 `allowDangerousHtml` 管线

**位置**

- `resources/server/public/selection-dock.js:1773` — `.use(mods[5], { allowDangerousHtml: true })`
- `resources/server/public/selection-dock.js:1775` — `.use(mods[7], { allowDangerousHtml: true })`
- `resources/server/public/selection-dock.js:1880` — `target.innerHTML = out;`
- 主聊天页同一模式：`resources/server/.next/static/chunks/app/page-87daa6ca210ab9dc.js`（`.use(s,{allowDangerousHtml:!0}).use(l,{detect:!0}).use(o,{allowDangerousHtml:!0})`，另有 2 处 `dangerouslySetInnerHTML`）

**渲染链（逐段确认）**

```
remark-parse(9978→模块 2948)
  → remark-attention(模块 1650)
  → remark-gfm(6933→模块 9204)
  → remark-rehype(7564→模块 3093)   { allowDangerousHtml: true }   ← 原始 HTML 直通
  → rehype-katex(804→模块 1648)
  → rehype-stringify(8740)          { allowDangerousHtml: true }   ← 还原成字符串
  → target.innerHTML = out                                            ← 落 DOM
```

全仓库**没有** `rehype-raw` / `hast-util-raw` / `parse5`（grep 命中 0），也就是说**没有任何 sanitizer**；`allowDangerousHtml` 两侧都开着，markdown 里的原始 HTML 会被逐字塞进 `innerHTML`。

**触发路径**

1. 十月新增的选段朗读面板把「模型回答」逐 chunk 渲染：`renderMarkdown(panelState.answerText, answer)` 每收到一个 SSE 分片就重跑一次 `innerHTML` ⇒ 注入点在流式过程中即可生效，无需等回答结束。
2. 输入侧两类：模型回答本身（可被提示注入影响）、教材原文/选段内容（`/api/textbook?locate=1` 与页文本）。
3. `<img src=x onerror="…">`、`<svg onload="…">` 这类载荷在 `remark-rehype` 阶段不会被当作文本，会原样进入 `innerHTML` 并执行。

**为什么这条是「十月的事」而不只是历史遗留**

- 仓库里含 `allowDangerousHtml` 的文件共 7 个：`6626-94bd6b870272b92e.js`、`8740.6efc03683701d1dc.js`、`app/page-3a1fef7566e26c43.js`、`app/page-87daa6ca210ab9dc.js`、`app/page-practice-ui-20260622.js`、`app/page-practice-ui-20260625-jyfix.js`、`app/page-practice-ui-20260626-postclass-notes.js` ⇒ **系统性问题，先于十月**。
- 但十月把它复制到了 `resources/server/public/selection-dock.js`（10-23 起未提交，+760 行）这个**新界面**上，而这个新界面专门消费「教材原文 + 模型长回答」，并且在 `resources/server/.next/server/app/index.html` 挂载为 `<script src="/selection-dock.js?v=20261021-52" defer>` ⇒ 攻击面比旧界面更大。
- 值得肯定的一点：`selection-dock.js` 除 markdown 这一处外，全程用 `textContent`（约 45 处）与 `escapeHtml`（`:1698`），SVG 围栏渲染成 data-URI `<img>`（`svgFigure`，约 `:1708`）⇒ SVG 里的脚本不会执行。**唯一的破口就是 markdown 管线这一处。**

**影响**

见 V-02（渲染进程拿到的是带特权的能力面）。

**修复方向**

1. **管线级**：在 `remark-rehype` 之前插入 `rehype-sanitize`（白名单：p/strong/em/code/pre/img/a/h1-h6/ul/ol/li/table…，禁止 `on*` 属性与 `javascript:`）；若不便加依赖，则在 `remark-parse` 阶段用自定义 micromark 扩展把原始 HTML 节点降级为文本。
2. **去参数**：把 `allowDangerousHtml: true` 去掉后，raw HTML 会走 `remark-rehype` 的默认转义路径，行为立刻变安全；这属于**改动最小、收益最大**的一步，代价是失去 raw HTML 能力（当前内容里其实没有依赖 raw HTML 的排版）。
3. **CSP 兜底**：`main.js` / `resources/server/server.js` / `.next/server/app/index.html` 中 `Content-Security-Policy` 命中数均为 **0**。应给渲染层加：`default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; script-src 'self'`，让注入的脚本/事件属性即便漏进来也难落地。
4. **测试**：新增冒烟测试，断言渲染产物中不含 `onerror=`、`javascript:`、`<script`；并对 `selection-dock.js` 与主聊天页 chunk 各做一条。

**能力签发不会被同页注入脚本挡住**：`main.js:35153-35172 issueAdaptiveCapability` 依次校验

1. `event.sender !== mainWindow.webContents` → 注入脚本在主窗口里，通过；
2. `event.senderFrame !== event.sender.mainFrame` → 注入脚本在主 frame，通过；
3. origin 必须是 `http:` + loopback + 端口等于本地服务端口 → 页面 origin 本身就满足。

⇒ 三重校验防的是「别的窗口/别的 origin 来要令牌」，**防不住同页脚本注入**。

**已被削弱的点（要写清楚，别误判）**：`main.js:34557-34558`

```js
ipcMain4.handle("store:getApiKey", async (_e, provider) => {
  if (true) return "";
```

`store:setApiKey` 同样在 `:34572-34573` 被 `if (true) return;` 短路 ⇒ **本构建里 API key 的读取与写入是关闭的**（像是发布前的开关）。所以今天的真实影响是「会话令牌 + 能力令牌 + 截屏 + 写文件」，**不是**「直接拿到模型 key」。但只要有人为了恢复配置功能去掉这个 `if (true)`，V-01 的影响会立刻升级到最高档。

**修复方向**

1. 按 V-01 修掉注入源头（治本）。
2. `exportPdf` / `captureScreen` 这类原生能力改为**需要一次真实用户手势**（例如 main 侧记录最近一次鼠标事件的时间戳，IPC 携带一个只有 UI 能算出的 nonce），而不是「渲染层说调用就调用」。
3. `getCapability` 收窄为「按用途签发」（读会话的令牌不能调聊天），并给能力令牌加短 TTL + 单次使用。
4. 给 `main.js` / `server.js` / `index.html` 加 CSP（当前 0 命中）。
5. 在 `preload.js` 里补一句注释，说明 `getApiKey` 被硬关的原因与恢复条件（现在 `if (true)` 没有解释，容易被后人当成手滑删掉）。

## 3. 中危发现

### V-03 资产层 SVG 校验两套标准，且响应头无加固

- `resources/server/lib/assets/store.js:194-216 validateSvg`：切掉 SVG 根节点前后的散文、注入 `xmlns`、判 512 KB 上限；**不拦 `<script>`、不拦 `on*` 事件属性**；且当正文里**没有** `</svg>` 时（`close < 0`）整段原文原样保留。
- `resources/server/lib/assets/intents.js validateSvgSource`：同一职责，但**有** `<script[\s>]` 拒绝 ⇒ 两套标准，同一资产从不同入口进来得到的清洗程度不同。
- `resources/server/lib/assets/http.js:272-293 handleFile`：按 `file.contentType` 直出字节，SVG 即 `image/svg+xml`（`store.js:644,656`），响应头只有 `Cache-Control: private, max-age=31536000, immutable`，**没有 CSP、没有 `X-Content-Type-Options: nosniff`、没有 `Content-Disposition: attachment`**。

风险路径：SVG 若能被诱导成「以 `image/svg+xml` 直接导航打开」，则其中的脚本会在应用的 origin 下执行（这是 SVG 相对 PNG 的固有差别，而本仓库的资产锚点 `asset://` 正是让 SVG 可被直接打开的机制）。

**修复方向**：统一到 `intents.js` 的严格档（拦 `<script>`、`on*`、`javascript:`、`xlink:href` 外部协议）；`validateSvg` 找不到 `</svg>` 时直接判非法而不是整段保留；`handleFile` 对 SVG 加 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`、`X-Content-Type-Options: nosniff`，或干脆对 SVG 强制 `Content-Disposition: attachment`。

### V-04 `GET /api/assets?audit=1&repair=1` 用 GET 改磁盘状态

`resources/server/lib/assets/http.js` 的 `handleList` 暴露 `audit` 与 `repair` 两个参数，`repair=1` 会触发索引修复（写 `index.jsonl`）。GET 语义上应当无副作用，副作用 GET 会被预取器、爬虫、浏览器扩展意外触发，也绕过「只读接口可以放心缓存」的假设。

**修复方向**：`repair` 改为 `POST /api/assets/repair`（带能力令牌与账号域校验），`audit` 可保留为只读。

### V-05 鉴权契约测试把最敏感的两个端点排除在断言之外

`resources/server/sensitive-api-auth-contract-smoke-test.js`（104 行）列出 24 条路由断言 fail-closed，运行时打印：

```
SKIP async route module chat
SKIP async route module groupchat
```

**修复方向**：对异步路由改用 `routeModule.handle`/Next 包装层探测，或直接接入 `resources/server/smoke-test-utils.js` 的 `TestEnvironment` 做活探针（本次审计用的 `tmp/audit-live-auth-probe.js` 就是这个形态，可直接产品化为 `*-smoke-test.js`）。

### V-06 新增的整本 PDF 冷提取面

未提交的 `resources/server/lib/textbook-text-index.js`（425 行）在命中时会把**整本教材**逐页 `getTextContent()` 提取并缓存。实测（真实教材 144 页 / 8.8 MB）：

- `extractPages` 冷启动 **2079 ms**；热查 6–9 ms；单本缓存约 0.1 MB；`CACHE_LIMIT = 6`。

`/api/textbook?locate=1` **已被能力令牌保护**（活探针实测无令牌 401 `auth_missing`，与文档 E-405 一致），所以这不是匿名 DoS，而是「已登录用户可用大量 `textbookId` 反复触发冷提取」的**放大面**。成本随页数线性增长，且缓存按 book 维度、上限 6 本。

**修复方向**：把冷提取改为「按页惰性 + 结果落盘缓存」（页级缓存文件），或给同一账号的冷提取加并发闸与冷却；`MAX_QUOTE_CHARS = 400` 与 LCS 的 O(quote×page) 已实测无风险，可保留。

## 4. 低危与观察项

### V-08（低）绝对路径回传

`resources/server/.next/server/app/api/textbook/route.js` 的 `_textbookLocate` 响应体含 `sourcePdf: h`（服务端 PDF 绝对路径，如 `C:\Users\ASUS\AppData\Roaming\socratopia\project-data\...`）。该路由受能力令牌与账号域校验，因此只有账号主人看得到自己的路径，危害限于「暴露本机目录结构」。**修复方向**：改成只回相对 id 或书名。

### V-09（低）OCR 散框判定带

`resources/server/lib/ocr/ocr-quality.js`（提交 `9563592`）新增 `strayBoxSuspect = strayBoxes / Math.max(1,length) >= 0.02 ? strayBoxes : 0`，并把 `boxedCharacters` 计入 `suspicious`；判定乱码的条件是 `replacement>=2 || controls>=2 || boxedCharacters>0 || mojibake>0 || repetitive`。注释声称「dense scatter 仍会被拦」，但**密度落在 2%–5% 区间的散框页不再被判乱码**。原始故障（KUyw 教材把例题末的方框渲染成 U+25A1，p.182/185 各 2 个散框导致整页被判乱码 → 阅读窗口卡在 p.181 → 连续 3 轮 `advance_pdf_range_unavailable`）确已修复，但新规则留了一个窄带。

### V-10（低）提交信息与内容不符

`b268e51`「Add repository README; harden SVG validation namespace」的实际改动是：`intents.js` +11、`store.js` +5、`selection-dock.js` +6 的 `xmlns` 自动注入。**没有做任何净化**（不拦 `<script>`、不拦事件属性）。「harden」一词会让人误以为已经处理过 XSS。**修复方向**：在 V-03 真正修掉后，把结论写进 `IMAGE_ASSET_LAYER_T13_COMPLETION_REPORT.md` 的对应小节。

### V-11（低）硬开关没有注释

`main.js:34557-34558`（`getApiKey`）与 `:34572-34573`（`setApiKey`）里的 `if (true) return ""` / `if (true) return;` 让 API key 存取永久短路，但代码里没有任何说明为何如此、如何恢复。这是**可用性风险**（配置功能事实上不可用）兼**安全幻觉**（审计时容易把这段死代码当成「已加固」）。

### V-12（低）仓库根即工作目录

`outputs/` 已被 `.gitignore` 覆盖（`git check-ignore -v` 实测），个人求职材料（简历、投递清单、大头照）当前**没有**进版本库，`.gitignore` 亦覆盖 `resources/settings*.json`、`resources/set*.json`、`win-unpacked/resources/{settings,set}.json`。风险在于结构：仓库根目录同时是「发布运行时」和「个人工作区」，`win-unpacked/` 快照里带着需要手工回填的 `set.json`（含 live key），任何整目录复制/打包都可能把它带出去。

### V-13（观察）图层 640 行休眠

`assets.boxMode="off"` 兜着几何裁图机器（`locate-figure.js`、`figure-box.js`、`figure-ink.js`、`page-lines.js`，约 640 行）整体休眠 —— 这是十月 10-12 一天内三次价值翻转后的沉淀（详见月度清单 §0 路线要点 1）。不是漏洞，是**沉没成本**：需要一次明确判定（复活 or 删除），否则会以「看起来在用」的形式长期存在。

### V-14（观察）未收口的工作区

10-23 起 12 项改动（+940/−125）无验收记录，其中 `resources/server/lib/textbook-text-index.js`（425 行）与配套冒烟测试（250 行）**未跟踪**——历史里没有，备份里没有，只有工作区有。
