## 1. 原因 A：换路由不写 effort ⇒ MiniMax 400

### 1.1 代码链路

1. `dsh-subagent/lib/index.js:450`
   ```js
   if ((resolved.provider !== parentProvider || resolved.model !== parentModel)
       && requested?.reasoningEffort === void 0) delete resolved.reasoningEffort;
   ```
   注释写得很清楚：*"Changing the route without naming an effort clears the parent's route-owned
   effort so the selected model resolves its own default."*——**换路由且不点名 effort ⇒ effort 被删掉**。
2. `dsh-tool-subagent/lib/index.js:122`（`preflightChildLlmRoute`）同规则：
   ```js
   const reasoningEffort = requested?.reasoningEffort
       ?? (inheritParentReasoningEffort && !routeChanged ? parentOptions.reasoningEffort : void 0);
   ```
3. pi-ai 的 `streamSimple`（`@earendil-works/pi-ai/dist/api/anthropic-messages.js:668`）在没有 reasoning 时置
   `thinkingEnabled: false`，并在 `:902` 发出
   `params.thinking = { type: "disabled" }`（`thinkingLevelMap.off` 为 `null` 时该分支生效）。
4. MiniMax 的 Anthropic 兼容端点（`https://api.minimaxi.com/anthropic/v1/messages`）直接拒绝：

   ```json
   {"type":"error","error":{"type":"invalid_request_error","message":
    "invalid params, model \"MiniMax-M3.1-Flash\" requires adaptive thinking;
     thinking.type=\"disabled\" (including reasoning.effort=none) is not allowed (2013)"}}
   ```

5. 子代理第一轮以 `stopReason: error` 结束 ⇒ `settlementSummary(childId, stopReason)`
   （`dsh-subagent/lib/index.js` 约 613 行）把 `error` 映射成 **"failed before it finished."**。

### 1.2 直接复现（`tmp/probe-mn-thinking.js`）

| `thinking` 载荷 | 状态 | 耗时 |
|---|---|---|
| 缺省（不传该字段） | **200** | 1 689 ms |
| `{type:"enabled",budget_tokens:1024}` | **200** | 1 124 ms |
| `{type:"adaptive"} | **200** | 1 163 ms |
| `{type:"disabled"}` | **400**（2013） | 228 ms |

也就是说：**MiniMax M3 系列必须开着 thinking**，"关掉思考"不是合法请求。

## 3. 为什么报错这么难懂

- 工具层只回一句 `Error: subagent run failed`，**上游的 400/403 正文不会传给调用方**。
- `C:\Users\ASUS\AppData\Roaming\dsh-tauri\logs\desktop.log` 与 `logs/tauri/dsh-web.log` 里**没有任何
  "subagent" 字样**；子会话事件文件 `sessions/--E-huanjing-sogeladi-Socratopia--/<childId>/session.v4.jsonl.zstd`
  解压后只有 289 字节头部，真正的事件在投影存储里。
- 唯一可靠的指纹在
  `C:\Users\ASUS\.dsh\storages\session_projcache\sessions\<childId>.json`：
  `subagentTiming.settledMs ≈ 400–800`、`lastTurnCompleted:false`、
  `sessionStats.steps = 1`、`tokenUsage.totals` 全 0、`modelSelection.lastUsed` 里**没有** `reasoningEffort` 字段。
  ⇒ **"秒死 + 0 token + 无 effort" = 请求被上游当场拒绝**，而不是模型不会干活。

## 4. 照做就行：子代理调用规则

1. **换路由一定要点名 `reasoning_effort`**：`low` / `medium` / `high` / `max` 任选其一。
   - MiniMax M3 系列 **永远不要用 `off`**（`off` ⇒ `thinking disabled` ⇒ 400）。
   - `MiniMax-M2.7` 只声明了 `off/low/medium/high`（没有 `max`）⇒ 用 `high`。
2. **最省心的写法**：不传 `provider` / `model`，让子代理继承当前会话路由与 effort（已验证 ✅）。
3. **暂时别用 `x/DeepSeek-V4.1-Flash`**：等网关恢复（`deepseek.nwafu.edu.cn` 现在整站 403）。
4. **可靠的替代**：`kimi-coding/k3-256k`（不是推理模型 ⇒ 不发 thinking ⇒ 天然不踩这个坑）、
   `deepseek-official/deepseek-flash`、`tu/*`。
5. 一次只发一个子代理（虽然并发本身没有被证明是原因，但串行更容易看清是哪一路炸了）。
