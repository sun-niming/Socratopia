# 共享世界、原著知识与角色连续性方案

状态：设计完成，尚未开始运行时代码实现。  
基线日期：2026-09-15。  
阶段备份：[00-stage-backup.md](00-stage-backup.md)。  
开发注意力锚点：[WORKSTATE.md](WORKSTATE.md)。

## 愿景

在 Socratopia 中创建翁法罗斯和提瓦特，使玩家与角色共同生活在一套可追溯、可持续演化的世界状态里。角色既保留原著身份、口吻、关系和知识边界，也能记住与玩家及其他角色实际共同经历的事情。角色不会因为共用一个模型而全知，不会因为知识库存在就把所有资料机械复述，也不会因长期使用而逐渐脱离原著。

## 方案结论

本方案采用三层结构：

1. **常驻模板**：`story.md` 与 `npc_*.md`，稳定世界前提、角色身份、性格、语气和原著关系基线。
2. **世界知识库**：保存较长的原著历史、地点、组织、人物经历和文献，按当前角色、时间点、地点及问题检索。
3. **动态世界状态**：保存角色位置、活动、关系、在场情况、共享事件及见证范围，使一次互动能影响之后的个人对话和群聊。

任何一层都不能代替另外两层。教材知识库继续服务教学内容；世界知识库是独立命名空间，不能把世界资料伪装成教材。

## 权威顺序

发生冲突时按以下顺序处理：

1. 用户在当前会话中的最新明确要求；
2. 项目根目录 `AGENTS.md` 和 `CLAUDE.md`；
3. 本目录的架构与约束文件；
4. `WORKSTATE.md` 中当前已确认的执行状态；
5. 历史记录、旧计划和代码注释。

`WORKSTATE.md` 是注意力锚点，不得覆盖更高优先级指令。开发模型发现它与代码、用户要求或验证结果不一致时，必须先把差异写入 `WORKSTATE.md`，再继续修改代码。

## 本次设计不包含

- 不在本阶段直接修改运行时代码。
- 不立即扩展固定的四个伙伴槽位。
- 不引入外部向量数据库、常驻后台服务或新的云端依赖。
- 不自动把下载资料写入用户账户世界。
- 不允许后台自行生成未经玩家参与的永久世界事实。

第一版先证明：同一个已发生事件能被正确的角色记住、被未见证者保持未知，并在一对一对话和群聊中得到一致表现。达到这个验收点后，再评估动态场景 NPC 和更大角色规模。
