# Socratopia 可插拔知识源计划书

## 1. 目标

把 Kimi 做成 Socratopia 的一个可插拔外部知识源，同时为后续接入其他 RAG、Search、数据库、机构知识库、网页检索服务预留统一接口。

本计划不把 Kimi 视为 Socratopia 的核心知识库，也不把任何单一外部服务视为最终事实源。Kimi 的定位是：

- 外部知识扩展器：补充教材和本地知识库之外的背景、例子、相关概念。
- 联网核验助手：对模型生成内容、教材外事实、较新知识进行二次核验。
- 候选证据来源：提供资料线索、关键词、可能来源，但需要 Socratopia 继续做证据包装和可信度判断。
- 可替换 Provider：后续可被官方 API、搜索引擎、本地 RAG、数据库或其他知识源替换。

## 2. 背景与约束

当前仓库是 Socratopia 的 Windows 打包产物，不是原始 TypeScript/React 源码树。适合直接编辑的位置主要是：

- `resources/server/lib/`：后端公共能力。
- `resources/server/.next/server/app/api/`：编译后的 API route bundle。
- `resources/server/server.js`：独立 Next.js server bootstrap。
- `tools/`：补丁和路由生成工具。

已知事实：

- Kimi 当前没有官方 API。
- 用户拥有 Kimi 会员。
- 当前可用信息是 Kimi 客户端本地数据目录：`C:\Users\ASUS\.kimi`。
- 后续可能不继续使用 Kimi，因此架构必须兼容 Kimi，但不能绑定 Kimi。

设计约束：

- 本地教材、课堂上下文、用户当前学习进度优先。
- 外部知识源只能作为可追溯的补充证据或候选证据。
- 不能把 Kimi 输出直接写死进教学逻辑。
- 涉及本地客户端数据、浏览器登录态、用户隐私时必须显式授权。
- Provider 失败不能导致主教学流程不可用。

## 3. 总体架构

建议新增一个知识源编排层：

```text
Teaching / Practice / Resume / Reasoning
  -> Knowledge Source Router
    -> Local Textbook Provider
    -> Local Knowledge Base Provider
    -> Kimi Client Provider
    -> Web Search Provider
    -> RAG Provider
    -> Database Provider
  -> Evidence Normalizer
  -> Evidence Cache
  -> Trust Policy / Verifier
  -> Final Answer Composer
```

核心原则：

- Router 负责决定问谁。
- Provider 负责拿候选知识。
- Normalizer 负责统一格式。
- Verifier 负责标注可信度、冲突和缺口。
- Composer 负责把可用证据合并进教学、练习、复习或推理流程。

## 4. 推荐目录结构

## 5. Provider 统一接口

所有知识源都实现同一个最小接口：

```js
{
  id: "kimi-client",
  label: "Kimi Client",
  kind: "external_llm",
  capabilities: {
    search: true,
    expand: true,
    explain: true,
    verify: true,
    citations: "best_effort"
  },
  isAvailable: async function (ctx) {},
  query: async function (request, ctx) {},
  healthCheck: async function (ctx) {}
}
```

`request` 建议结构：

```js
{
  mode: "search", // search | expand | explain | verify | compare
  question: "",
  context: {
    textbookTitle: "",
    currentPage: null,
    selectedText: "",
    learnerLevel: "",
    courseLanguage: "zh-CN"
  },
  constraints: {
    requireCitations: true,
    maxLatencyMs: 30000,
    maxTokens: 3000,
    allowExternal: true
  },
  trace: {
    sessionId: "",
    userAction: "",
    requestedAt: ""
  }
}
```

Provider 返回统一证据包：

```js
{
  providerId: "kimi-client",
  status: "ok", // ok | partial | unavailable | error | timeout
  mode: "verify",
  answer: "",
  claims: [
    {
      text: "",
      type: "fact",
      confidence: 0.72,
      support: ["source-1"],
      conflicts: []
    }
  ],
  sources: [
    {
      id: "source-1",
      title: "",
      url: "",
      origin: "kimi",
      quotedText: "",
      retrievedAt: "",
      reliability: "unknown"
    }
  ],
  raw: {
    excerpt: "",
    adapterMeta: {}
  },
  cost: {
    latencyMs: 0,
    tokens: null
  }
}
```

## 6. Kimi Client Provider 设计

由于 Kimi 没有官方 API，Kimi Provider 必须被设计成适配器，而不是普通 HTTP API client。

### 6.1 支持模式

建议支持四种运行模式：

```text
disabled
  不启用 Kimi。

manual
  Socratopia 生成结构化查询提示词，用户手动复制到 Kimi，再把结果粘回。

client_bridge
  通过用户授权的本地自动化或浏览器桥接访问 Kimi 客户端 / Kimi Web。

local_readonly_discovery
  仅读取 `C:\Users\ASUS\.kimi` 的非敏感结构信息，判断版本、缓存、配置、可用性。
```

第一阶段建议优先实现 `disabled`、`manual` 和统一接口。`client_bridge` 与 `local_readonly_discovery` 放在第二阶段做安全评估后再启用。

### 6.2 Kimi 查询 Prompt 模板

Kimi Provider 不应发送自由散乱问题，而应生成结构化提示词：

```text
你是 Socratopia 的外部知识核验源。
请围绕以下问题提供候选资料、关键结论、可能争议和可追溯来源。

问题：
{{question}}

本地教材上下文：
{{context}}

请按 JSON 结构回答：
{
  "summary": "...",
  "claims": [
    {"text": "...", "confidence": 0.0, "reason": "..."}
  ],
  "sources": [
    {"title": "...", "url": "...", "why_relevant": "..."}
  ],
  "uncertainties": ["..."],
  "suggested_queries": ["..."]
}

如果无法确认来源，请明确写 unknown，不要编造 URL。
```

### 6.3 本地目录访问边界

`C:\Users\ASUS\.kimi` 只能作为兼容性调查入口，不能默认作为知识库直接读取。

允许做的事：

- 读取目录结构和文件名，判断是否存在配置、缓存、数据库文件。
- 记录客户端版本、数据格式、更新时间等非敏感元信息。
- 在用户明确授权后，抽样检查文件格式。

不应做的事：

- 默认读取聊天记录、账号信息、token、cookie、密钥。
- 把 Kimi 本地缓存直接当作可公开证据。
- 依赖私有数据库结构作为长期稳定接口。

## 7. Source Router 策略

建议按任务类型选择知识源：

```text
课堂讲解 / 教材内问答
  local-textbook -> local-kb -> external only if insufficient

教材外背景扩展
  local-kb -> kimi/search/rag -> verifier

事实核验 / 最新知识
  search/rag/kimi -> source verifier -> answer composer

练习出题
  local-textbook -> local-kb -> external examples only

错因诊断
  learner model -> local-kb -> external only for补充解释
```

默认优先级：

1. 当前教材页和教学上下文。
2. Socratopia 本地知识库。
3. 用户导入资料和历史学习记录。
4. 配置启用的外部知识源。
5. Kimi / Search / RAG / Database 中按任务策略选择。

## 8. 可信度策略

每条外部知识进入教学回答前，都要经过最少三步：

1. 证据标准化：拆成 claims、sources、uncertainties。
2. 可信度标注：区分官方资料、论文、百科、社区、模型总结、未知来源。
3. 冲突处理：如果外部知识与教材冲突，默认教材优先，并提示存在外部差异。

可信度等级建议：

```text
high
  官方文档、法规原文、论文原文、教材原文、本地用户指定权威资料。

medium
  知名机构文章、可靠百科、可追溯技术博客、多个来源互相印证。

low
  社区回答、论坛、模型总结、未给出处的 Kimi 回答。

unknown
  无来源、来源不可访问、无法复核。
```

## 9. 缓存策略

外部知识结果需要缓存，但缓存的是证据包，不是最终答案。

缓存 key 建议包含：

- providerId
- mode
- question hash
- context hash
- provider version / adapter version
- retrievedAt date bucket

缓存文件可放在用户数据目录，而不是仓库打包资源目录。缓存结构示例：

```json
{
  "key": "...",
  "providerId": "kimi-client",
  "createdAt": "...",
  "expiresAt": "...",
  "request": {},
  "response": {},
  "verification": {}
}
```

过期策略：

- 教材解释：7 到 30 天。
- 最新事实：1 到 3 天。
- 软件版本、政策法规、价格、日程：默认当天过期。
- 用户明确固定的资料：直到资料更新。

## 11. 分期实施

### Phase 0：文档与边界确认

- 完成本计划书、上下文文档、核收指标。
- 确认 Kimi 不是唯一知识源。
- 确认是否允许读取 `C:\Users\ASUS\.kimi` 的目录结构。

### Phase 1：Provider 抽象与手动 Kimi 模式

- 新增 `resources/server/lib/knowledge/`。
- 实现 provider contract、source router、normalizer、trust policy。
- 实现 `kimi-client-provider` 的 `manual` 模式。
- 增加 smoke test。
- 不改 UI 或仅提供调试 API。

### Phase 2：Kimi 客户端兼容调查

- 在用户授权后只读检查 `C:\Users\ASUS\.kimi`。
- 判断是否存在稳定的本地配置、缓存、索引或协议痕迹。
- 输出 Kimi compatibility report。
- 不读取敏感内容，除非用户明确指定文件。

### Phase 3：自动桥接 Kimi

- 通过用户授权的本地桥接方式访问 Kimi Web 或客户端。
- 加入超时、取消、重试、失败降级。
- 把 Kimi 返回转换为统一证据包。
- 保证 Kimi 不可用时 Socratopia 仍可正常使用。

### Phase 4：接入其他知识源

- Search Provider。
- RAG Provider。
- Database Provider。
- Provider 排序、并发查询、结果合并、冲突展示。

### Phase 5：产品化 UI

- 设置页增加知识源开关。
- 教学回答展示“外部资料参与”提示。
- 支持查看证据、来源、时间、可信度。
- 支持用户选择“本地优先 / 联网扩展 / 严格核验”。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Kimi 无官方 API | 自动化脆弱 | 适配器模式，先做 manual，再做 bridge |
| Kimi 页面或客户端改版 | Provider 失效 | healthCheck、版本探测、失败降级 |
| 外部知识不准确 | 教学误导 | claims/sources/trust policy，不直接采信 |
| 用户隐私泄露 | 高风险 | 本地目录只读授权、敏感字段屏蔽 |
| 外部服务慢 | 教学体验变差 | 超时、缓存、异步补充 |
| 后续换知识源 | 重构成本 | 统一 provider contract |

## 13. 推荐下一步

1. 先实现 `resources/server/lib/knowledge/` 的纯逻辑骨架和 smoke test。
2. 做 `manual` Kimi Provider，验证证据包格式和 Router 策略。
3. 在用户授权后只读扫描 `C:\Users\ASUS\.kimi` 的目录结构，形成兼容性报告。
4. 再决定是否实现自动桥接 Kimi 客户端或 Kimi Web。
