# 项目背景与前景展望

## 1. 项目背景

Socratopia 是一个 Electron + Next.js 的学习陪伴软件。软件中的伙伴会通过 LLM 生成教学内容，再由 TTS 播放给学习者。课堂回复不是单纯的自然语言：它可能同时包含普通正文、Markdown、代码、LaTeX 公式、集合符号、逻辑符号、积分、求和、矩阵和旁白动作描写。

最初的 TTS 文本清理把复杂公式统一替换成“这个公式”或“来看这个公式”。这会造成三个问题：

1. 学习者听不到公式本身，数学教学信息丢失；
2. 公式中的上下标、分数、根号和运算顺序没有被表达；
3. 公式符号存在多义时，简单字符映射容易产生错误语义。

因此项目建立了一个独立的数学语义化核心，目标不是“把每个字符念出来”，而是把公式转换为稳定、可审计、不会被后续上下文推翻的中文数学朗读文本。

## 2. 核心目标

```text
LaTeX
  → KaTeX MathML
  → 规范化 MathML
  → 数学语义 AST
  → 符号词典、结构规则、数字规则、上下文证据
  → semantic / structural / detailed / skip
  → 冻结的中文数学朗读文本
```

核心目标有五个：

- 简单明确的公式自然朗读；
- 复杂公式使用结构清楚的详细朗读；
- 语义不确定时不武断猜测；
- 解析失败时局部安全跳过，不阻塞正文和后续 TTS；
- 同样输入和上下文产生确定、可复现的结果。

## 3. 为什么不采用单纯映射表

映射表适合确定性的叶子符号，例如：

```text
=加
≤=小于等于
α=阿尔法
∈=属于
```

但分数、上下标、根号、积分和量词依赖结构。相同的视觉符号还可能有不同含义：

```text
|A|       绝对值 / 集合基数 / 行列式
f^{-1}    逆函数 / 倒数 / 负一次幂
(a,b)     有序对 / 开区间
AB        隐式乘法 / 线段名 / 矩阵乘积
P(A|B)    条件概率 / 非概率领域中的普通函数
```

所以核心采用“结构解析 + 角色化词典 + 证据优先级”，而不是完整公式硬编码。

## 4. 语义安全原则

核心遵循以下优先级：

```text
正确且自然
  > 正确但结构化
  > 静默跳过
  > 错误猜测语义（禁止）
```

例如没有任何上下文时：

```latex
|A|=5
```

只能读成：

```text
左竖线 A 右竖线，等于五
```

只有明确知道 A 是有限集合或矩阵时，才分别读成基数或行列式。

核心输出在返回前被冻结。后续上下文只能影响未来公式，不能回写已经生成的结果。

## 5. 已完成的技术成果

当前核心位于：

```text
resources/server/lib/math-speech/
```

主要能力包括：

- KaTeX → MathML；
- MathML → AST；
- 分数、根号、幂、上下标；
- 积分、极限、求和、求积；
- 集合、逻辑、量词；
- 矩阵和分段函数；
- 科学记数法和中文数字；
- 多字符符号事实；
- 作用域和冲突处理；
- 语义冻结；
- malformed 和控制字符安全降级；
- 确定性和性能基准；
- 不依赖网络、LLM、TTS 或前端。

## 6. 验收结果概览

第四轮独立验收已经确认：

- 第一轮 11 项缺陷已修复；
- 第二轮 P/Pr 角色问题已修复；
- 第三轮多字符 `Pr` 和关键语料删除问题已修复；
- 概率角色黑盒 40/40 通过；
- 黄金语料 278 条，规范化唯一 278 条，重复 0；
- `semantic=217`、`structural=37`、`detailed=10`、`skip=14`；
- 语法、Acorn、TTS/runtime 回归全部通过；
- all-skip benchmark 会正确非零退出；
- 禁止路径和敏感路径相对最新基线无漂移。

这些结果证明“已定义合同范围内的核心”具备稳定基础，但不等于任意中文自然语言上下文都能被正确解析。

## 7. 仍然存在的边界

当前核心的自然语言符号事实抽取仍是有限规则，不是完整中文语义解析器。它适合处理明确定义句式，但不应被宣传为可以可靠理解所有以下句式：

```text
Pr 是一个函数。
Pr 定义为函数。
Pr 不表示概率，而是函数。
有人误以为 Pr 是函数。
除非另有说明，否则 Pr 表示概率。
```

因此第一版前端接入应优先依赖：

- 公式自身明确结构；
- 明确 LaTeX 命令；
- MathML `intent`；
- 上游显式结构化 `symbolFacts`。

自然语言字段只能作为低置信辅助证据，不能在没有充分验证时自动把结构读法升级为自然语义。

## 8. 前景展望

### 8.1 近期前景：安全接入 TTS

下一阶段不是直接改现有前端正则，而是建立独立混合文本适配层：

```text
Markdown
  → 先保护代码、链接、转义美元和 HTML
  → 识别完整公式片段
  → 批量调用数学语义核心
  → 合并正文与公式语音文本
  → 进入现有 TTS 串行队列
```

接入层必须支持公式失败局部化、旁白过滤、零音频、句子边界和缓存一致性。

### 8.2 中期前景：课堂数学语义增强

- 将公式朗读与教材知识点绑定；
- 支持章节级符号表；
- 对复杂公式提供“简洁/详细”用户偏好；
- 在消息中保存公式语义诊断；
- 让教师或开发者查看公式为何采用结构化读法；
- 为公式和自然文本建立一致的音频缓存版本。

### 8.3 长期前景：多语言和无障碍数学

- 扩展繁体中文和英文规则；
- 评估 MathCAT/Speech Rule Engine 的可复用规则；
- 支持 MathML `intent` 作为跨平台语义接口；
- 为视障学习者提供语音导航和子表达式定位；
- 结合公式高亮、朗读和教材定位；
- 建立跨学科数学、物理、工程符号词典。

### 8.4 产品价值

如果接入层保持保守、可审计和可回退，数学公式语义化可以让 Socratopia 从“能朗读文本”提升为“能朗读结构化学习内容”。关键价值不在于覆盖所有公式，而在于：

```text
不读错关键数学含义
不打断课堂
不让未知公式拖垮 TTS
让复杂内容可以持续扩展
```

## 9. 成功的长期衡量标准

长期不应只看“公式语义化比例”，还应监控：

- 错误数学语义数：必须为 0；
- 因公式失败导致的 TTS 中断：必须为 0；
- 旁白误送 TTS 数：必须为 0；
- 结构化结果被后续上下文推翻数：必须为 0；
- 公式前端接入后的回归失败数；
- 学习者对公式朗读可理解度的人工/用户反馈。

---

## 10. 总结

本项目已经完成了数学语义核心的独立建设和多轮验收。当前最重要的不是继续无限扩展符号特判，而是保持边界清晰：

1. 核心负责确定性数学结构和安全中文读法；
2. 接入层负责 Markdown、代码、旁白和 TTS 队列；
3. 前端只在专门评审通过后接入；
4. 重新生成语音是独立后续项目；
5. 所有后续扩展都必须保留结构化回退和语义冻结。
