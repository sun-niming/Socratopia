## 3. 接入前必须做出的决策

### 决策 A：自然语言事实来源

推荐第一版：

```text
自然语言声明 = 低置信辅助信息
结构化 symbolFacts / MathML intent = 高置信信息
```

不得因为一句普通中文句子中出现“Pr 是函数”就自动覆盖明确 MathML intent，也不得让解析失败时回到高风险默认语义。

### 决策 B：接入形态

推荐：本地 Next.js 服务端批量 API。

原因：

- 核心已经是服务端 CommonJS；
- KaTeX 已在服务端依赖中存在；
- 避免复制到浏览器 bundle；
- 避免核心规则和前端规则分叉；
- 更容易做统一测试和版本管理。

建议请求形态：

```json
{
  "segments": [
    {"type": "text", "value": "由"},
    {"type": "math", "latex": "x^2+1=0", "context": {}},
    {"type": "text", "value": "可知……"}
  ]
}
```

### 决策 C：公式提交时机

以完整句子为最小语义提交单元：

- 不以单 token 解析；
- 不在公式刚出现时猜测后文语义；
- 句子完成后一次批量解析；
- 失败公式局部 skip；
- 结果进入 TTS 前冻结。

### 决策 D：缓存

缓存键至少包括：

```text
规范化 LaTeX
locale
朗读 style
相关 symbolFacts/intent
规则版本
```

后续重新生成语音必须是显式操作，不能后台静默覆盖已经播放过的音频。
