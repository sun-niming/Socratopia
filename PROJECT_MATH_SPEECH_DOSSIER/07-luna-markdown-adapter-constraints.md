# Luna 实施任务：Markdown 混合文本数学语音适配层

## 任务目标

在现有 `/api/math-speech` 分段接口之上，实现稳定的：

`Markdown 文本 → 有序 segments → 数学语义转换 → TTS 文本`

本任务只负责解析适配层和前端调用衔接，不重新设计数学核心，不修改 TTS 服务协议。

## 明确范围

必须完成：

- 识别行内公式 `$...$`、块公式 `$$...$$`、`\(...\)`、`\[...\]`。
- 正确避开 fenced code block、行内代码、Markdown 链接 URL、图片 URL。
- 保持原文顺序；普通文本和公式必须生成有序 segment。
- 批量调用 `/api/math-speech`，传递 `locale`、`style` 和必要的 `context`。
- 单个公式转换失败时只回退该公式原文，不得丢失整段文本。
- 保留取消、超时和请求失败时的可控回退路径。
- 旁白性质文本继续跳过 TTS，但不得误跳过普通台词。
- 增加版本字段或适配器版本常量，便于迭代留痕。
- 更新 `PROJECT_MATH_SPEECH_DOSSIER/06-iteration-log.md`，记录本轮变更。

## 禁止事项

- 不修改数学核心语义规则、词典和验收基线。
- 不改变 `/api/math-speech` 既有请求/响应字段含义。
- 不引入新的 Markdown 第三方依赖。
- 不重写整个前端语音模块；只增加适配器和最小调用改动。
- 不修改 `resources/settings.json`、`resources/set.json`、`resources/app.asar`。
- 不把 Markdown 解析逻辑放入服务端数学核心。
- 不为了“解析成功”强行猜测未知 LaTeX 语义。
- 本轮不扩展测试设计；实现完成后交由 Terra 按独立验收文档测试。

## 解析约束

1. 先扫描并保护代码块、行内代码、链接和图片，再识别公式。
2. 转义字符必须遵守 Markdown 规则：被反斜杠转义的 `$` 不得作为公式边界。
3. 块公式优先于行内公式；公式标记不完整时按普通文本保留。
4. 解析器输出必须是纯数据，不直接播放音频。
5. 每个 segment 保留原始文本或原始 LaTeX，禁止静默改写。
6. 公式上下文只使用显式传入的句子/段落上下文，不跨会话隐式累积。
7. 旁白判断采用白名单规则并记录跳过原因；不确定时保留 TTS。
8. 设定单次文本、公式、segment 数量和总请求体上限，超限时可解释地回退。

## 回退与错误处理

- API 不可用、超时、HTTP 错误、JSON 非法：按 segment 回退为可读原文。
- 数学结果 `ok:false` 或 `speech` 为空：使用结构化/原始 LaTeX 的安全朗读文本。
- 任何异常不得阻塞后续普通文本播放。
- 合并结果必须保持 segment 输入顺序，禁止并发响应乱序。
- 不记录 API 密钥、用户隐私或完整敏感对话内容。

## 文件边界

优先修改：

- `resources/server/.next/static/chunks/` 中现有语音 bundle 或新增适配器 bundle。
- 必要时同步 `win-unpacked/resources/server/.next/static/chunks/`。
- `PROJECT_MATH_SPEECH_DOSSIER/06-iteration-log.md`。

不得修改服务端数学核心，除非发现阻断适配器的明确契约错误，并先记录原因。

## 交付内容

- 变更文件清单及每个文件的目的。
- 解析器输入/输出示例（至少包含代码块、转义 `$`、块公式、失败回退）。
- 已知限制和未解决风险。
- 迭代记录更新。
- 不宣称测试通过；将测试状态标记为“待 Terra 独立验收”。

## 完成判定

只有满足以下条件才可交给 Terra：

- 公式、代码、链接、普通文本顺序可追踪。
- 单段失败不会造成整条 TTS 文本丢失。
- 旁白跳过规则不会扩大到普通对话。
- 源 bundle 与运行包副本同步。
- 无越界文件修改，且所有暂缓事项仍保持暂缓。
